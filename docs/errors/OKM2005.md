# OKM2005

Unordered limit

## What happened

A limit whose order does not end in a unique key can return a different row set each time. Under for(), the tenant key is ignored, so the rest of that unique counts.

## Fix

End orderBy with the primary key or a unique column.

## Rule

`unordered-limit`

## Default

Level `warn`. Severity `high`. Phase `dev-runtime`. Evidence `static`.

## Safe alternatives

- End orderBy with the primary key or a unique column.

## page

### bad

```ts
async () => {
```
