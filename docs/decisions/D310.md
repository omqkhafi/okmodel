# D310 — `find({ distinct })` and Postgres `distinctOn` (F8-2)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`find()` takes `distinct: true` and `distinctOn: [fields]`; both load `src/runtime/distinct.ts` on first use. `distinct: true` needs `select` (without it every row differs by its primary key) and writes `select distinct`. `orderBy` may name selected fields only, and it is written by select position, because a timestamp is selected as text and an `order by` on the column would not match it. `distinctOn` writes `select distinct on (keys)`, takes visible fields once each, and needs an `orderBy` whose first keys are those fields in any order. The keys after them choose the row each key keeps, and `nulls` applies as on any `orderBy`. NULL is one value for both. They are refused with OKM1120 before any SQL when: `distinct` is not `true`, both are set, `include` or `search` is set, `select` is empty or missing for `distinct`, or the `orderBy` does not lead with the keys. `page`, `one`, and `count` do not take them (the unknown-key OKM1120). `limit` or `.all(reason)` still applies (OKM1101). Hidden fields cannot be a `distinctOn` key. The tenant, archive, and preset predicates apply as on any read. The lazy handle has `sql`, `inspect`, and `all`; `.stream()` and `.required()` are not on it, as for a row lock. Dialects: `select distinct` is standard SQL and native on Postgres, SQLite, and MySQL/MariaDB. `distinct on` is Postgres only; SQLite and MySQL/MariaDB would refuse it with a stable code and the alternative of a window `rowNumber`, with no emulation. Postgres is the only dialect in this repository, so there is no refusal path to write. Capability keys `query.distinct` and `query.distinctOn`. Startup graph: the featureless app grows by 89 minified and 14 gzip bytes (88,348 / 28,426 to 88,437 / 28,440) for the one routing branch in `client.ts`; the gates (90,900 / 30,170) and the runtime entry (5,288 / 2,026) do not move. No new ErrorKind. No catalog hash change. No decision is reversed. Issue #507
