# D270 — Inline relations are closed for 0.8 (P108)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`references(table, { as, has })` does not ship. The only acceptable call was `find({ include: { author } })` with no codegen. Every probe that typed that call broke a type ceiling or the app-size gate. `relations` on the table remains how an include is named. The study is `p108-inline-relations-study.md` (git history), measured on `7235a01`. Candidate A, an opt-in `relates` plus `inlineRows`, left every existing ceiling on the sample. Its feature fixture was 54,012 instantiations and 7,961 types. That call shape was rejected. Candidate B, a lazy harvest inside `table()`, measured query-200 17,450 / 6,447 (150 instantiations over 17,300), extensions 17,484 / 6,567, composite types 7,001 (70 over 6,931), and validate types 6,639 (35 over 6,604). Candidate C, `asRelation` with no `has`, fit the ceilings. Its feature fixture was 27,690 / 7,092. That call shape was not the approved one. Candidate D stored `as` and `has` as `string` on `references()` and dropped the literals. Type rows stayed put when the new fields were omitted. The app measured 90,932 minified, 32 over 90,900. P108B probed the approved call sites and was not shipped. E1, a type augmentation of `references` plus a hook `IncludeOf` reads, added 27 instantiations and 23 types on every query fixture. Extensions measured 17,313 instantiations, over 17,300. Composite types measured 6,954, over 6,931. E2, harvesting names when `find` resolves a table, measured query-200 18,120 / 6,459 and composite 25,396 / 7,014 on the to-one scan. A one-direction `as` form was discussed and was not measured in that shape. It is parked. Reopen only for a zero-generation route that fits the ceilings with no gate moved, or a TypeScript change that makes cross-table name inference cheap. No gate or ceiling moves. Issue #292
