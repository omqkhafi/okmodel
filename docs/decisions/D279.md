# D279 — The GitHub Action reads `okm migrate plan --json` (P117)

- **Status:** accepted
- **Area:** ci, tooling
- **Supersedes:** none

---

`okm migrate plan --json` prints one JSON document and no human plan text. The document is `name`, `class` (the strictest class), `steps` (`class`, `lock`, `sql`), and `findings` (`severity`, `code`, `place`, `reason`, `fix`). `lock` is the same string the human plan prints after `-- lock:`, including a row estimate when a target answers. The command still exits 1 on an error finding (OKM1510) after the document is written. The composite action `.github/actions/migrate` runs `okm migrate check` and `okm migrate plan --json` against the required `target` input. An empty name is OKM1853. The action never infers a target and never hardcodes one. It posts one pull-request comment marked `<!-- okmodel-migrate-plan -->`, updated in place, rendered by `renderPlanComment` from that document. `preview: true` runs `okm migrate apply --target <the same name>` and, when `seed` is set, `okm seed`. The database URL comes from the caller. The action does not create or drop a database. Protected targets stay on the existing policy. Comment writes use `GITHUB_TOKEN` with `pull-requests: write`. Fork pull requests receive no secrets, so preview is for a pull request in the same repository. An empty `version` input runs the source checked out with the action. A set `version` installs that published release. No new error code. No public runtime API. Nothing new is reachable from the runtime entry or from `connect()`. No gate or ceiling moves.
