# D186 — First release run failed before npm; CI and release hardening in PR #114

- **Status:** accepted
- **Area:** ci
- **Supersedes:** none

---

The first Release runs on v0.2.0 (#5 and the retry) failed in `publish` before npm: `release.yml` ran `bun run check` without Deno (and without `setup-node`), so `test:runtimes` reported "deno is not on PATH, and CI must run it". Nothing was published; the cause was never npm. PR #114 fixes it and hardens the rest: (1) `publish` sets up Node 22 and installs Deno v2.9.7 (same lines as `ci.yml`) before Check; the Node 24 step for `npm publish` moves after Check. (2) A guard in `tests/release-gate.test.ts` parses `ci.yml` and `release.yml` and fails if any job that runs `bun run check` differs from `ci.yml` in its Deno lines or Node version, so the two cannot drift. (3) Actions move to Node 24 releases, pinned by full SHA: checkout v5.1.0, setup-node v5.0.0, upload-artifact v6.0.0, download-artifact v7.0.0 (the oldest Node 24 major of each; `setup-bun` was already Node 24); the Node 20 warning is gone. (4) Every job runs on `ubuntu-24.04` instead of `ubuntu-latest`, because the label moves to Ubuntu 26 from 2026-10-19; moving to 26 is a deliberate later change. (5) Release policy: `scripts/release-check.ts` exempts a PR whose changed files are all under `.github/` from the version-bump and changelog rules (a three-dot diff against the base; an empty diff is not exempt; any file outside `.github/` brings both rules back). PR #114 itself changes `scripts/` and `tests/`, so it cannot use its own exemption; it is merged once with that one check red, as a bootstrap, because every other job is green and the red check is the rule being relaxed. The version stays 0.2.0: v0.2.0 was never published, so after the merge the tag is deleted and re-created on the new `main` and Release is run again. Seen, not changed: the `tag` job has `actions: write` that nothing appears to use; `ci.yml` checks out with full history and `release.yml` does not (nothing in `check` reads history). Found in P30 release
