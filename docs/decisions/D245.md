# D245 — postgres.js stream loop does not fit; migrate check skips a cleanup connection (P91)

- **Status:** accepted
- **Area:** adapters, tooling
- **Supersedes:** none

---

A postgres.js `stream()` still uses the driver's cursor. Reproduced on Postgres 17 with `pg_terminate_backend`: killing the backend between pages makes the next `cursor.next()` return `{ done: true }` and no error, with the rows already yielded intact; a `FETCH` write queued with `setImmediate` then throws `TypeError: null is not an object (evaluating 'socket.write')` outside the iterator promise. The replacement is a reserved connection and `FETCH`, loaded by `import()` on the first `stream()` call. Measured with the size script: the lazy chunk is `src/adapters/pg/postgres-stream.ts` at 454 minified bytes and pulls in `src/adapters/pg/cursor.ts` at 244. The postgres.js adapter incremental goes from 15,069 to 15,781, above the gate 15,093. The postgres.js connect entry goes from 42,173 / 14,861 to 42,213 / 14,855. Runtime entry stays 5,288 / 2,026, cold import 1.883 ms before and 1.747 ms with the chunk. Featureless app goes from 90,835 / 30,169 to 90,834 / 30,168. PGlite 40,204 / 14,201, node-postgres 41,893 / 14,732, and Bun.sql 41,387 / 14,462 stay put. The loop is not in the tree (D201). No gate moves. `hintOf` already returns reason `undefined_table` for SQLSTATE `42P01`, with a fix that names `okm migrate apply` and `okm migrate status` (D214). §14's nearest-name hint for an unknown table, field, preset, or option is `nearestName`. There is no B15 section in the design docs. The editor diagnostic already names `missing`. No new error kind. `okm migrate check` does not open a cleanup connection when the replay rolls back and `pg_current_xact_id()` is unchanged, including when a later error still rolls that transaction back. A step that commits still drops the scratch schema on a new connection, and a lost connection still confirms the drop. The truly-lost release path in D244 is unchanged. No catalog hash change. No public API change. Issue #209. D256 does not ship that loop. `.stream()` walks keyset batches, so the product gap closes without those adapter bytes.
