# D364 — Docs foundation: generated support constants, heading chips, and a shrinking frontmatter exemption

- **Status:** accepted
- **Area:** docs
- **Supersedes:** none

---

The handbook quotes one generated support sentence (floor, tested majors, package version, registry count) from `scripts/docs-support.ts`. `POSTGRES_FEATURES` is not renamed. `ENGINES` has one entry, `postgres`. MDX treats `{feature="key"}` as an expression, so the page form is `[feature="key"]`. That suffix renders a chip whose visible text is the minimum (`15+`, `18+`, `any`) and whose markdown, llms, and search text is one plain line. `[engines="postgres"]` is docs only, no proof. Pages that do not yet have `title`, a one-sentence `summary`, `since`, and `status` stay on an exemption list that only shrinks and is empty at the release candidate. A page that names an unknown registry key fails. Keys with no page are reported and do not fail. `tested-matrix` says CI ran on 18 until the release step fills it. No public API change. No new `ErrorKind`. No catalog hash change. The site does not import the runtime entry. Issue: none (PR only)
