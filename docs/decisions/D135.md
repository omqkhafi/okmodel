# D135 — Entry ceilings, dist informational, capability error

- **Status:** accepted
- **Area:** contracts
- **Supersedes:** none

---

The unminified `dist/` size is reported but no longer gated (it sat 821 bytes under its ceiling after P13 and would have needed a raise every prompt); each published entry has its own gate at measured +25%: `okmodel/pg/postgresjs` ≤ 12,600 bytes min / ≤ 4,500 gzip, `okmodel/pg/pglite` ≤ 10,700 / ≤ 3,900, `okmodel/pg` ≤ 66,900 / ≤ 20,900; the runtime entry (60 KB / 20 KB, D127) and the app fixture (D133) keep theirs. Adapter cold imports (7.9 and 10.1 ms) are dominated by the driver packages and are reported, not gated. A dynamic call of an operation the driver's capabilities do not allow throws OKM1111 (runtime, 1100 range), implemented with its first consumer in P15; OKM1110 stays the engine-version gate. The postgres.js adapter uses the unnamed protocol (`prepared: "unnamed"`), which stays correct behind poolers in transaction mode; a named-statement option for direct connections is evaluated in P15 with a benchmark.
