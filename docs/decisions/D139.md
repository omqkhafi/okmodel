# D139 — P15B outcomes, editor check tool, P16 split

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

(1) Multi-statement writes (chunked inserts) run on the driver's atomic `batch`, so begin, commit, savepoint and `outcome_unknown` stay in the adapter and no second transaction path exists; this is the internal runner of P15B. The interactive reserved-connection runner (code between statements) does not exist yet and is built in P29 with the public `tx`. (2) TypeScript 7 has no language server, so `bun run editor-check` uses a dev-only TypeScript 6 package over stdio; it is never imported or bundled, and it is revisited when TS 7 ships one. (3) P15B gates: app startup graph 74,218 / 24,471 measured, gate 76,444 / 25,205; total graph 103,117 / 33,314 reported; `okmodel/pg` 69,135 / 21,558 under 70,500 / 22,000. (4) The type-cost write probe on 200 tables is 6,451 types against the 6,500 ceiling (49 left): any prompt that gets within 3% of a ceiling reports it, and ceilings are raised only by decision (the inferred worst case is not what a default emitted-types consumer pays, D120). (5) Completions inside an `insert` object offer only the property under the cursor because the single and array overloads do not contextually type the object; P16 starts by finding a signature that lists the insertable columns, or records the gap in `docs/editor-check.md`. (6) P16 was too large for one reviewable prompt and is split: P16 is the planning side (introspect, normalise, diff, generate, build, check), P16B the applying side (apply, history, `okm_meta`, targets, protected policy, startup check).
