# D307 — `okm doctor --bundle` writes a local diagnostics file (X7, O-6)

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

Decided with Ali on 2026-10-21 (O-6): a tester sends diagnostics by hand, so the file is local, needs no network, and holds no values. Tooling only. No public API, `ErrorKind`, or catalog hash change. No gate move. (1) `okm doctor --bundle [--out <file>] [--force-file]` writes one JSON file, `.okm/doctor-bundle.json` by default, with `bundleFormat: 1` and sorted keys. An existing file is refused (exit 4) unless `--force-file`. `--bundle` is exclusive with an error code and with `--target`, and it does not connect: the envelope carries no `target`. (2) The content is versions (okmodel, Node, Bun), OS and arch, package manager, dialect and adapter packages with installed versions, the config file name, `.okm/` artifacts from a closed list of names with SHA-256, layout counts (workspace or not, migration files), the Postgres capability registry summary, and check results. It never holds a connection string, host, user, URL, table or column name, SQL text, row value, a path outside the project, or an environment variable value (none is read). A finding contributes its code and severity only, and a code outside `OKM####` and `coupling` is `unknown`. (3) Check results are the checks that need no database, run when the bundle is written: step lint, type preferences, cross-catalog keys, typed raw drift, the migration directory lint, the `okm-allow` audit, and the schema rules OKM2101 to OKM2103. They are not a record of the last `okm check` run, because that run writes nothing and a stored record would add a write to a command CI runs read-only. A stage that cannot run (a schema that throws) is a closed code in `checks.failures`, not a refusal. Checks that need a server (replay in a scratch schema, drift, extensions) are not in the file; the guide says so. (4) `--out` is the bundle path with or without `--json` (`CommandSpec.ownOutFlag`). With `--json`, `data.bundle` is the document and `outFile` names the file. `--force-file` is a boolean on `doctor`; on `init` it still takes a path. A flag-looking next argument is never a value, so the boolean spelling does not swallow `--out`. (5) Documented in the guide, the CLI reference, the threat model, and `schemas/cli-1/doctor.json`. A redaction test plants secrets in config, environment, schema, migration, and `.env`, and scans the output. `okm doctor --production` is X4 and not part of this change.
