# D372 — Handbook contract sections, since, and schema example pushes

- **Status:** accepted
- **Area:** docs
- **Supersedes:** none

---

A handbook contract section is written with content specific to that page, or it is omitted. "When to use it" and "When not to" say something a reader could not infer from the title. "Options" is a table of that page's options. "What the plan shows" appears only where the feature has a plan step, and it names the step kind and lock from the Postgres lowering. "Errors" gives each code with one line of what triggers it on that page. "Version" stays the generated support phrase. `scripts/docs-sentences.ts` fails when the same sentence of 40 or more characters, after whitespace is collapsed, appears on three or more pages under `site/content/docs`. The check names no sentence of its own. `<SupportPhrase />` and `<Tagline />` are not page text. A page's `since` is the first minor in which one of its registry keys exists. `scripts/docs-since.ts` reads the registry at tag `v0.10.6`: when every key the page names is absent there, `since` is `0.11`; a page with no feature key keeps its current value. The frontmatter lint accepts the package minor and the next minor while the package is still the previous minor, and it still rejects a value that is not a version. The docs example run pushes every complete `schema()` program on a schema page. A fence that does not call `schema()` stays type-checked. A refusal whose OKM code the page names is a pass. A push skipped because the topology image lacks pgvector or pg_cron is named, and those extensions run at the release candidate. No public API change. No new `ErrorKind`. No catalog hash change. Issue: none (PR only)
