# D229 — Tenancy strategies are imported factories (P82)

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

D228 put composite keys and path isolation on `columnTenancy()`. A column-only app then loaded the path compiler. Ali approved a pre-v1 break: each strategy is a factory the app imports, and `connect()` does not wait for a compiler. `columnTenancy({ key: "tenantId", type: "uuid" })` is one key, the same shape as before D228. A key list is a type error whose text names `compositeTenancy()`. A runtime check for that list was 84 minified bytes, over the +60 line, so it is not shipped; a non-string key still fails with the field-name definition. `compositeTenancy({ key: ["organizationId", "workspaceId"], type: "uuid" })` is its own module. `for()` still requires every key. The primary key, the extra unique, `.unique()`, foreign keys, `onConflict`, and OKM1704 stay as D228. `via("project.organization")` returns the table mark and its own `rewrite`. The column rewrite calls that function when the mark has one, and applies the endpoint unique the rewrite records. There is no `import()`, no `connect()` wait, and no unloaded state. `tenancy: { via: "..." }` has no `rewrite`, so schema build rejects it and the message names `via()`. The table option type stays `{ via: string }` because requiring `rewrite` on that type reshuffles minified names in `table.ts` and moves the featureless app gzip from 30,145 to 30,143. Bun drops unused `export { compositeTenancy }` and `export { via }` from `okmodel/tenancy`, so a column-only bundle contains neither file. Separate subpaths were not needed.
