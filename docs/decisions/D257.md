# D257 — `bucket()` refuses prototype result keys (P99P)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`as: "__proto__"` replaces the aggregate row's prototype, so the period is not an own property. `constructor`, `toString`, and `hasOwnProperty` shadow methods on that row. Those are the four names `filters().parse` already treats as ordinary keys (D215). `readBucket` refuses them with OKM1120 (`bucket as <name> is a prototype key. Use another name for the result.`) before any SQL. The check stays in `bucket-group.ts`, which loads on the first aggregate whose `groupBy` contains a bucket, so the stubbed startup graph does not include it. No new error kind. No public type change. No catalog hash change. No gate move. Measured with `bun run size` after the check: runtime entry 5,288 / 2,026, cold import 1.811 ms. Stubbed featureless app 90,593 / 29,338, the same as D256. postgres.js 40,533 / 14,098, PGlite 38,774 / 13,481, node-postgres 40,304 / 13,986, Bun.sql 39,275 / 13,590, all the same minified bytes as D256. The bucket chunk is 4,519 minified and 1,871 gzip. `bun run type-cost`: query-200 stays 17,239 instantiations and 6,374 types. query-200+page+aggregate+through stays 24,436 instantiations and 6,928 types, 3 under 6,931.
