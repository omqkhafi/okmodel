# D203 — P62 replica selection stays in the lazy chunk

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

An automatic read runs every replica, then health (a closed circuit), then consistency and lag (a no-op until P63), then capacity, then `routing.select`. `select` is `weighted` (the default), `roundRobin`, `leastConnections`, `latencyAware`, or a function. `weighted` is nginx smooth weighted round-robin, with state on the topology handle. Equal weights rotate in config order. `weight <= 0` stays OKM1120 (`replicas[i].weight must be a positive number.`), so `weighted` only sees positive weights. `roundRobin` ignores weights. `leastConnections` uses the router's in-flight count around each execute, not `stats().inflight`. Ties keep config order. `latencyAware` is an exponentially weighted moving average with alpha 0.2. The first sample is stored as itself. Successful reads and the health probe both feed it. A replica with no sample loses to one that has one. Ties keep config order. There is no jitter. A function receives `{ name, weight, inflight, latencyMs, lag }` (`lag` is null until P63; `latencyMs` is null with no sample) and `{ op: "read" }`. It must return one of those candidate objects or its name. Any other return is OKM1120 and the message names the return value. The router does not catch a throw. An `OkmError` thrown from the function stays that error. A plain `Error` is still mapped by the client. The function runs only for an automatic read with at least two candidates. `route: "replica"` and `using("replica")` do not call it; with a function configured they take the first eligible replica in config order. A named strategy still runs for that route, and capacity does not. Saturated means the endpoint has a configured `max` and `stats()` reports `idle === 0`, `waiting > 0`, and `size >= max`. No `max` means not saturated. If every healthy replica is saturated, an automatic read uses the primary with reason `fallback:saturated`, or OKM1844 when `fallback` is `"error"`. One connection failure retries the read once with the same strategy over the replicas that remain. `consistency` and `maxLag` still throw OKM1061. Startup minified bytes are unchanged. Gzip moves are the bundler renaming same-length locals: runtime entry 5,288 / 2,026 (+0 / +0, 224 gzip left under 2,250); featureless app 89,751 / 29,795 (+0 / +15, 205 left under 30,000); postgres.js 41,137 / 14,504 (+0 / -2, 96 left under 14,600); PGlite 39,135 / 13,884 (+0 / +1, 96 left under 13,980); node-postgres 41,547 / 14,673 (+0 / +0, 247 left under 14,920); Bun.sql 40,395 / 14,178 (+0 / +1, 292 left under 14,470). Each graph keeps at least 60 gzip bytes. The lazy topology chunk is 16,140 minified and 5,194 gzip (was 12,894 / 4,160). `query-200` stays 17,087 instantiations and 6,280 types.
