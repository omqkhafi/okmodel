# D290 — Pull, import, and ext scaffold emit buildable names (B-14 to B-19, B-38)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Tooling only. `okm pull` and `okm import drizzle` write `.references(<export>)` using the table binding, not the SQL table name, so a sanitized parent builds. Export bindings and file stems are unique under lowercase fold (`Tasks` / `tasks` → binding `Tasks` / `tasks_2`, files `Tasks.ts` / `tasks_2.ts`) so row-type names do not collide, and never a Windows reserved device name (`con`, `aux`, `nul`, `com1`–`com9`, `lpt1`–`lpt9`, any case): those get a `_` prefix on the stem. The same database always yields the same names. SQL names stay in `sqlName` when the binding differs. A column `__proto__` is emitted as `["__proto__"]:`. Drizzle import forces composite primary-key columns not null. Missing or failing `oxfmt` prints a notice on stderr, leaves the files unformatted, and still returns the report. `okm ext scaffold` includes composite types (`typtype = 'c'`). No public schema DSL change. No new error kind. No catalog hash change. No runtime-entry or featureless-app gate move. Issue #337
