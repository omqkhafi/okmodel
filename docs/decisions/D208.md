# D208 — The startup hash leaves out roles and grants, and catalog checks read scratch schemas as `public`

- **Status:** accepted
- **Area:** contracts
- **Supersedes:** none

---

Found by the reference app (P65) and fixed in P65A. (1) `okm migrate check` sets `search_path` to each scratch schema before it introspects it, because `pg_get_viewdef` and `format_type` qualify every name that is not on the path. A declared view and a function that takes a schema enum no longer fail with OKM1547 or OKM1020. Replayed steps rewrite `in schema "public"` to the scratch schema too, so default privileges stay there. (2) View scratch (`sealViews`) creates the catalog's functions after the stub tables and before the views, so a view that calls a declared function passes `okm check`. (3) `archivable()` writes the partial unique predicate as Postgres prints it, `(archived_at IS NULL)` or `("archivedAt" IS NULL)`. Stored catalogs with the old text change once. On a database created with the old text, `connect()` is OKM1520 and `okm check` is OKM1510 (OKM1529) until `okm generate`, an `okm-allow OKM1529` line, and `okm migrate apply` rebuild the same index. `okm migrate check` keeps OKM1547 at the migration that first created the index, as before the fix; no command rewrites a shipped migration and `lintFrom` does not lift it. (4) Function grants name argument types from `oidvectortypes(proargtypes)` with spaces removed, in introspection and in `okm doctor`, so a function with named arguments no longer drifts and doctor no longer skips it. (5) Grant targets and default privileges use the schema they are applied to, so `--provision` grants stay in its scratch schema. (6) Role, grant, and default-privilege objects are not part of the startup hash. A `schema()` catalog never has them, so `connect()` hashes it unchanged, with no runtime bytes. `okm_meta`, `okm_history`, `.okm/catalog.json`, and `.okm/catalog.hash` store the catalog without them (`startupCatalog`, `startupHash`). `okm check` and `okm doctor` still verify them. A catalog without roles hashes byte-for-byte as before (pinned in `tests/roles.test.ts`). `okm migrate apply` restamps a stored hash to the startup hash only when it equals the pre-D208 hash of a migration already in `okm_history`, including when nothing is pending, and prints `restamped <id>`. It is a `history-repair` write, so a protected target needs `--allow-protected`. Any other hash is left and stays OKM1520. (7) `db.views` is typed from `schema({ views })` on connected, scoped, and routed clients: camel-cased column names, each `string \| null`, with `find` (limit or `.all(reason)`), `one`, `count`, and `exists`. Type only.
