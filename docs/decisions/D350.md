# D350 — Dotted field and to-one paths in `db.*`

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Amends D348: `"home.city"` and `"project.name"` are keys of `where`, `select`, `orderBy`, and `groupBy`. One lazy module, `src/runtime/paths.ts`, loads only when a key contains `.`. `plan.ts` dispatches on that dot and does not own the resolver. `update` stays in the lazy writer and still prints `SET "home"."city"` (`(home).city` is 42601 in SET). A composite field prints `("home")."city"` through `compositeAccess` in `src/dialects/pg/path-sql.ts`. A bigint, numeric, or decimal field, and an array of those, is selected as `(access)::text` and decoded with the field codec. `orderBy` and `groupBy` use the raw access so a bigint sorts as a number. Nested fields, enum fields, and domain fields use that field's operators. An array field takes `eq` and `contains`; a bare array is OKM1121, the same rule as any other column. A to-one path is `"relation.column"`, the P5 form, or a composite field of that row (`"author.home.city"`). A second relation is OKM1120 before any SQL. The join is `toOneJoinSql` (no tenant of its own). `db.*` then runs `emitWhere` on the join, so the related table keeps its tenant and archive predicates; `via()` stays `exists`. The view compiler still walks paths itself: its builders are not the runtime index, and sharing the walker would import runtime from dialects or put the resolver on the startup graph. It prints the join with `toOneJoinSql` and a field with `compositeAccess`. Unknown paths are OKM1120. No new `ErrorKind`. Registry key `query.paths` (`proof:query.paths`). Closed-profile refusal is `refusal:query.paths`. Path keys are not on the static call types.
