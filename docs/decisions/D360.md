# D360 — A featureless app loads the query model; DDL compiles on the first catalog read

- **Status:** accepted
- **Area:** runtime, dialects, contracts
- **Supersedes:** none

---

`schema()` stores table options as descriptors: foreign keys, indexes, checks, exclusions, policies, series, comments, generated expressions, and composites. The first `.catalog` read loads `src/dialects/pg/catalog-compile.ts` through `createRequire` in `catalog-require.js`, called from `catalog-load.ts`. `createRequire` runs on that read, not at import: a Workers bundle leaves `import.meta.url` unset and evaluating it at import crashes the isolate. `okmodel/pg` has a `workerd` condition, `src/dialects/pg/index.workerd.ts`, whose `schema()` installs the compilers before it builds. Wrangler keeps that call because `schema` is declared in that file. Node resolves `import` and does not load it. That JavaScript file is the one dialects import of `node:module`, so a consumer typecheck with `types: []` does not need Node types. A literal `require()` is inlined into the app bundle, so the loader uses `createRequire`. A table that sets `exclusions` loads `exclusion.ts` while `schema()` runs, so OKM1060 still throws there. A featureless app does not. A new table option stores a descriptor and emits from `catalog-compile.ts`. It must not add a static import to `schema()` or `table()` that a featureless app cannot tree-shake. The catalog hash is still the full document. Connect without an artifact hashes that document. Queries do not. `column-mark.ts` stays on the startup graph because composite enum labels are read while the query model is built. `identityKey` lives in `identity-key.ts` so `staticNamespace` does not load the JSON encoder. No new `ErrorKind`. No public API change. No catalog hash change. Method: `measureStubbedStartup` in `scripts/size.ts` (Bun.build, minify, splitting, dynamic imports stubbed, `postgres` external) 109,235 / 35,552 to 85,063 / 28,743. Issue: none (PR only)
