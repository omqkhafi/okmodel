# D231 — Row-level security is `rlsTenancy` and the role check is the first scoped call (P83)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`rlsTenancy({ key: "tenantId", type: "uuid" })` from `okmodel/tenancy`. One key. `via()` and `compositeTenancy()` on that schema are refused at schema build. The column predicate stays on every statement. `okm generate` emits `ENABLE` and `FORCE ROW LEVEL SECURITY`, policy `{table}_tenant` for all commands (`tenant_col = nullif(current_setting('app.tenant', true), '')::<type>`), and policy `{table}_unscoped_select` for `SELECT` (`current_setting('app.unscoped', true) = 'on'`). A `global()` table gets no policy. A non-rls catalog hash does not change. Every scoped call starts a transaction with `select set_config('app.tenant', $1, true)`. A user `tx()` sets it once. A read is `BEGIN READ ONLY` and follows the operation's route, including a replica, through `okmReadOnlyUnit` on the lazy router. That unit is inlined there so the router does not import the rls module. `unscoped()` reads set `app.unscoped`. An `unscoped()` write is OKM1701. The role check runs on the first scoped call per pool, before any statement, and is cached. It refuses a superuser, then `BYPASSRLS`, then the table owner (OKM1707, `reason`). It is not in `connect()`. A view over tenant tables is `WITH (security_invoker = true)`. Other strategies omit it. Policies protect a missing predicate. They do not protect arbitrary SQL that sets `app.tenant` as the application role. Measured with `bun run size` inside `bun run check`: runtime entry 5,288 / 2,026 (cold import 1.765 ms).
