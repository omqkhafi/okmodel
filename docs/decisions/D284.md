# D284 — `describe` and `buildCatalog` on `okmodel/migrate` (P118)

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

The programmatic schema API is `describe(schema)` and `buildCatalog(description)` on `okmodel/migrate` (D26). Nothing is added to the runtime entry, to `schema()`, or to an adapter. `describe` returns JSON. `logical` is `namespace`, `name`, and `format` (R5), and those three are `public`, `public`, and `1`: the namespace `schema()` compiles. `defineConfig({ namespace })` places the catalog after that. Placement changes the catalog hash and does not change `logical`. `catalog` is the catalog document `serializeCatalog` already writes, with sorted keys and no functions. `buildCatalog` reads that document, including after `JSON.parse`. The catalog hash matches the catalog built from the schema. Codecs, client generators, and relation helpers stay on the schema. They are functions, and the hash does not include them. `okm catalog export` stays the column snapshot (D277). There is no sync API. No new error kind and no new OKM code.
