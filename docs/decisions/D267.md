# D267 — `okmodel/otel` maps the existing observers (P105)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

The entry is `okmodel/otel`. It does not import `@opentelemetry/*` and it is not a dependency. The caller passes a tracer. There is no meter: §5.5 and the M2 row name `db.*` span attributes and the fingerprint as the query summary, not a metric. `otel({ tracer, statement? })` returns `hookm`, `onRoute`, and `query`. `hookm` and `onRoute` are the observers `connect` already calls. `query` takes an `inspect()` result, because those observers do not carry a fingerprint, statement text, or a table. A route span is named for the hook's `op` (`read`, `write`, `tx`, or `lock`). `db.system.name` is `postgresql`. `db.operation.name` is that same op. The span kind is client (`2`). The endpoint and the reason are a span event named `route`: they are not database attributes. The span starts and ends in that call. `onRoute` fires once, when the endpoint is chosen, so the span has no duration. A transaction span opens on phase `start` and ends on `commit` (status OK) or `rollback` (status ERROR, `error.type` `rollback`). Depth 0 is named `transaction`. A greater depth is `savepoint`. Overlapping work at one depth pairs last-in, first-out, because the event has no span id. `onError` records `error.type` as the error name and, when the error has an OKM code, that code on the exception, with no message and no stack. A query the caller receives as a throw is not an `onError`. `query(inspect())` sets `db.collection.name` to the table, `db.operation.name` to the call (`find`, `one`, and the other read names), and `db.query.summary` to the fingerprint (§5.5). `db.query.text` is set only when `statement` is true, and only from that inspection. Parameters are never attributes. A tenant id is not an attribute: the spec does not ask for one, and `where` is not copied. The entry is experimental. Nothing in the query path, the runtime entry, or a gated graph imports it. No gate is added. Issue #284
