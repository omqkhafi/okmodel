# D178 — P27b accepted: a column takes the objects its codec declares; list inserts take different keys

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

Verified on Postgres 17 before fixing. (1) Reproduced: `insert`, `update` `set` and `where` refused every object with OKM1121, including Temporal values for `timestamptz`, `timestamp`, `date`, `time`, `timetz` and `interval`, json and jsonb, arrays, bytea, ranges and points. A `Date` is not an input of any default codec, so it stays OKM1121 and is not a bug. (2) Fix: each codec names the object kinds it takes (`accepts`, as `Object.prototype.toString` spells them), carried to the planner on the column; a column with none refuses every object, so the operator-object guard is unchanged for text, integer, uuid, bigint and the rest. `t.custom` gains an optional `accepts`; without it a custom column refuses objects. One planner function (`takeObject`) serves insert, `set`, and the operands of `eq`, `lt`, `lte`, `gt`, `gte`, `between`, `inList`, `notIn` and `not`. A range object without `empty` is OKM1210 before any statement. (3) Spec differences accepted: in a `where` a bare object is refused for every column and `eq(value)` is the equality form for any object value, not only json and jsonb. (4) The array-insert key finding does not reproduce at runtime (different keys, `undefined`, `null`, defaults, tenancy, archivable, validation, conflict clauses and chunking already match single inserts); it was a types bug, the list overload required every key; fixed in `types.ts`. (5) Found: `interval` and `timetz` cannot be read back (see D179). Size: featureless app 88,393 / 29,385 (+115 / +60, exactly on the stop line); no gate or ceiling moved; `query-200-validate` 24,888 and `page+aggregate+through` 24,070, both about 3.0% under their ceilings.
