# D183 — P30 finding resolved; hygiene and size choices

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

(1) `batch` refuses `restore` and any write that carries `expect` with OKM1121 (option (a) of D182): a check that needs the statement's result cannot run inside an atomic unit on a batch-mode driver, so the rule is the same on every driver and fails closed instead of reporting after commit; `tx()` is the way to do it. Option (b) (move the checks into SQL that raises) is not 0.2; it can be reconsidered when a batch-mode adapter exists. The fix goes on the P30 branch as a second commit with a regression test (every write kind in a list, blocked restore and wrong `expect` both refused before any statement) and a stop line of +30 / +15 on the featureless app. (2) Duplicated helpers (`noteArchive`, `requireFilter`, `primaryFields`, `isPool`, `statsOf`, `asParams`, `refuse`, `isRecord`) are not deduplicated in 0.2: sharing them moves bytes onto the startup graph or pulls the write chunk into the archive path, and room is 2,062 / 222. A dedupe is allowed only as a step that shrinks or keeps the bytes. (3) The entry-chunk size pass is not in 0.2. It is the first step of the 0.3 train, before P40, because the extension, function, view and role features need startup room; it starts with a measurement (the report's 2,700 to 4,000 gzip estimate is unmeasured), has a stop line, and no gate or cap moves without Ali. (4) Registered codes never thrown: 24, mostly for later trains; the three that belong to 0.2 specified behaviour (OKM1110 engine version, OKM1191 no snapshot plan, OKM1702 unverifiable tenant SQL) are checked in the same follow-up commit: each is either thrown where the spec says it is, or the spec says it is not reachable in 0.2 (typed raw SQL is M2; no public runtime path takes raw SQL on a tenant table). OKM1111 is added to the spec error table; OKM1000 in the spec is a range label, not a code. Found in P30
