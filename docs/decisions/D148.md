# D148 — Keys: the quickstart exposed a gap

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

P17D found that the only UUID primary key is `t.id()`, which always defaults to `uuidv7()` (Postgres 18 only, OKM1812 below it), is guarded and cannot be supplied on insert; a normal column has no `.primaryKey()`, and there are no composite or natural primary keys. So the README had to teach a table without a primary key. Fix in P17G: `.primaryKey()` on a column and a composite primary key option; `t.id()` takes an explicit default (`uuidv7()` or `gen_random_uuid()`, the latter from Postgres 13) and the OKM1812 fix text names it; an id the caller supplies is allowed when the default is `none`. Until then the 0.1.1 README uses `t.identity()` (bigint identity primary key, works on every supported version). Found in P17D
