# D103 — Migration failure

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

A migration is atomic in one transaction where PostgreSQL allows it; steps that cannot be transactional are split out by the planner and marked; every step checkpoints in the target's history; a failed run stops at the failing step and a later `apply` resumes without repeating finished steps (a failed concurrent index is dropped and rebuilt); `apply` holds a session-level advisory lock per target, a second concurrent apply fails with OKM1522. Reason: partial failure is the normal case on large databases and must be resumable and non-racing
