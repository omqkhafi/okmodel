# D213 — CI runs the check steps in parallel

- **Status:** historical
- **Area:** ci
- **Supersedes:** none

---

`bun run check` on one runner was the remaining wait, about six minutes, because format, lint, types, tests, and the package checks ran one after another. A pull request update starts that one run. CI runs the steps as `area / piece` checks (`CI / lint / static`, `CI / types / compiler`, `CI / test / <group>`, `CI / runtimes / portable`, `CI / package / checks`, `CI / attest / measure`, `CI / label / paths`, `CI / lint / pull request`). A long test group is split: `migrate` and `migrate pg`, `drivers` and `rows`, `schema`, `columns`, and `schema pg`, `tenancy`, `client`, and `client pg`, plus `package`, `contracts`, and `safety`. The required status on `main` is `gate / check`. It passes when every slice passed and fails when one did not. `bun run check` on this machine stays one command. The release workflow still runs that command. No runtime change. Issue #152
