# D113 — Versioning and changelog

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Every merged prompt adds notes under `## Unreleased` in `changelog.md` and bumps the version with `bun run bump next`, which moves `package.json` to `<next release>-next.N` (for example `0.1.0-next.3`); the gate prompt of a release train ends with `bun run bump release`, which drops the suffix and promotes `Unreleased` to a dated heading. The first releases are 0.1.0 at P17, 0.2.0 at P30, 0.3.0 at P44, 0.4.0 at P55 and 0.5.0 at P66. Only released versions are published and tagged. CI fails a pull request whose version equals the one on `main` or whose `changelog.md` has no new entry. The `okm-ship` skill writes the notes and ends with `bun run bump next`; `bun run bump` gains the `next` and `release` kinds next to `patch`, `minor`, `major` and `--set`. Changelog area headings use the plain layer names (`contracts`, `dialects`, `adapters`, `runtime`, `tooling`, `docs`). Reason: the version and the notes must follow the work without anyone remembering to update them, and pre-release versions do not pretend to be patches of a release that has not happened
