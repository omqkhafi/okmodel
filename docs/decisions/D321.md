# D321 — Date and time modes

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Decided with Ali on 2026-11-03 for 0.10.3. A date or time column is `"iso"` (default), `"date"`, or `"temporal"`: `schema({ defaults: { time } })`, and `{ mode }` on `date`, `time`, `timetz`, `timestamp`, `timestamptz`, and `interval`, which wins. The object form also takes `precision` (`fields` on `interval`); the positional forms stay. The mode is client only: catalog, hash, SQL, and migrations do not change. Row types follow it: a column that names no mode is typed `TimeText<K>` (a string) and `schema()` swaps it when the default is `"date"` or `"temporal"`. Audit on Postgres 15–18, `TimeZone` UTC, `DateStyle` ISO, `IntervalStyle` postgres: `timestamptz` text is `2026-11-03 09:00:53.582634+00` (fraction trimmed, offset `±HH`, or another offset when the session zone is not UTC); the typed read path already projects bare `timestamptz` and `timestamp` through `to_char(... 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')`; `date` is `2026-11-03`; `time` is `09:00:53.5`; `timetz` is `09:00:53.5+05:30`; `interval` is `1 day 02:00:00`. Canonical `"iso"` reads: `timestamptz` `YYYY-MM-DDTHH:MM:SS.ffffffZ` in UTC, six digits (another offset is moved to UTC with the microseconds kept); `timestamp` `YYYY-MM-DDTHH:MM:SS.ffffff`; `time` `HH:MM:SS.ffffff`; `date` as sent; `timetz` and `interval` as sent, not ISO-8601 (no duration parser is added). `infinity` and BC values come back as sent. `"iso"` writes take ISO-8601 text (`T` or a space; an offset required on `timestamptz`, refused on `timestamp`), and malformed text is OKM1210 before the database. `"date"` is a `Date` for `date`, `timestamp`, `timestamptz` (milliseconds; `timestamp` and `date` as UTC); other types keep the `"iso"` text. `"temporal"` is the previous behaviour. Codecs: `time.ts` keeps only the ISO encode a literal default needs; ISO decode, `Date`, and Temporal codecs are `time-codec.ts`, loaded by the server check before the first query (`loadTimeCodecs()` loads them without a client). A `temporal` column with no `Temporal` global is OKM1210 from `connect()` through a schema hook, naming the runtime. Bucket day keys, `min`, `max`, and typed `raw()` follow the mode. `.defaultNow()` is exactly `.defaultSql("now()")` on `timestamptz`, `timestamp`, and `date`. A `Date` or Temporal object passed to `.default()` is OKM1060 (frozen at schema load). `codecs.timestamps` moved to `defaults.time` and is OKM1060. `okm init` writes `defaults: { time: "iso" }`; `okm init --time` sets it in an unmodified generated schema. Ranges stay Temporal. No new error code or kind. Amends spec §6.6. Issue: #668
