# D373 — A durable change feed on `watch`

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

Amends D367 and D368. `watch: { feed: { keep } }` stores one row per changed key in the managed table `okm_changes` (xid8, identity `seq`, `rel`, `op`, `key` jsonb, `tenant`, and `at timestamptz default clock_timestamp()`). `keep` is a duration. `{ push: false, feed }` installs the feed and no `NOTIFY`. Statement triggers insert from transition tables, one insert per statement. Truncate writes one `truncate` row with an empty key and a null tenant, and every consumer of that table receives it. A reader takes rows with `xid < pg_snapshot_xmin(pg_current_snapshot())`. The cursor lives in `okm_cursors`, one row per table and consumer name. The active consumer holds a session advisory lock and prunes by `keep`; a cursor behind `okm_feed_floor` calls `onResync` or throws OKM1935. `{ tx }` on a URL the shared pooler signal calls pooled is OKM1936. The column is `rel` because `table` is a reserved identifier. No new `ErrorKind`. No catalog hash algorithm change. Issue: none (PR only)
