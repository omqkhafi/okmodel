# D352 — Identity options, shared sequences, per-scope counters, and numbered references

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`t.identity({ generated, start, increment, cache, min, max, cycle })` stays the row id. `generated` defaults to `"always"`. `"byDefault"` makes the insert value optional. `scope`, `reset`, and `when` on identity are OKM1060 and name `sequence()` from `okmodel/seq`. A number people see is `sequence()` from `okmodel/seq`, used as `sequence(name, options).column({ by, scope, when, moves })`. There is no `t.sequence` on `okmodel/pg`: that call would sit on the app startup graph. `.next()` and `.default(seq)` are not public. No `scope`, `reset`, or `when`, and not a tenant table, is a PostgreSQL sequence owned by the column. Gaps after rollback are normal. `cache` can hand values to one session ahead of another. `ALTER SEQUENCE` changes increment, cache, min, max, and cycle and does not restart. A changed `start` is OKM2120 and is not restarted. Shrinking or changing `as` in place is OKM2124. Otherwise one counter table per series, not per tenant. The key is the scope columns and the period. `insert ... on conflict do update ... returning` locks the counter row until commit. A generated `security definer` function (`search_path` `pg_catalog, public`) plus a `BEFORE INSERT OR UPDATE` trigger assigns the number for every writer, including raw SQL. The app role has no privilege on the counter table. The counter is not a catalog object and gets no tenant policy. The definer does not read the user table (OKM2112). A scope column with a foreign key to the user table is copied onto the counter with `ON DELETE CASCADE`. A unique index covers scope, period, and number. `moves` defaults to `"refuse"`; `"renumber"` assigns a new number. Tenant tables include every tenant key. `via()` has no tenant column, so `scope` is required. A new scope starts at 1. `reset` is `day`, `week`, `month`, `quarter`, `year`, or `{ every, unit, from }`. `at` is required when `by` is `timestamptz`. `when` leaves the column null until the expression is true. `numbered()` is a stored generated column: prefix, then `lpad` of the text with `greatest(pad, length)`, never plain `lpad` and never `to_char`. `okm doctor` prints `setval` when a sequence is behind (OKM2205), warns from 50% of the range (OKM2206), and reports a counter behind its highest number per scope and period (OKM2207). `okm check` warns on DELETE plus a counter (OKM2118, `archivable()` suppresses it), a unique reference that omits the period (OKM2119), and a year taken from `timestamptz` without `at time zone` (OKM2123). Bounds are OKM2121. A series still used, or a counter key change, is OKM2122. `okm pull` writes `sequence()` for a standalone sequence and skips identity-owned sequences. Reference rows that set an explicit id add `OVERRIDING SYSTEM VALUE` when the identity is always, then one `setval` that does not rewind. Grants on sequences are usage, select, and update, checked with `aclexplode`. `okm access` labels a sequence `sequence <name>`. Registry keys: `identity.options`, `sequence.native`, `sequence.counter`, `sequence.reset`, `sequence.when`, `sequence.numbered`, `grants.sequence`. `comment.sequence` was already proved.
