# D287 — A fragment refuses a backslash (B-01)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`scanLiteral` only treated a doubled quote as an escape. Postgres also treats a backslash as an escape in an `E` string and when `standard_conforming_strings` is off, so a fragment that closes a quote with a backslash escape desynced the guard: `;`, `--`, `$`, and parentheses went unchecked and a tenant filter could be escaped. Decision: refuse any backslash in fragment template text with OKM1125 and the fix "pass the value as an interpolation". That covers an `E` string escape, a hex escape, and the scs=off case. Dollar quotes, `;`, `--`, and `/*` stay refused outside quotes; inside quotes they stay plain text. Doubled quotes and `U&'...' UESCAPE` without a backslash keep working. The same `compile` path guards `fragment`, `raw`, and nested fragments; `sql-fragment.ts` only emits parts already scanned. No new public API. No new error kind. No catalog hash change. No gate or ceiling moves. Issue #334
