# D340 — `okmodel/expr`: typed expressions as plain data, comparisons stay the `where` vocabulary, printing and the scratch check are tooling

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

New lazy subpath, not imported by the app entry, with 20 helpers and the list encoder (cap 25): `col`, `add`, `sub`, `mul`, `div`, `mod`, `and`, `lower`, `upper`, `length`, `concat`, `coalesce`, `nullif`, `cast`, `jsonText`, `extract`, `atTimeZone`, `caseWhen`, `now`, `setting`, plus `settingList`, `isExpr`, and `nodeOf`. A node is plain data behind a symbol brand (JSON cannot create one, as for operators). The result type, nullability, and volatility are in the TypeScript type; one stable operand makes the result stable; `ImmutableExpr` rejects a stable helper at compile time (`tests/expr.test-d.ts`). There is no second comparison API: `eq`, `lt`, `lte`, `gt`, `gte`, `between`, `inList`, `or`, `not` are the existing operators and an expression is a valid operand (`lt(col("limit_qty"))`), so `plan.ts` and the app startup graph are untouched. Parameter-free printing reuses `emitWhere` with a sink that writes each bound value as a literal (`printWhere`, `src/tooling/migrate/expr-sql.ts`); a codec may bind a bigint, number, or boolean, so those print as they are; NUL text, a relation filter, and a value the codec refuses are OKM1120 or OKM1121 before any SQL. `concat` prints `coalesce(a, '') || coalesce(b, '')` and takes text only, because SQL `concat()` is stable. `cast` and `extract` involving a `timestamptz` are stable; `atTimeZone` with a fixed zone is immutable (checked in `pg_proc` and by a generated column on 15, 17, and 19). `setting` prints `(select nullif(current_setting('x', true), '')::type)`; a list type prints the cast outside the subselect (`((select coalesce(nullif(...), '{}'))::text[])`), because inside it `= any(...)` with a typed left side fails with 42883, and `settingList` double-quotes every element, escapes backslash and double quote, writes NULL bare, and `{}` for an empty list: a plain join fails six of twelve cases. A generated column and an index refuse the subselect itself (0A000), so `setting` is for policies, checks, and queries. Known limit: the volatility of a `where` object inside `and()` or `caseWhen()` is not tracked by the type and counts as immutable, so Postgres decides. `checkScratch` (`scratch-check.ts`) runs statements in one transaction that always rolls back, on an in-memory PGlite or a provisioned URL, and returns the SQLSTATE and OKM1848 (`now()` in an index is 42P17, `to_char(timestamptz)` and `concat()` in a generated column are 42P17, a missing function is 42883). Two codes are new, OKM1847 and OKM1848, both kind `invalid`. Issue: none (PR only)
