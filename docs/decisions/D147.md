# D147 — npm README is per version

- **Status:** accepted
- **Area:** docs
- **Supersedes:** none

---

The README on npmjs.com is the one inside each published version, and relative links in it do not resolve (the quickstart, production checklist and known-limits links showed red on the 0.1.0 page, and the page told a new reader nothing about how to use the package). So the README must be self-contained: install, a runnable quickstart with the real commands, the command list, what 0.1 does not have, measured size, and absolute GitHub links for the longer docs; a CI check fails on a relative link in the README, and the README's code blocks are run by the docs-as-tests quickstart test (D144). A README fix reaches users only with a new version, so it ships as 0.1.1; the release workflow stops hard-coding `v0.1.0` and accepts a tag equal to `v` plus the `package.json` version. Found after the 0.1.0 release
