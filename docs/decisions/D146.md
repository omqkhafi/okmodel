# D146 — Release 0.1.0 and how it publishes

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`okmodel@0.1.0` is on npm with `latest` pointing at it and a signed provenance statement. The release workflow publishes with `npm publish` (Node 24, npm 11.5.1 or newer) through an npm trusted publisher for `omqkhafi/okmodel`, workflow `release.yml`, no environment, and stores no npm token: `bun publish` cannot do the OIDC exchange (oven-sh/bun#22423) and failed twice with `missing authentication`, which a re-run could not fix because `workflow_dispatch` uses the workflow file on the selected ref. The `v0.1.0` tag was moved once onto the commit that fixed the workflow (16e475d, pushed to `main` directly), which was safe only because nothing had been published; a published tag is never moved. The package is still built with Bun (`prepublishOnly` stays `bun run build`). npm 11 prints that it removed `bin[okm]` and `bin[okmodel]`, which is its rewrite of a leading `./`; the published manifest must keep both commands, checked with `npm view okmodel@0.1.0 bin` and a run of `okm` from a fresh install. Hardening to do: set the package's publishing access to the option that requires two-factor authentication and disallows bypass tokens (trusted publishing still works), delete any stray npm token in the repository secrets, and add a tag ruleset for `v*` (and a release environment with approval once there are other contributors), because a trusted publisher trusts any run of `release.yml` in the repository. After the tag, `bun run bump next` must move the version to the next release's `-next.N` and open a new changelog heading; P20 verifies that. Found in the 0.1.0 release
