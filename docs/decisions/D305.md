# D305 — Versioned `update` requires `version` in the type (Q5)

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

D254 left `version` optional on `UpdateTarget` and required it only at runtime. Decision: `versioned()` stamps `~versioned: true` on the table type (same shape as `~archive` for `archivable()`). `TableApi.update` selects a required-`version` target when that flag is present; a non-versioned table keeps `version` optional on `UpdateTarget`. O-5 adds one member on that target: `version: "any"` is legal only with `lock: "skip"` and `limit`, and that call returns the claimed rows (an empty array when nothing matched). Every other versioned update still requires `version: number`. The runtime OKM1120 for a missing `version` stays as the backstop when types are bypassed. Per-row update lists and `expect` are unchanged. No new ErrorKind. No catalog hash change. The per-table conditional measures +26 instantiations and +7 types on the 200-table query probes (extensions 17,312 instantiations, features 6,938 types). Ceilings move by the D176 rule (measured plus 3 percent, rounded down): inferred-200 instantiations 17,300 → 17,831; query-features types 6,931 → 7,146. No size gate move. Types lane starts here (Q5, then Q7, Q6, Q3, R7). Issue #392
