# D301 — Linter accepts the planner's own NOT VALID / VALIDATE pair on a new column

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

Tooling only. No planner change. OKM1531 already exempts a `widen-check` validate and the temporary `IS NOT NULL` floor validate. It also exempts a `VALIDATE` whose matching `ADD CONSTRAINT … CHECK … NOT VALID` is earlier in the same migration when every column of that check was `ADD COLUMN`ed earlier in that migration with a non-volatile default, or as a nullable column with no default. Pairing matches `notNullFloorValidate`. A check on an existing column, a volatile default, and every other validate stay OKM1531. No new ErrorKind. No catalog hash change. No gate or ceiling moves.
