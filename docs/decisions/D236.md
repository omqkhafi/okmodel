- **Area:** tooling

`rlsTenancy` stores the policy text `pg_get_expr` prints. A lowercase unreserved column stays bare, so `(tenant_id = (NULLIF(current_setting('app.tenant'::text, true), ''::text))::uuid)` is unchanged and the snake-case notes catalog stays `4d4cb5789b2d906687fb778b2415b222862cab1acd52b2356fae4251f99de9cf`. `tenantId` is `("tenantId" = …)`. `TenantId` and the reserved words `user` and `order` are quoted the same way. A reserved word is still OKM1122 at schema build. The default-casing notes catalog moves from `79c039a8f2826eca3e01aa3c23214790639228c56dda9c89b68754fe602f9544` to `d1996ab9c5b461dc7d9a0f05cf151e9876a19e8b83cc6a2df7c779b73bb750aa` because that expression could not be applied: Postgres folded the bare name to `tenantid`. The planner pulls the referenced unique in front of the foreign key, and drops reverse that list. `parseCatalog` builds a materialized-view index with `materializedViewIndex`, so the document no longer depends on a column that is not in the catalog. Generate, apply, and check accept one column or several, unique or not. Table-index documents round-trip as before. Apply revokes `INSERT`, `UPDATE`, and `DELETE` on a materialized view from a role whose table defaults include those privileges. The catalog stays select only. `GRANT USAGE ON SCHEMA` that does not add the grantee fails with OKM1825 (`kind` `forbidden`). The fix is `ALTER SCHEMA <schema> OWNER TO <migration role>`. No new error kind. `okm migrate check` makes an existing migration role the owner of the scratch schema and retargets `ON SCHEMA` as well as `"public".`. The namespace grant recorded from a scratch schema uses the logical schema name. `withOwner(..., "ignored" \\| "external")` is read from `table.name`.
