# D129 — Engineering standards

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Every prompt is built for the best performance, speed, lightness and cold start, not only to pass tests. Rules: nothing is added to the runtime entry without need (tooling stays out of it, `sideEffects: false`, lazy work, no module-level computation); no duplicated logic (one helper, one place); small, obvious public API with clear names, precise types and actionable errors; no avoidable allocation or repeated work on hot paths; every report states runtime entry size, cold import, and any type-cost change; each prompt ends with a self-review against these rules before the report. Budgets in D127 stay the hard limits; these rules are the habit that keeps us under them. Added by Ali on 2026-10-02
