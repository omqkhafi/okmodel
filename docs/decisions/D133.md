# D133 — Gated measurements and ratchet after P12

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Type cost is gated on what a consumer pays: fixtures compiled against the built declarations with `skipLibCheck`; source-based numbers are reported only. Ceilings ratchet to measured +25% (D127 rule): inferred 200 tables ≤ 17,300 instantiations / ≤ 6,500 types; 500 tables ≤ 42,400 instantiations; ≤ 84 instantiations per added table; emitted consumer ≤ 700 types (kept); column sample ≤ 720 instantiations / ≤ 1,100 types. The tagged-operator surcharge keeps its source-based ceiling (800) because the declaration number is 0. The package `dist/` byte ceiling (unminified, install size) moves from 184,000 to 241,000 because `table()`, `schema()` and `emitRowTypes` joined the Postgres bundle; the figures that matter for startup are the app-bundle ceilings: 10 tables with 8 column types, tree-shaken, ≤ 48,000 bytes min / ≤ 15,800 gzip / cold import ≤ 15 ms (D127). The 0.1 runtime budget (60 KB min, D127) is already 38 KB for core + schema; watch it in P13–P16 and finalise at P17. The serialised-catalog loader must trust a build artifact (stored version and hash, no re-validation, validation only in `okm check` and dev): measured 8.2 ms to load vs 7.0 ms to build, of which 7.1 ms is validation and object building; implemented with `okm build` in P16
