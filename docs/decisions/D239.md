- **Status:** accepted

`refresh()` returns a thenable and runs on the first `await`. `batch([view.refresh()])` is OKM1121 before any statement, so an unawaited failure is not an unhandled rejection. The refresh reserves the primary and sets `app.unscoped` in that transaction. Under `FORCE ROW LEVEL SECURITY` the owner then sees the source rows. `CONCURRENTLY` sets the session value and clears it before release, because that form cannot run inside a transaction. There is no option to refresh as another role. The application role is kind `driver`, reason `not_owner`, and the message names the migration role. A plain view has no `refresh` at runtime. A `refresh` value other than omitted or `"concurrently"` is OKM1120. A populated materialized view is not RLS-protected. The column predicate and OKM1820 guard it. Bun.sql and PGlite throw OKM1120 when a positive `timeout` is passed. The kind is `invalid` and the message is `timeout`, which keeps those connect graphs under their gates.
