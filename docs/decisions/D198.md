# D198 — Reference rows live on the schema; an empty target installs the head catalog

- **Status:** accepted
- **Area:** contracts
- **Supersedes:** none

---

A migration file stores catalog JSON, not a second copy of the DDL. The head snapshot is the last catalog. Installing it plans that catalog from an empty catalog, so grants and roles are included and a new table keeps the plain statements. `reference` rows stay on `table({ reference })`. They are not copied into the catalog and they do not change the catalog hash. Apply and `provision(target)` insert a missing key and never update or delete, so a label change does not update, a dropped declaration does not delete, and a new key is inserted on the next apply without a DDL migration. An empty target (no `okm_meta`, `okm_history`, or `okm_backfill`, and no other relation, enum, domain, or extension in the namespace) records `provisioned@<migration id>` and does not replay steps. A target that already has those history tables stays on the replay path. A non-empty target with no history is OKM1851. Provision on an empty protected target is allowed without `--allow-protected`. `provision(target)` is one configured target. Registry `create(id)`, schema-per-tenant, and database-per-tenant are M5. `okm migrate check` stays the P53 replay. `--provision` compares a snapshot install with that replay after `canonicalTypeName` (D191) and reports OKM1521. OKM1542 flags a data statement outside backfill. Reference inserts are not migration steps, so they are not flagged. No new error code. No gate, cap, or ceiling moves. Found in P53A. Issue #82
