# D249 — Atomic operators stay the documented four; a claim is lock skip plus limit (P93)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

The audit found the operators already shipping. `inc`, `json.set`, `arr.append`, and `arr.remove` compile in `write.ts`, which loads on the first write. `json.set`, `arr.append`, and `arr.remove` were already typed on those columns. `inc` was typed on every update field. `find` already takes `lock: "update"` or `"share"` and `wait: "nowait"` or `"skip"` inside `tx()` (OKM1830). There is no `findMany`. `lock: "skip"` on a read is OKM1120 and the message names `lock: "update"` and `wait: "skip"`. `nowait` stays a read wait. `wait` on `update` is OKM1120. The gap was the update claim (tool 14). `update` of one target accepts `lock: "skip"` together with `limit`. The statement updates the table and selects the physical row with `tableoid` and `ctid`, skip locked, and a bound limit. `ctid` alone repeats on another partition and on an inheritance child, so a limit of one could change a row the filter did not select. The query table model has no partition flag and no inheritance-parent flag. The catalog records declarative partitioning on the table definition and does not record an inheritance parent. A primary key is optional, so the claim does not switch to it. Every claim matches both columns. A path-parent update that used to rewrite by `ctid` matches the same pair. A path list update still applies the caller's where and does not rewrite by `ctid`. The write owns that statement, so it runs on its own or inside `tx()` and `batch()`. Rows another transaction holds are skipped. A list cannot claim. `limit` without `lock`, or `lock` without `limit`, is OKM1120. `limit` must be an integer from 1 to 2147483647 (OKM1121). A path-parent move together with a claim is OKM1120. There is no `orderBy` on a claim. `inc` is now only a number or a bigint column. A text column is OKM1124 (`inc adds to a number. title is a text column.`). A `numeric` or `bigint` stored as a string is still outside that type, the same hole as `sum` and `avg`; the statement accepts `inc` when the database type is numeric. A null number stays null. There is no `dec`, no `mul`, and no coalesce helper. A per-row list that sets one field with an operator in one row and a plain value, or a different operator, in another is OKM1120 (`qty is both inc and a value in this update.`). The same operator on every row stays one update. A repeated target stays OKM1120 (D246). New code stays in `write.ts` and `lock.ts`. Both already load on first use. No new lazy chunk. No runtime entry change. No new error kind. No catalog hash change. No public return type change. No gate move.
