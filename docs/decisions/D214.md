# D214 — Runtime reliability for a replica, a close, and error text (P69, QA-M1, QA-M5, QA-L8, QA-L9, QA-L11, QA-L12)

- **Status:** accepted
- **Area:** runtime, contracts
- **Supersedes:** none

---

A read that a replica refuses or drops falls back to the primary on postgres.js, node-postgres, and Bun.sql, and `onRoute` reports `fallback:unhealthy`. The deep check walks `cause`, each `AggregateError.errors[]` entry, nested `code` and `errno`, and the Bun.sql codes. It has a depth of 8 and a cycle guard. It lives in the lazy topology chunk, and the startup graph keeps the shallow check. A driver error with an empty message takes the first inner message, or `driver error`. Closing a client before `connected` settles leaves a clear `unavailable` error on `connected` and no unhandled rejection. 42P01 and 42703 map to `undefined_table` and `undefined_column`, with a fix that names `okm migrate apply` and `okm migrate status`. TLS and certificate codes map to `unavailable` with reason `tls` and a fix that names `sslmode`. OKM1104 lists each accepted constraint once and names the tenant key once. OKM1200 reads `Validation failed: <field> <reason>`. Calls that share one caller signal share one abort listener. Cap for this step, once: no connect graph grows more than +800 minified or +250 gzip over D210, and the runtime entry stays within +100 minified or +40 gzip. Measured against D210: runtime entry unchanged at 5,288 / 2,026; featureless app +313 / +121; postgres.js +464 / +152; PGlite +464 / +138; node-postgres +464 / +144; Bun.sql +464 / +152. Each connect gate is raised to the measured value +50 minified and +20 gzip, rounded up to the next 50 and 10 (table below). Type probes are unchanged.
