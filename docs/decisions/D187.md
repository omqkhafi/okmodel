# D187 — The second release failure was the publish argument; 0.2.0 is folded into 0.2.1

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Release run 37264007346 passed the tag job, all eight Postgres jobs and Check, then failed in `npm publish packed/okmodel.tgz`: npm reads a path without `./` as the git shorthand `user/repo` and tried to clone `github.com/packed/okmodel.tgz`. It was never an npm permission or trusted-publisher problem. The fix is `npm publish ./packed/okmodel.tgz`, and `tests/release-gate.test.ts` now fails when any `npm publish` argument in any workflow does not start with `./` or `/`. Because 0.2.0 never reached npm, it is not released on its own: the fix lands in PR #113, 0.2.1 is the first public release and includes everything listed under 0.2.0, and the changelog says so. The `v0.2.0` tag is deleted from the remote and not re-created, so no release tag is moved a third time. Lesson: a release workflow cannot be proven by its tests alone; the first real run is the proof, and each failure so far (Deno missing, bare publish path) was invisible to every earlier gate.
