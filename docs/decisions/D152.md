# D152 — Scripts exit by themselves; `await using` closes the client

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

A connected client gets `Symbol.asyncDispose` (attached only when the runtime has the symbol; the built declaration hides it behind a conditional type so no consumer lib breaks), and a second `close()` shares one promise. Measured: postgres.js starts two referenced timers (idle and lifetime) we cannot reach, so unref'ing alone does not help; the plain (non-TLS) pool now sets `idle_timeout: 0` and `max_lifetime: null`, opens its own sockets, unrefs them while nothing is in flight, and refs them again for each call. A finished script exits in about 0.12 s on Node and Bun instead of 30 s, and a long-lived pool keeps its backend pid across a 4 s hold (tested). A pool opened with TLS still uses the driver's socket and the 30 s idle timer; that path is unchanged and documented (P17G looks at it). PGlite already exits on its own. Cost: the app startup graph grew 77,537 / 25,625 to 79,162 / 26,185 and the postgres.js connect entry to 39,569 / 13,715, leaving 0.86% and 0.70% under their gates; no gate moved, and any further change that pulls this adapter needs a ceiling decision first (D138 cap ends with 0.1). Found in P17D2
