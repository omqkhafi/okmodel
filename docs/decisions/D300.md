# D300 — `describe()` reports `minPostgres` and extensions; doctor and check use them; Neon capabilities stay the shared flags

- **Status:** accepted
- **Area:** adapters, tooling
- **Supersedes:** none

---

`describe(schema)` on `okmodel/migrate` adds `minPostgres` (15–18) and `extensions: { name, reason }[]` beside `logical` and `catalog` (D284). The floor is the project floor, the declared `minPostgres` / deprecated `requires.postgres`, or 18 when a column stores `uuidv7()`. `describe()` accepts a `schema()` result, a prior description, or `{ catalog, minPostgres }` and keeps that floor: a carried numeric `minPostgres` is `max(carried, computed)`, so `describe(describe(s))` keeps a declared floor, `describe({ catalog })` with no floor uses the project floor, `uuidv7()` in the catalog still reports 18, and a carried floor outside 15–18 is OKM1020. Extensions come from `extension(...)` records, dependency edges (columns and functions), and index `using … _ops` tails mapped to known packs. `okm doctor` and `okm check` connect and refuse with existing codes: OKM1802 / OKM1803 for the major, OKM1811 for a missing extension. On `okm check`, the major runs before author drift and the extension check runs after it. An extension an applied or pending migration creates is not OKM1811 for a missing install; when that package is absent from `pg_available_extensions`, OKM1811 points at `okm migrate apply` after the package is on the server (#400). Several targets and no `--target` print `server checks skipped: N targets, pass --target <name>` instead of connecting. No new ErrorKind and no new OKM code. Catalog hash is unchanged. Neon already exported `capabilities` / `httpCapabilities` (D269, D296); the shared adapter-contract test asserts both modes use only the existing capability names (`transactions`, `stream`, `listen`, `cancel`) and that the entry re-exports the registry values. No new capability names. No gate or ceiling moves. Issue #369
