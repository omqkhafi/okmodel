# D143 — 0.1 budgets, API freeze rules, requireMeta

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

(1) 0.1 budgets, set at measured +3% (D142): app startup 77,524 / 25,641 measured, gate 79,849 / 26,410; connect entries postgres.js 39,849 / 13,815 and PGlite 38,146 / 13,505 (measured +5%); adapter incremental bytes over the runtime entry 12,074 of 15,093 and 9,608 of 12,010 (+25%); runtime entry 24,426 / 8,584 against 60 KB / 20 KB; total graph 112,001 / 36,162 printed. The `okmodel/pg` barrel (70,046 / 21,872) is printed, not gated: a per-export tree-shake test plus the app fixture are the gates, and P17B confirms that test exists and fails when an export pulls in the whole barrel. (2) `requireMeta` (default off) makes a missing `okm_meta` OKM1520 in `connect()`; nothing is inferred from `NODE_ENV` or a target name (§19.8), so a production setup declares `protected: true` on the target and sets `requireMeta: true`, and the docs say so. (3) Subpaths stay as they are (`okmodel`, `okmodel/pg`, `okmodel/pg/postgresjs`, `okmodel/pg/pglite`, `okmodel/migrate`); the empty `okmodel/testing` entry leaves the exports map until 0.4 and the name is reserved in the docs. (4) Before the freeze every export is classified stable, experimental or internal: exports of `okmodel` that only sibling entries or dialect authors need (`sha256`, `throwNamed`, `nearestName`, `catalogError`, the catalog builders, whose names `table` and `index` duplicate the ones in `okmodel/pg`) are not the application API; internals move behind an undocumented `okmodel/internal` subpath only if no bundle grows, and an API snapshot test per subpath makes an accidental export fail CI. (5) Reserved-option versions follow the plan: `manyThrough` is 0.2 (P27), not unassigned; the error text is corrected and the known-limits page lists `.hidden()`, `.sensitive()`, `.validate()` and every other reserved item by version. (6) Docs state measured numbers only (startup graph, install size, cold import, with the CI source); no size or speed claim without a number. (7) The 0.2 starting point for P30 is 91,000 min / 30,000 gzip on the startup graph (tenancy +2 KB, traits +3 KB, presets +1.5 KB, archive +2 KB, field exposure +1.5 KB; transactions and validation load on first use); it is above the D138 cap, which ends with 0.1, and P30 re-estimates it.
