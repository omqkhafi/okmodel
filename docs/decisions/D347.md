# D347 — Generated column expressions and composite foreign keys

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

`.generated((columns) => expr \| where \| sql)` replaces the raw string. STORED is the default. `{ stored: false }` emits VIRTUAL and needs PostgreSQL 18 (OKM1812, declared floor and a pre-SQL check). A virtual column cannot be a key, a foreign key, a plain index, or a partition key (OKM1920). `index(column)` on a virtual column becomes an expression index on that column's expression. A foreign key target that is not a primary key, a unique constraint, or a non-partial unique index is OKM1921 in plan, check, and apply, not in `schema()`. `foreignKeys` is the composite form. `.references()` stays one column and takes the same options. `deferrable: "deferred" \| "immediate"`. `onDelete: { setNull \| setDefault: [columns] }` is the PostgreSQL 15 list. `match: "full"` is optional. A nullable composite key with MATCH SIMPLE is OKM2108. A data probe that would reject rows stops with OKM1922 and "Nothing was changed." No new `ErrorKind`. The raw-string form is removed. Measured startup of the merged tree (`measureStubbedStartup` in `scripts/size.ts` on `scripts/app-startup.ts`, dynamic imports stubbed, `postgres` external, Bun 1.4.2, `bb3be727`) is 97,381 minified and 31,962 gzip, above 94,680 and 30,850. `query-200-validate` is 7,131 types, above 7,130. Those ceilings are not moved here. Issue: none (PR only)
