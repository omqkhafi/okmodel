# D295 — Tree cycles, Action author, driver test cleanup, testing helpers (B-10, B-22, B-05, B-06, B-42, B-35, B-32, B-28, B-34)

- **Status:** accepted
- **Area:** adapters
- **Supersedes:** none

---

(1) **B-10.** An `update` that sets a tree parent to the row's own id still fails at plan time (OKM1120). An update that would point the parent at a descendant is refused at execute with the same code; the lazy write statement uses a recursive guard and matched/updated counts. A non-key `where` is still unchecked. `batch` refuses that guarded update. (2) **B-22.** The sticky plan comment match requires the marker and an allowed author (`github-actions[bot]`, plus `GITHUB_ACTOR` when set). Another author's marked comment is not patched. (3) **B-05 / B-06.** Wire and error driver-suite cases drop leftover `okm_*` tables before the pool closes. (4) **B-42.** `package.json` `engines.bun` is `>=1.4.0`. `okm driver test` refuses an older Bun with a clear message. Cases without a body stay `unsupported`, never `pass`. (5) **B-35.** A throw from a custom `routing.select` that is an `OkmError` keeps its kind; any other throw becomes kind `invalid` with that value as `cause` (not `driver`). (6) **B-32 / B-28 / B-34.** Factories and `isolation()` work under `compositeTenancy()` by treating every tenancy key as scope and filtering them from `ref()`'s primary key. Concurrent creates use a per-call in-flight set (no shared cycle marker). `isolation()` seeds every composite key on view sources and refreshes matviews; outside that helper, call `db.views.<name>.refresh()` after factory inserts. No new public API. No new ErrorKind. Codes OKM1140–OKM1179 stay reserved. No catalog hash change. Tree check stays in the lazy write chunk. Issue #342
