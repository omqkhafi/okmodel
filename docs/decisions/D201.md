# D201 — P60 topology runtime; connect entries get no more bytes

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

`connect({ primary, replicas })` loads `src/runtime/topology.ts` through a dynamic import only when the first argument is an object and not a pool. A string or a pool stays the previous client and does not load that module. The promise opens one pool per endpoint (`max` is the default; a replica `pool.max` overrides it). The primary is named `primary`, never `replica-0`. Replica names default to `replica-1`, `replica-2`. A probe on each replica runs `SELECT 1` and a replay position every `probe` (default 1s). Two consecutive failures open the circuit; the next delay is `probe * 2^min(max(failures-1, 1), 8)`, capped at 30s. Timers are unref'd and `close()` clears them and closes every pool. `replication.position` is detected per endpoint and stored; routing does not read it. Until P61 every operation uses the primary and `inspect()` stays `single-endpoint`. `routing.select` (P62), `consistency` and `maxLag` (P63), and `fallback` (P61) throw OKM1061. A bad shape is OKM1120. Migrations refuse a target that carries `primary`, `replicas`, `weight`, or `pool` with OKM1845. A shared helper measured larger than four inline copies (featureless app 89,597 / 29,770, postgres.js 41,122 / 14,483, PGlite 39,096 / 13,866, node-postgres 41,532 / 14,651, Bun.sql 40,381 / 14,168) and was not kept. The inline branch is featureless app 89,561 / 29,757 (+100 / +37 over 89,461 / 29,720), postgres.js 41,088 / 14,473 (+98 / +27), PGlite 39,062 / 13,858 (+105 / +32), node-postgres 41,498 / 14,643 (+96 / +27), Bun.sql 40,347 / 14,158 (+96 / +24). Runtime entry 5,288 / 2,026 (+0 / +0). The lazy topology chunk is 7,084 minified and 2,512 gzip. Stop line for P61, P62, and P63: routing, selection, and consistency live entirely in the lazy topology chunk. The connect entries get no more bytes. Bytes left under the gates after P60: postgres.js 512 minified / 127 gzip, PGlite 238 / 122, node-postgres 902 / 277, Bun.sql 853 / 312. No gate, cap, or ceiling moves. Found in P60. Issue #85. D202 spends the `route` key on the connect entries and leaves the rest of this stop line in place. **Amended by D325 (one missed probe at `connect()` opens the circuit; later probes still take two consecutive failures).**
