# D327 — Pull, generate, and check share one expression, and a check may be `NOT ENFORCED`

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

A table check is read from `pg_get_expr(conbin, conrelid)`, not from a slice of `pg_get_constraintdef`. `conenforced` (treated as true where the column does not exist), `convalidated`, and `connoinherit` are the state. `NOT ENFORCED` is `enforced: false` on `ConstraintDefinition` and on `checks`. Absent means enforced. A plain function is unchanged. PostgreSQL stores `NOT ENFORCED` with `convalidated` false by itself: that is not drift and it never emits `VALIDATE`. An enforced check with `convalidated` false still plans `VALIDATE`. `NO INHERIT` is OKM1020. The check key is the real constraint name when it is not `{table}_{key}_check`, so two checks on one column do not collide. generate, check, and migrate check reprint through `sealAuthored`. A difference that is only server normalisation is not a migration. `NOT ENFORCED` needs PostgreSQL 18 (`check.notEnforced`, OKM1812 when `minPostgres` is lower, OKM1802 on an older server). Changing enforcement is `ALTER CONSTRAINT` on 19 and a commented drop and re-add on 18. Pull omits `okm_meta`, `okm_history`, `okm_steps`, and `okm_backfill`. No new ErrorKind. No catalog hash change for a check that stays enforced. No gate move. Issue: none filed
