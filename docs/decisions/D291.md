# D291 — Write safety: unknown keys and sensitive causes (B-39, B-33); B-40 split

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

(1) **B-39.** `insert`, `update`, upsert / `onConflict`, and first-or-create refuse an unknown key with OKM1120. The message names the key and the table (same shape as `orderBy`). Typos are no longer dropped. Guarded, sealed, and computed fields keep OKM1190 and the rest. No new ErrorKind. Codes OKM1140–OKM1179 stay reserved. (2) **B-33.** When the error's table has a sensitive column, or the error names a sensitive column, `mapPostgresError` sets `cause` to a plain object with only safe fields (`name`, `sqlstate`, `constraint`, `table`, `column`, nested driver `code`). It never copies `detail`, `message`, parameters, `where`, or `internalQuery`. Tables with no sensitive column keep today's cause (`error.cause ?? error`). `includeValues` stays the explicit opt-in that can keep values. Covers postgres.js, node-postgres, Bun.sql, and PGlite through the shared mapper. D58 and D125 are unchanged. (3) **B-40.** Split to its own branch. Wiring the protocol parameter check through the read `client` path grew the featureless app by more than 100 B over the stop line (measured +371 minified with the combined change). No OKM1126 in this step. Issue #339
