# D202 — P61 read routing spends the route key only

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

Reads on a topology use the first replica whose circuit is closed. The session is the topology handle, one per `connect()`, shared by `for()`, `unscoped()`, and a connection from `reserve()`. A successful write sets a flag and later reads use the primary until P63. `route` on a read and `db.using` with `"primary"` or `"replica"` override that. `onRoute` receives the choice. A throw is swallowed. `inspect()` stays `single-endpoint`; routing reasons there move to the M2 dev inspector. A string or pool serves either `route` from its one endpoint and has no `using`. OKM1843, OKM1844, and OKM1840 are raised from the lazy router, from `lock.ts`, and from the transaction facade. `client.ts` gains only the copy of `route` inside `callOptions`, plus the allowlist entries in `plan.ts`. Nothing else was added to the startup graph.
