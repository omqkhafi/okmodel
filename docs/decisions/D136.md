# D136 — App-fixture budget and entry gates after P14

- **Status:** historical
- **Area:** product
- **Supersedes:** none

---

What an application ships is the app fixture (`okmodel` + `okmodel/pg` used parts + errors + whatever is added), so the 0.1 budget of D127 (60 KB min / 20 KB gzip, cold import 15 ms) applies to that fixture, not only to the runtime entry; the interim gate moves from 48,000 / 15,800 to 60,000 / 20,000 and P15 and P15B must fit inside it or stop and report a breakdown so that a reasoned budget can be decided with evidence, not guessed. P14 numbers: runtime entry 24,389 min / 8,568 gzip (+6.4 KB for `OkmError`); app fixture 45,445 / 14,875. The adapter ceilings P14 set from its own measurement (postgres.js ≤ 19,850 / 6,870, PGlite ≤ 17,870 / 6,230) are accepted as interim because `OkmError` is in those standalone bundles (acquire timeout is an `OkmError`); the published package shares one copy (bundle-purity). `OkmError` identity must exist once per process, as the catalog does.
