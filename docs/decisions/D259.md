# D259 — PGlite numeric parameters, an explicit undefined search, the rest of the prototype keys, and a self-child sync (P99 QA)

- **Status:** accepted
- **Area:** adapters
- **Supersedes:** none

---

Four fixes before 0.7.0. No new error kind. No public type change. No catalog hash change. No gate move. PGlite's serializers were identity, so a JS number or bigint that `encodeBigintString` returns unchanged reached the bind writer and failed with SQLSTATE `08P01` (`insufficient data left in message`). Class `08` then classified that as `unavailable` and retryable. The fix is only in the PGlite adapter. `pglite-wire.ts` loads from `open` and is not in the connect startup graph. A number or bigint is its decimal spelling. A boolean is `t` or `f`. Parsers stay identity. An `08P01` is replaced with an error that has the same message and neither a SQLSTATE nor a cause, so the kind is `driver`. `08006` and the other connection failures stay `unavailable`. `find` and `count` keep an explicit `search` key when the value is `undefined`, and that value is OKM1120, the same as `""` and `null`. A call that omits the key does not load text search. `refusePrototypeKey` also refuses `valueOf`, `isPrototypeOf`, `propertyIsEnumerable`, `toLocaleString`, `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`, `__lookupSetter__`, and `then`. The message stays `<where> <name> is a prototype key. Use another name for the result.` The helper stays in the bucket and window chunks. `sync` on a relation whose related table is the owner's table refuses an id list that contains the parent's own id, before any SQL, and writes nothing. Other relations are unchanged. Measured with `bun run size` against D258: runtime entry 5,288 / 2,026, cold import 1.722 ms, unchanged (812 / 224 under 6,100 / 2,250). Stubbed featureless app 90,572 / 29,339 against 90,593 / 29,338 (−21 / +1). postgres.js 40,512 / 14,096 against 40,533 / 14,098 (−21 / −2). PGlite connect 38,621 / 13,386 against 38,774 / 13,481 (−153 / −95), inside the 40 minified byte allowance. node-postgres 40,283 / 13,991 against 40,304 / 13,986 (−21 / +5). Bun.sql 39,254 / 13,591 against 39,275 / 13,590 (−21 / +1). The gzip rises are the search-key check, which is shorter minified than the `!== undefined` test it replaced and compresses less well. postgres.js adapter incremental stays 15,069 of 15,093. PGlite adapter incremental is 11,387 of 12,010 (was 10,931). The wire chunk is lazy, so it counts there and not in the connect entry. query-200 stays 17,239 instantiations and 6,374 types. query-200+page+aggregate+through stays 24,436 / 6,928. The tagged-operator surcharge stays 639. Addendum: the self-child refusal is only a tree-shaped plain `many`, where the owner table is the related table and the relation has no `through`. `manyThrough` is accepted, including a row that links to itself. The message says "tree". Issue #252
