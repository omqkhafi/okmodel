# D358 — pgvector pack

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`pgvector()` is `okmodel/pg/pgvector`, the same subpath shape as `pgTrgm`. The SQL extension name is `vector`. `vec.vector(n)` and `vec.halfvec(n)` are `number[]` columns. The wire text is `[1,2,3]`. The encoder accepts only plain finite numbers, checks the dimension, and refuses an empty array (OKM1210). Both types stop at 16000 dimensions. There is no `bit`, `sparsevec`, `<~>`, or Hamming. `vec.hnsw(column, { metric, m?, efConstruction? })` and `vec.ivfflat(column, { metric, lists })` return `IndexCall`. `metric` is required (`cosine`, `l2`, or `ip`). There is no default hnsw opclass and no version pin. `efConstruction` is the option name; the reloption is `ef_construction`. `m` and `lists` keep those names. `IndexCall.nameKey` is optional and becomes `{table}_{nameKey}_idx`, so two vector indexes on one column do not share a name. A string column name cannot see the column type, so `contribute` rewrites the opclass family from the staged column. A handle from `indexes` already carries `dataType`. `distance` is a select fragment. `within` is a where value. `nearest` is an orderBy value on the same tagged arm as `relevance()`: `orderScan` sets the operator bit for any tagged operator, and `emitOrder` sends any tagged operator through the lazy compiler. Direction stays in that compiler (`nearest` ascending, `relevance` descending). `select` stays a list, and `indexes` stays a function. `fn()` does not fall out of that arm. `OrderBy` does not include a fragment, so accepting `fn()` would reverse D282. D282 stands. `schema()` refuses hnsw on `vector` above 2000, hnsw on `halfvec` above 4000, ivfflat above 2000, a second vector index for the same column and metric, and a missing metric (OKM1930). Extension preflight is advisory only for the name `vector` when the role can create extensions. The verdict is `CREATE EXTENSION`. A non-superuser 42501 says "not trusted: needs a superuser or a provider that allows it". Other extensions keep the untrusted refusal. Changing `vector` to `halfvec` changes the opclass, so the index is dropped and recreated in the same plan. A storage change uses the D343 replace path. `createIndexSql` appends `WITH` on a using-tail index, which the P2 path omitted. Introspection stores `pg_opclass.opcname` for hnsw and ivfflat, including the default `vector_l2_ops`, which `pg_get_indexdef` omits. `okm doctor` maps an hnsw build 53100 to OKM2208. That failure was not provoked: `maintenance_work_mem = 64kB` only emitted a notice. OKM2129 is unused. No new `ErrorKind`. No catalog hash change for an index that does not set `nameKey`. Registry keys: `ext.pgvector`, `type.vector`, `type.halfvec`, `index.hnsw`, `index.ivfflat`, `query.vectorDistance`, `query.vectorWithin`, `query.vectorNearest`. The pack is not on the featureless startup graph, the runtime entry, or a connect graph. The order-arm edit is on `plan.ts` and shrinks those graphs.
