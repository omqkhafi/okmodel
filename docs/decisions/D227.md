# D227 — `db.views.name.refresh()` refreshes a materialized view (P81B)

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

No arguments, and it returns void. The statement is `REFRESH MATERIALIZED VIEW`, with `CONCURRENTLY` when the view declares `refresh: "concurrently"`. The name is unqualified so `search_path` matches a view `find`. It is a write: `classOf` treats `refresh` like `insert`, so a client with a replica sends it to the primary, and it uses the statement timeout and `mapPostgresError`. A missing method on a plain view would be a TypeError, which `OkmError.from` reports as kind `driver`. The handle throws OKM1120 (kind `invalid`) instead, and the type omits `refresh` unless `"~kind"` is `"materialized"`. Views stay on a scoped client, which is the rule they already follow. The refresh is not tenant-scoped. `0A000` (not populated), `55000` (no unique index), and `42501` (not the owner) stay kind `driver` and gain a fix line. The statement module is a dynamic import from the view hook. A featureless app stays 90,721 minified (gzip 30,153, one byte under the hidden-check run). An app that imports a view is 98,071 / 32,349 at startup. The `refresh.js` chunk is 531 bytes and is outside that startup graph. No gate moves. Issue #170
