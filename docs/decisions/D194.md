# D194 — Plan row estimates stay out of the linter and the migration file; a declared table rename renames default names

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`okm migrate plan` prints a row estimate from `pg_class.reltuples` when one target is configured, or `--target` names one, and that database answers. It never runs `count(*)`. `reltuples` of `-1` prints `rows unknown (table not analyzed)`. A relation absent from `pg_class` prints `new table`. No target, several targets without `--target`, or a target that cannot be reached prints the lock alone and does not error. The query is one read-only transaction and follows the other read-only commands: `plan` is allowed on a protected target, and a pooler host is not refused. A safe-rewrite step is labelled `safe rewrite applied`. `ACCESS EXCLUSIVE` on more than 1,000,000 estimated rows, outside a safe rewrite, prints a plain note and is not a lint finding. Estimates are not lint input and are not written to SQL, catalog files, or `okm_history`. `okm generate` stays offline. A partition or inheritance parent is estimated from its own `reltuples` only. The number is only as fresh as the last analyze. A table `renamedFrom` plans `ALTER TABLE … RENAME TO`, then renames the primary key, unique and check constraints, foreign keys, indexes, and identity sequences whose names are the defaults `{table}_…`. A custom name is left as it is. An add and a drop with no declaration is still OKM1530. No gate, cap, or ceiling moves. Found in P51. Issue #79
