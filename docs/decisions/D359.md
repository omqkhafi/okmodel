# D359 — Event triggers on `trigger()`

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

`trigger({ event })` is an event trigger. There is no `eventTrigger()` builder and no second schema list. Events are `ddl_command_start`, `ddl_command_end`, `sql_drop`, and `table_rewrite`. `login` is OKM1931: a mistake locks every session out, and PostgreSQL BUG #19488 skips login triggers on a standby. Tags on roles, databases, and tablespaces are OKM1931 (0A000). A tag the event cannot see is warning OKM2129. The function must be plpgsql, take no arguments (42P13), and return `event_trigger` (42P17), also OKM1931. `enabled` is `true`, `false`, `replica`, or `always` (catalog O, D, R, A). There is no `OR REPLACE`. A change of event, tags, or function is drop plus create. `enabled` is `ALTER EVENT TRIGGER`. A unique rename is `RENAME`. Event triggers are created last and dropped first (2BP01). `okmodel/event` installs the compiler. The featureless app does not import it. Presets are `guardDdl`, `enableRls`, `auditDdl`, and `notifyDdl`. `manual` is the role boundary (`session_user`, `pg_has_role` `usage`/`set` on 16+ and `member` on 15). `drops` and `rewrites` read `okm.allow_drop` and `okm.allow_rewrite`, which `okm apply` sets per step after `--allow-protected` or `--allow-blocking`. A step outside a transaction sets the session form only on a proven direct URL and resets it in `finally`. A pooler is OKM1931. The GUC is a belt. `enableRls` enables row security and does not force it. `rls: false` in a covered schema is OKM1931. `auditDdl` writes two tables in schema `audit` through a security definer function with `REVOKE EXECUTE ... FROM PUBLIC`. `keep` is not an option: retention is a docs recipe. `notifyDdl` sends the tag and the object, cut at 8000 bytes. `DROP EVENT TRIGGER` is never blocked. Creating one needs a superuser or a host route. `okm check` states required versus found (OKM2209): Neon `neon_superuser`, Supabase `postgres`. `okm doctor` and `okm access` list event triggers. An undeclared one is `unmanaged`. An apply error raised by an event trigger names the enabled triggers and the disable or drop statement. Pull writes `trigger({ event })` and the function as `sql`. Presets are not recognized. `referencing` is statement-level, `after`, one event, no `updateOf`. Registry keys: `trigger.event`, `trigger.guardDdl`, `trigger.enableRls`, `trigger.auditDdl`, `trigger.notifyDdl`, `trigger.referencing`, `comment.eventTrigger`. No new `ErrorKind`. `OBJECT_KINDS` gains `eventTrigger`. Existing catalog hashes stay the same. Issue: none (PR only)
