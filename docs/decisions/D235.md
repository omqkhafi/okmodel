- **Area:** product

QA of P80 through P87 on Postgres 15, 16, 17, and 18 found no data-loss, isolation, or security defect and did not move a catalog hash. No new API. A three-hop path update that points a child at another tenant's parent is OKM1705 and the row stays. Path `onConflict` is OKM1120. A reporting role under `rlsTenancy` is not `BYPASSRLS`: select of a hidden column and every write are `42501`, a count without `app.tenant` is 0, a transaction-local `set_config` sees that tenant's row, and the setting does not leak after commit. `isolation()` fails when a column or composite predicate is removed and when the row-level policies are dropped on a role that is not the owner. `ignored` and `external` survive apply and an introspected drift plan, and a hand-added column on an external table is not dropped. A plain `CREATE TABLE` database connects, and `requireMeta: true` on it is OKM1520. Every operator `parse` applies, hostile JSON fails closed or stays a parameter, and a relation allowlist plus a hidden field are refused. Check, primary key, and not-null stay outside the mapped name-key set. `okm migrate plan` diffs the author snapshot, so it prints no steps when `0004_sql_names` is already the head file and the live database is still on 0.5.1 names.
