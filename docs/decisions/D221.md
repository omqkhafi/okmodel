# D221 — Tenant onConflict names the unique without the tenant key (P81)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`onConflict: { on: "title" }` matches `UNIQUE (tenant key, title)`. The conflict target is the unique's columns in constraint order, including the tenant key, so Postgres hits that constraint. The inserted row is still stamped with the caller's tenant, and the update touches only the row that shares that key. Naming the tenant key in `on` stays OKM1104, matching the accepted-list sentence that the key is not named. A unique that does not include the key, including `.unique({ global })`, still matches the names the caller wrote. The branch stays in `src/runtime/conflict.ts`, which `write.ts` already loads on first conflict. Gated graphs are unchanged from D219: app 90,506 / 30,063. The app total graph is 196,302 / 63,858.
