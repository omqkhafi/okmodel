# D150 — Release gate: no tag without the Docker-backed suite

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

0.1.0 shipped with a planner bug (an identity column made `okm push` and `okm generate` fail with a second `CREATE SEQUENCE`; fixed in 0.1.1) because the round-trip tests installed their start catalogs with `renderCatalog`, which already folds the sequence, and the postgres job runs a hand-listed subset of tests on Postgres 17 only. The release workflow runs `bun run check` only, with no Postgres at all. Rule from now on: a release is published only after (1) every test, not a hand-picked list, runs against real Postgres in Docker on each supported major version (a version matrix; PGlite and the wire server never replace it), (2) the packed tarball runs the README and quickstart commands against that Postgres, (3) the release workflow depends on that job passing, and (4) after publish a smoke job installs the version from npm in a fresh directory and runs the quickstart again, failing if the version or its provenance is missing. A test that does not run in the matrix is listed with its reason. More drivers (node-postgres, Bun.sql) are added in P18 through the same conformance suite and capability registry, so a capability a driver or an environment lacks is reported as a skip with a reason, never hidden. Found in 0.1.1
