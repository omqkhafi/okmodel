# D237 — CRLF migration files and Windows paths (P88W)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Migration SQL is normalized when it is read. `\r\n` and a lone `\r` become `\n` before `parsePlan`, and that text is what apply, `okm migrate check`, the linter, status, and a backfill header see. A non-empty file that still has no steps, and no `-- no steps` line, fails with kind `invalid` and reason `no-steps`. It does not print `nothing to apply`, so a hand-written `truncate` is OKM1542 in LF and in CRLF. A leading UTF-8 BOM is stripped from migration SQL, catalog JSON, and `catalog.hash`. A NUL byte is treated as UTF-16: migrations use kind `invalid` and reason `utf16`, and a catalog uses OKM1027 with `fieldReason` `utf16`. No new error kind. The catalog hash is SHA-256 of the file after the BOM is removed and every `\r` is removed, in the writer and in the loader. `serializeCatalog` and `catalogHash` of an LF document are unchanged, so an upgrade from 0.5.1 or from an applied 0.6.0 catalog keeps its hash (D116). Config paths resolve from the project directory for schema, tables, migrations, out, seed, status, check, provision, apply, and dev. An absolute spec and a `..` spec both work. `artifactDir` drops a trailing backslash as well as a slash. `callerLocation` splits a frame on a backslash as well as a slash. `okm generate init` writes `.gitattributes` (`migrations/*.sql text eol=lf`, `*.catalog.json text eol=lf`, `.okm/** text eol=lf`) only when that file is absent. `engines.node` is `>=22.18`.
