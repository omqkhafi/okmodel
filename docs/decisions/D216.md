# D216 — QA timeouts, packaging, CI, docs, and the 0.5.1 gate (P71)

- **Status:** accepted
- **Area:** ci, docs
- **Supersedes:** none

---

QA-M3: reproduced on the P70 tree. Bun.sql with a row locked in another transaction and `timeout: 300` never settles, and neither does a caller `signal`. PGlite with the outer client used inside `tx()` queues behind the transaction; PGlite also ignores `statement_timeout` and blocks the JS event loop while a statement runs, so a JS race can never beat it. The fix was built and verified: a client-side race in the lazy watch path rejects with kind `timeout` or `cancelled` at the deadline (302 ms and 301 ms measured), the pooled connection stays busy until the statement really ends, a reserved connection is destroyed on release, and the PGlite outer-in-`tx()` call throws OKM1192 (5 ms, no false positive on an unrelated queued call). Sizes against main (runtime 5,288 / 2,026; app 90,851 / 30,157; postgres.js 42,382 / 14,898; PGlite 40,393 / 14,257; pg 42,795 / 15,048; Bun.sql 41,643 / 14,592): the Bun.sql graph fit at +108 / +39, but the PGlite graph measured +191 / +92 against the +150 / +50 cap for this item, with a single-site floor near +178. Per the escape hatch the code was removed, no gate moves, and M3 is a known limit: `timeout` and `signal` do not settle an in-flight statement on Bun.sql and PGlite, and the outer-client PGlite call queues. OKM1192 stays reserved and is not thrown. QA-R1: the pack step (`prepack`/`postpack` around `bun pm pack`) strips `workspaces` from the tarball manifest only; `tarball-smoke` asserts it. QA-R2: the suite preflight probes the primary, names the URL when down, and exits 1 under `CI=true`; each harness-gated skip counts toward `N Postgres tests SKIPPED`. `loadPostgresGate` itself never throws for a missing database: the always-on CI slices run gated files with no database and skip by design (D212). QA-R3: a `temporal / node` matrix job (22 and 24 with `temporal-polyfill`, 26 natively) joins the `gate / check` needs; the suite workflow proves the D215 pid probe refuses a transaction-mode pgbouncer with OKM1854 (round-robin rotation makes it deterministic), so it runs on label, weekly, and release without touching `release.yml`. No Bun-adapter lock-timeout job: M3 was removed, so there is no lock-timeout behavior to cover. QA-R4: `type-cost` measures `inferred-250` (17,650 instantiations) and fails above 21,180 (measured +20%); time is reported, not gated. QA-D1 to D8: D3, D4, and D7 already matched behavior; D1, D2, D5, D6, and D8 are fixed as documented in the changelog. The gate: runtime entry unchanged at 5,288 / 2,026; every other gate identical to main; `query-200` under 17,300; no gate, cap, or ceiling moves except the new R4 ceiling. No new ErrorKind, no new public option, no new exported symbol. Issue #149
