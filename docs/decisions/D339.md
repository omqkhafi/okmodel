# D339 — A step has a weight, `blocking` or `rewrite`, apart from its class, and apply stops over 100,000 rows without `--allow-blocking`

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Step `class` (`expand`, `contract`, `unclassified`) already exists and means possible data loss: it is what `--allow-protected` reads and what `plan --json` prints as `class`. Downtime is a different axis, and one step can be both (a column type change is `contract` and a rewrite), so the new field is `weight`, not another `class` value. `blocking` holds a lock that blocks readers and writers for the whole build and has no online form. `rewrite` rewrites the table under ACCESS EXCLUSIVE. A migration file records it as a `-- weight:` line after `-- lock:`; a reader that does not know the line ignores it, and a step with no weight prints no line. A file keeps no table list, so the tables are read again from the statement (`"schema"."table"`); a weighted step that names no readable table is refused, not skipped. `okm migrate apply` and `okm push` count the rows of those tables on the real target after the advisory lock and before the first step, and before the ledger tables are created: a bounded `count(*)` over a `limit 100001` subquery, read only, 2 s, never `pg_class` alone, because `reltuples` is stale after a burst of inserts (the interleaving test analyzes a 10-row table, inserts 150,000 rows, and apply stops). `reltuples` only raises the estimate for a bigger table. Over 100,000 rows the refusal is OKM1847 (kind `invalid`, exit 4 like the other guards, `retryable: false`), it ends `Nothing was changed.`, and `--allow-blocking` lifts it for that invocation (no short form, not read from the environment; the agent block lists it with the other guards). The estimate is about 45 s per million rows for `blocking` and about 1.3 s per million for a `rewrite` type swap, measured on real servers and printed as an estimate, good to an order of magnitude. `okm migrate plan` prints it on the lock line, from `reltuples` and the same bounded count when the table was never analyzed; `--json` adds `weight` per step and, with a target, `estimatedRows` and `estimateMs`. The lock timeout and `--lock-wait` cover getting the lock, not the build. No existing step kind is classified: `set-column-type`, `set-enum-column`, `recreate-enum`, and a stored generated column are the candidates, and each needs a per-statement lock proof (only some type changes rewrite), so the mechanism ships with its first user (the exclusion constraint) in a later step. No new ErrorKind. Issue: none (PR only)
