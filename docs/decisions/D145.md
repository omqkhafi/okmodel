# D145 — P17C outcomes and the 0.2 operator set

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

(1) Public subpaths now carry only public API (`okmodel/pg` no longer exports `compileColumn`, `emitRowTypes`, `mapPostgresError` or the operator tag helpers; `okmodel/migrate` exports `defineConfig` and its types); the `okmodel/pg` barrel is 62,063 / 19,409, the runtime-entry gate 6,100 / 2,250, app startup unchanged at 77,537 / 25,625 (gate 79,849 / 26,410). Ali tags `v0.1.0` after merging from `docs/release.md`; the release workflow needs npm credentials or trusted publishing configured, which the dry run cannot prove. (2) The quickstart and recipe tests run against an in-process Postgres wire server in `check`, because that job has no Docker database; P20 also runs the quickstart test in the `postgres` job against real Postgres. (3) The 0.2 operator set is defined in spec §10.1 (draft 24): type-directed helpers `contains`, `containedBy`, `overlaps`, `hasKey`, `hasAnyKey`, `path(segments, op)` and `matches(q, { mode?, config? })`, plus the atomic write operators `json.set`, `arr.append`, `arr.remove` as namespace exports; a mismatch between operator and column type is OKM1124 at runtime and a type error at compile time. Extension operators (trigram, citext) move from P20 to P40, and text search on a plain `text` column is not supported in 0.2. (4) P20 keeps one function per operator (tree-shaken, barrel not gated), the tagged-operator source surcharge stays under 800 (639 now), and the composite probe may grow by at most 3% (6,479 of 7,100 now) or P20 reports per-operator contribution and stops (D133, D140).
