# D154 — Client-side generators through `.default()`, and a schema-level id default

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

(1) `.default(x)` takes a literal value or a client generator (a generator value or a function returning the column's type); a generator means the client fills the field on insert when it is omitted. The database expression form stays `.defaultSql(sql)`, as in the spec today. No separate `.generate()` / `.auto()` name: `.auto()` reads as autoincrement, `.generated()` is Postgres's word for computed columns, and Prisma and Drizzle already teach one default concept. `.default()` is client-side or a plain literal and `.defaultSql()` is the database's, and the catalog output labels a client default as `client`. Built-in generators are `uuidv4` (the runtime's `crypto.randomUUID()`), `uuidv7` (our own, so Postgres below 18 can have time-ordered ids with no database support) and `okid(options)` (D153); where they are imported from (a root export or a small `okmodel/ids` subpath) is decided in P19 against the tree-shake gate. (2) A client default is not part of the database catalog or its hash and produces no migration when it changes (D153); the column is `NOT NULL` with no database default, so a writer that bypasses okmodel (psql, another service, raw `INSERT ... SELECT`) must supply the value, and the docs say so; prefer a database default when several systems write the table. (3) The insert type makes the field optional and the select type keeps it required; a guarded id (`t.id` family) is filled only when omitted, a plain column with a client default may also be supplied by the caller. (4) `t.id(...)` takes its options per column, and `schema({ tables, defaults: { id } })` sets what a bare `t.id()` means for every table (`uuidv7`, `uuidv4`, or a client generator); a per-column option wins; the effective choice is shown in the catalog output; changing the schema default after tables exist is a type or default change and the planner classifies it like any other (a uuid to text change is a recreate and needs a declared replacement, D131). With no `defaults.id` and a declared server below 18, OKM1812 names the `defaults.id` fix. (5) `connect({ generators })` may replace a built-in generator, so tests get deterministic ids (the testing package in 0.4 uses it). All of this ships in P19 with OKID. Found when planning ids for 0.2
