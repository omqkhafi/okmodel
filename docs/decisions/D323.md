# D323 — `okm generate` asks before it writes a drop

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

Decided with Ali on 2026-11-05. A developer can remove a column from the schema without meaning to, and apply then refuses with OKM1510 and an override the person has to type by hand. When stdin is a terminal and `--json` is absent, `okm generate` lists each planned drop (OKM1511 to OKM1518) by step, code, and statement, then asks `Drop it? [y/N]`. A no writes neither the SQL nor the catalog and exits 1 with OKM1510. A yes asks for a reason and writes `-- okm-allow CODE: reason` on each drop step; an empty answer writes `confirmed at okm generate`. The file stays the acknowledgement (D192) and `okm check` lists the line. No flag skips the question, and a run without a terminal (CI, a pipe, `--json`, an in-process `run()` with its own stdout) writes the file and exits 1 as D303 describes. Other error findings are not asked about. Tooling only. No public API, `ErrorKind`, or catalog hash change. No gate moves
