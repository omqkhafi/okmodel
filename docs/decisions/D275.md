# D275 — `okm pull` writes schema source and drops nothing silently (P111)

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

`okm pull` reads the selected namespaces (the target's `current_schema()` unless `--schema` names others) and writes one table file per table plus the schema file in the project's layout. `--out` writes `schema.ts` and `tables/` under another directory. The connection is read-only, so a protected target is allowed and `--allow-protected` is not required (§19.7). An existing file is OKM1855: the command writes nothing, and the fix names `--out` and the file. There is no prompt. Pulled objects are managed. Written kinds are tables, columns (type, default, nullability, identity, stored generated), primary and composite keys, unique constraints, checks, foreign keys with one local column, indexes that have a column (including a partial predicate or an expression), the sequence an identity column owns, enums, domains, and extensions. Functions, triggers, views, materialized views, policies, roles, and grants are printed under `not pulled yet` with a count, and so is anything `table()` cannot say: a partition, a composite foreign key, a standalone sequence, an expression index with no column, a column type with no builder, a deferrable or nulls-not-distinct constraint, a non-default collation, and an identity that is not generated always as the only primary key. Comments are not pulled because the catalog does not store them. The logical namespace stays `public`, because `schema()` has one namespace. The same database produces the same bytes. No new catalog kind and no new builder. Nothing new is reachable from the runtime entry or from `connect()`. Issue #309
