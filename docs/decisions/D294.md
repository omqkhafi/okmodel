# D294 — postgres.js and pg storm recovery (B-02, B-43, B-44)

- **Status:** accepted
- **Area:** adapters
- **Supersedes:** none

---

postgres.js sets `backoff: () => 0.05 + Math.random() * 0.2` (seconds, under 1 s with jitter) so reconnects no longer grow to 10–20 s per attempt. `timeouts.acquire` defaults to 10 s on postgres.js and node-postgres when omitted; a timeout stays OKM1846 (kind `timeout`). A module-level `uncaughtException` listener swallows postgres.js `nextWrite` on a null socket (Bun `socket.write` and Node `reading 'write'`) and rebuilds each open pool so the next read is not stuck on a dead queue. Other uncaught exceptions `console.error` and set `process.exitCode = 1` so Bun does not exit 0 when the listener returns (migrate CLI refusals keep stderr and fail). node-postgres arms every client on `connect` and logs idle/`error` events through the notice path without throwing (B-44); checked-out clients keep a listener after the pool removes its idle handler. No new public API, error kind, or catalog hash change. No gate move. Measured: runtime entry 5,288 / 2,026; featureless app 90,718 / 29,587; postgres.js incremental 15,956 of 16,000. Issue #340
