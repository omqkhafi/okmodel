# D210 — A field value is a leaf in the effective-filter walk

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

A write whose where has no effective predicate is OKM1102 on `update`, `delete`, `archive`, and `restore`. `undefined`, `{}`, and an object whose own values are all `undefined` have none. A field value other than `undefined` is a predicate: `null`, a scalar, an array, an object, and an operator. The walk does not enter a field value. It enters the where object's own keys, `and` (some branch has a predicate), `or` (every branch has a predicate, otherwise OKM1121; `or([])` matches nothing), and `not` only when `not` is the where itself. `emitWhere` skips `undefined` and an empty record, the same as before this walk, and does not call the predicate check. No preset, filter, tenancy, or relation code builds an empty `or()` branch. `or()` with a non-array or more than one argument is OKM1121 at the call (`Pass an array: or([a, b]).`); a non-array value in the planner is the same code, not `false`. An unknown key on the first argument of `update` is OKM1120, and the message says `timeout` and `signal` go in the second argument. `tx(fn, options)` is OKM1120 (`options go first: tx(options, fn)`). A bad option on `find`, `one`, and `count` returns a rejected query, so `safe` and `catch` see OKM1120. D125 is unchanged: a bare object in a where is OKM1121 for every column, and its fix names `eq`. `eq(value)` is the equality form, so a timestamp, a date, bytes, or a jsonb object (including `{}`) filters the matching rows. A bare object is still a predicate, so the planner raises OKM1121 and not OKM1102. A `Date` stays OKM1121 (D178). **Not reproduced:** `page` and `aggregate` already returned a rejected query (QA-M11).
