# D137 — Size gate at P15: optimize first, then staged ceilings

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

P15 stopped as D136 required: the app fixture with `connect` and one `find` measured 87,179 min / 27,620 gzip against 60,000 / 20,000, and `okmodel/pg` 68,427 / 21,358 against 66,900 / 20,900 (cold import 10.8 ms, fine). The biggest source modules on the path were `runtime/plan.ts` (41 KB), the postgres.js adapter (15 KB), `runtime/client.ts` (13 KB), SQLSTATE mapping plus driver errors (16 KB), tagged operators (7 KB), adapter batch (5 KB) and two row-decode paths. The interim 60,000 / 20,000 was a guess made before a planner existed, so it is replaced by evidence, but not by the raw number: P15 first runs a D129 optimisation pass on the read path (error mapping and the include planner load lazily on first failure or first include; tagged operators are one function per operator so unused ones tree-shake; adapter batch stays out of the read path until P15B/P29; no routing or topology code in `client.ts` before P60; one row-decode path; capability flags only for what is checked; no eager registries), and measures first-query latency next to cold import so lazy loading cannot hide a cost. The app-fixture gate is then set to the measured size plus 3% and may not exceed a hard cap of 75,000 min / 24,000 gzip; above the cap P15 stops again with a before and after per lever. P15B may add at most 12,000 min / 3,800 gzip over the P15 gate (one more stop-and-report if it cannot), and P17 finalises the 0.1 app budget at the measured size with the D133 ratchet (lower it whenever measured 5% or more under, never raise without a decision). `okmodel/pg` is the everything-exported entry, so it moves to measured +3% (≤ 70,500 / 22,000 unless the pass lowers it); each export must stay tree-shakable, which the app fixture proves. The public `connect` entries (`okmodel/pg/postgresjs` 47,694 / 15,263, `okmodel/pg/pglite` 45,733 / 14,673, driver external) get gates at measured +5% after the pass. The D135 standalone adapter gates stay. The named-statement benchmark runs in P15; the option ships only if it is at least 15% faster at p50 on repeated queries over a direct connection and costs 300 bytes min or less, otherwise the negative result is recorded and the unnamed protocol stays the only mode.
