# D238 — RLS runtime guards (P89)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

A hand-written step that disables row-level security, stops forcing it, drops a policy, creates or alters a policy with `USING (true)` or `WITH CHECK (true)`, grants `BYPASSRLS`, or changes the owner of a tenant table is OKM1550. `-- okm-allow OKM1550: reason` is the only bypass. The rule sees `\n`, `\r\n`, and a lone `\r`. `okm check` and drift omit policies when `relrowsecurity` is false, and they already compare `relforcerowsecurity` and the policy expression through the policy record. No catalog field was added, so an existing 0.6 catalog hash does not move. The first scoped statement on each endpoint runs one cached query for the role and the policy expressions. The cache key is the endpoint pool and a generation that bumps when that endpoint is unreachable or its circuit closes again. OKM1707 names the endpoint. `reason` stays `superuser`, `bypassrls`, or `owner`. A policy that does not match stays kind `invalid`. No new error kind. Inside `tx()`, `set_config('app.tenant', $1, true)` is queued at transaction start, before any savepoint, and it is set again when the statement's scope differs from the last one applied in that transaction. A rolled-back savepoint clears that memory so the next statement sets it again. The reporting role stays able to set `app.unscoped` itself. That is documented: the role is not tenant-safe against its own SQL. No public API change. The guard lives in the lazy rls module. The featureless app does not import it.
