# D309 — `aggregate({ countDistinct })` (F8-1)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`aggregate()` takes `countDistinct: [fields]`, a list of field names like `sum` and `avg`. A result row gets `countDistinct.<field>` as a number. It writes `count(distinct <column>)`, so NULL is not counted: a group whose values are all NULL, and the one total row of an empty table without `groupBy`, count 0. `groupBy` over an empty set returns no rows, as for every aggregate. It takes the column types `min` and `max` take (json, jsonb, bytea, point, line, tsvector, and arrays are OKM1124), and a hidden or unknown field is OKM1120. The tenant and active-set predicates apply as on any read. Dialects: `count(distinct col)` is standard SQL and native on Postgres, SQLite, and MySQL/MariaDB. Postgres is the only dialect in this repository, so there is no refusal path to write. Capability key `query.countDistinct`. The change lives in the lazy `aggregate` chunk: runtime entry 5,288 / 2,026 and the featureless app startup graph 88,348 / 28,426 are unchanged, the total graph grows by 200 bytes, and no gate moves. No new ErrorKind. No catalog hash change. No decision is reversed (D125 is about `where`). Issue #506
