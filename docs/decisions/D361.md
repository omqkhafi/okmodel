# D361 — Round 6 gaps: event-trigger labels, bundle compiler, procedure pull

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

Amends D359 and D360. `okm access` loads the project through `loadBuiltSchema` and the lazy `.catalog` getter when a project is present, so a declared event trigger is `declared` and only an undeclared one is `unmanaged`. With no project the rows stay `unmanaged` and the text says the schema was not loaded. `refuseDisabledRls` uses each table's namespace after trigger placement, so `rls: false` is OKM1931 in every schema `enableRls` covers, and a missing `rls` still defaults to true there. An apply error names enabled event triggers only when the text contains `okm_guard` or the Postgres `where` context names the function of an enabled event trigger. A plain `RAISE` from a table trigger does not. `okmodel/pg/catalog` exports `armCatalog()`. A single-file bundle calls it before `schema().catalog`, because `createRequire` has no sibling `catalog-compile.js`. A missing sibling is OKM1020 and names that call. A featureless query does not import it. Pull copies `routine` and `commits` when it augments a procedure, so a plpgsql procedure and a `commits: true` procedure replan to zero steps. No new `ErrorKind`. No catalog hash change. Issue: none (PR only)
