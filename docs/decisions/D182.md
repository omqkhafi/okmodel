# D182 — P30 gate for 0.2: property tests ship, feature-full app measured, one open finding

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

The gate adds four property tests on real Postgres with a fixed seed (20261005, `OKM_PROPERTY_SEED`; scale `OKM_PROPERTY_SCALE`; `OKM_PROPERTY_REPORT=1` prints coverage): `isolation.property`, `safety.property`, `statements.shape`, `archive.correctness`. Each is checked for sensitivity by dropping a predicate or swapping a column on the wire. They found no isolation, safety, statement-count or archive defect. They found one defect in `batch` (P30-1): a `restore` blocked by an archived parent (kind `invalid`) and a write with a wrong `expect` (kind `not_found`) are checked in `finish`, after the batch has committed, so the caller sees the error with `batchIndex: null` and the other writes of the batch stay. The spec says all commit or none does. Not fixed in P30: a fix needs the check inside the atomic unit, which a batch-mode driver (Neon, D1) cannot do after the fact. Proposed (not decided): (a) `batch` refuses `restore` and `expect` with OKM1121, or (b) the restore blocking and the count check move into SQL that raises, so the unit rolls back. Resolved by D183. One dead function (`withTenantScope`) is removed. Found in P30
