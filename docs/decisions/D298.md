# D298 — `--config` and programmatic plan, apply, status (G7)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Global `--config <path>` on every `okm` command that loads a config; default discovery stays `okmodel.config.ts` in the working directory. A relative or absolute path sets the project root to that file's directory so monorepo packages and absolute paths work. A missing file is `invalid` and names `okmodel.config.ts` and `--config`. Docs and the loader agree on `okmodel.config.ts` (not `okm.config.ts`). Public `plan`, `apply`, and `status` on `okmodel/migrate` share the CLI implementation: no process exit, prompts, or stdin. `plan` returns stable step ids, class, SQL, and lint; `status` returns coarse compatibility (`up to date`, `pending`, `ahead by expand`, `diverged`) with pending `${migrationId}:${stepIndex}` ids; `apply` resumes from those history ids and throws the same typed errors. Nothing enters the runtime entry or the featureless app graph. No new ErrorKind. No catalog hash change. No gate move. Issue #367
