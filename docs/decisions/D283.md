# D283 — `connect()` reads `okm_meta` in the catalog namespace (P115B)

- **Status:** accepted
- **Area:** runtime, contracts
- **Supersedes:** none

---

`schema()` still compiles `public`. `defineConfig({ namespace })` places the catalog, and apply still creates that schema and sets the session search path so `okm_meta` lands there (D277). `okm build` and `okm generate` write `.okm/namespace` with that name when it is not `public`, and delete the file when it is `public`. `connect()` reads the file from `catalogDir` or the default `.okm` before the startup query. A missing file, or `public`, keeps the unqualified query text. Another namespace qualifies `okm_meta` and, when the hashes differ, `okm_history`. `to_regclass` still lets a database with no `okm_meta` in that namespace plan, and a null hash still skips the check. A hash that does not match is OKM1520, the same compatibility error as `public`. No new error kind and no new public API. The catalog hash is unchanged. No gate or ceiling moves.
