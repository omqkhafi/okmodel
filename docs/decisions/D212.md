# D212 — A pull request skips real Postgres unless it asks

- **Status:** historical
- **Area:** ci
- **Supersedes:** none

---

D151 ran the suite on 15 and 18 and the tarball on 18 for every pull request. Those suite jobs take about ten minutes and they set the wait. `bun run check` already runs PGlite and the in-process wire server. A pull request now runs `check` and `attest`. The label `needs: postgres` runs the same shorter matrix: the suite on 15 and 18, the tarball on 18. A pull request update is one Actions run. The suite and the tarball are jobs in that run when the label is already present. Adding or removing the label, without a push, starts `.github/workflows/postgres-pr.yml` and does not cancel the run. `bun run verify` is the run on this machine, one version or `--all`. The release gate and the weekly run still cover 15 through 18 for the suite and the tarball (D150). `main` still requires only the `check` status. Tooling and CI only. The runtime entry is unchanged. Issue #152. Current status: `postgres-pr.yml` is gone. A pull request runs the Postgres 18 suite when the diff touches `src/dialects`, `src/runtime`, or `src/tooling/migrate`. The `needs: postgres` label does not start that suite. After merge is manual (`workflow_dispatch`) and covers tested majors 15 to 19. `gate / check` stays the required status.
