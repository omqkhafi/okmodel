The cap stays 91,000 / 30,000, so P25 to P29 share 5,644 minified and 1,639 gzip, about 1,129 / 328 each. Two things the implementation settled that the spec had not: (1) a tenant table's primary key is `(declared key, tenant key)` with `UNIQUE` on the same columns, instead of a separate `UNIQUE (id, tenant_key)`; this lets two tenants share an id and is what the composite foreign keys point at, and the spec section 9.1 was changed on the branch to say so; (2) a unique that a trait adds after the tenancy rewrite is not widened with the tenant key (`timestamps()` adds none). This is a known limit until traits run before the rewrite or the rewrite re-checks traits; it goes in `docs/known-limits.md` and P30 tests that no shipped trait adds a unique. Found in P24
