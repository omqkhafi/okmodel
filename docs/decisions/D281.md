# D281 — Extension packs and `okm ext scaffold` / `okm ext test` (P116)

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

The M2 contrib packs are their own subpaths: `okmodel/pg/unaccent`, `hstore`, `ltree`, `btree_gist`, `btree_gin`, `fuzzystrmatch`, and `pgcrypto`. `scripts/ext-generate.ts` writes them from the contrib `default_version` on `REL_15_STABLE` through `REL_18_STABLE` plus a naming overlay. Users do not run it. The drift check compares that table with the connected server. `vector` is deferred: `packages/harness/docker/compose.yml` uses official `postgres` images, which do not ship pgvector, and this change adds no topology service. D358 ends the deferral: proofs use `pgvector/pgvector:pg<major>` on its own port, not an apt install into the suite and not a compose service. `uuid-ossp` stays `extension("uuid-ossp")`. `ltree().ancestorOf` and `descendantOf` are `@>` and `<@`. They are not the parent-column walk (D252). `daitchMokotoff` needs fuzzystrmatch 1.2 and PostgreSQL 16. `fipsMode` needs pgcrypto 1.4 and PostgreSQL 18. An omitted pin does not fail. A floor that still allows a version without the feature fails OKM1812 when the method is called. `requires` and `provides` sit on the `extension()` object. `contribute()` does not store them, so the catalog hash is unchanged. `okm ext scaffold` prints a starting definition from `pg_depend`, `pg_type`, `pg_proc`, `pg_operator`, and `pg_settings`. `--out` writes that file and never overwrites. `okm ext test` checks declared types, operators, functions, and index methods. A signature mismatch is `invalid`. A version or Postgres floor the server misses is OKM1812. Both commands use the read-only `check` policy, so a protected target is allowed. No new error kind and no new OKM code. The featureless app and the connect entries do not import a pack. No gate or ceiling moves.
