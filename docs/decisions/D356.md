# D356 — Procedures, typed arguments, run(), and definer routine security

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`fn(name, { kind: "procedure" })` is the existing builder. `returns` and `volatility` are type errors. Identity is the name plus `IN` and `INOUT` types. `OUT` is not identity. OKM1023 covers both kinds. A kind change is drop plus create. Argument and return types are column builders. The string type form is removed. Three bodies: a typed `(args, query) => [statements]` compiled to `BEGIN ATOMIC` with every parameter qualified; a lazy `(handle) => sql` callback whose interpolated tables are `dependsOn`; and plain `sql`. `run(db, args, options?)` sends `CALL` in named notation, casts every argument, and passes `NULL::type` for every `OUT`. `bigint` and `numeric` arrive as strings. A driver that already parsed `timestamptz` hands a `Date` to the codec. `commits: true` is explicit and is refused before send inside a transaction (OKM1551, 2D000), with `security: "definer"`, with `searchPath`, with a `BEGIN ATOMIC` body, and when the flag disagrees with `COMMIT` or `ROLLBACK` in the body. `COMMIT` inside `EXCEPTION` is OKM2126. The same shape is `CREATE OR REPLACE`. Any other shape is drop plus create in one migration, and grants and the comment are applied again. `DROP PROCEDURE` and `GRANT ... ON PROCEDURE`. A rename keeps the stored body and the procedure fields, so the author's updated text is what the plan emits. Pull reads `prokind = 'p'` and writes the `sql` form. Another language is not pulled yet. Every security definer routine, procedure or function, is created with `REVOKE EXECUTE ... FROM PUBLIC` in the same transaction, then the declared grants. That revoke is re-applied after every recreate. A definer procedure that touches a tenant table is OKM2125. An undeclared custom errcode, or a standard-class code, is OKM2127. `raises` puts `raised` on the error. No new `ErrorKind`. `okm call` runs one procedure. `schedule` is not an API. Registry: `fn.procedure`, `fn.procedure.commits`, `fn.run`, `fn.definerRevoke`, `fn.raises`, `grants.procedure`, `comment.procedure`. Existing function catalog hashes stay the same. Issue: none (PR only)
