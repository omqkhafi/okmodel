# D336 — Apply waits for a lock for `--lock-wait`, and retries only 55P03

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

One helper (`lock-wait.ts`) replaces the three fixed-count retry loops in the runner and the step engine, and the `retries` count is gone: `--lock-wait <duration>` is the one knob (default 2 minutes, `0` tries once). Only SQLSTATE `55P03` is retried, read from `sqlstate` or `code`, never from message text. A deadlock (`40P01`), a statement timeout (`57014`), and every other error stop the step. Each attempt is a new transaction that sets `lock_timeout` and `statement_timeout` with `set_config(…, true)` (`SET LOCAL`), so a failed attempt rolls back whole. `lock_timeout` for one attempt is 1 second by default (it was a 5 second session value) or `--lock-timeout`. The wait counts the time failed attempts and pauses took (50 ms doubling, capped at 500 ms), not the time a successful statement ran. `--lock-timeout`, `--lock-wait`, and `--statement-timeout` take one duration form (`500`, `500ms`, `30s`, `2m`; a bare number is milliseconds). Config `timeouts.lock` keeps its meaning as the per-attempt value. There is no config key for the wait. `okm push` and `provision()` keep the defaults. Issue: none filed
