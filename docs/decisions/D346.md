# D346 — One pooler detector: URL signals, then eight clients only when a decision still depends on it

- **Status:** accepted
- **Area:** docs
- **Supersedes:** none

---

Amends D344 and D345. `detectPooler` is the decision. `resolvePooler` calls it with the URL and `allowPooler` first. Eight clients (`probeConcurrent`) open only when no signal matched. Check, seed, baseline, resolve, and migrate check use that path and refuse with OKM1854 when the result is pooled. Apply, push, and provision still refuse a URL signal up front. Apply opens the eight clients only when a step cannot share a transaction. Doctor and an unclassified login already did. The single-session loop (`probePooler`, `probeStableBackend`, `assertStableBackend`) is gone. A `version()` that names PGlite is one process, not a pooler, so the client count is not a signal there. A stable idle pid is not a signal and is not proof of a direct connection. App startup, `measureStubbedStartup` in `scripts/size.ts` with dynamic imports stubbed and `postgres` external, stays 93,572 minified and 30,831 gzip. The runtime entry stays 5,442 / 2,105. No new `ErrorKind`. No new OKM code. No gate or ceiling moves. Issue: none (PR only)
