# D343 — Index options, expression indexes, and real comments

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`index()` keeps one chain. A key is a column handle (`desc`, `nullsFirst`, `nullsLast`, `ops`), a typed expression, or `sql`. `.where` takes a `where` object, an expression, or `sql`. `.using`, `.include`, `.with`, and `.unique({ nullsNotDistinct: true })` are the other setters. `.concurrently()` does not exist: the planner owns `CONCURRENTLY`. Btree is the default and is not stored. A custom btree opclass, order, or nulls order is an element, not a `using btree` tail. A non-btree `using …` tail stays the expression form. Storage values are the text Postgres returns. A storage-only change is a replace: `DROP INDEX CONCURRENTLY IF EXISTS` the temporary name, `CREATE INDEX CONCURRENTLY` under `name_okmnew`, drop the old index, `ALTER INDEX … RENAME TO`. `ALTER INDEX … SET` is not used. Include is btree, gist, or spgist and only plain columns. Unique, descending, and nulls order are btree. A name over 63 bytes is OKM1122. Non-immutable built-ins and a function declared stable or volatile are judged by `checkScratch` (OKM1848) from `okm check`, not from `schema()`. Unique on a non-btree method, including a `using gin` tail, is OKM1903 at plan time. OKM1900 is the view cycle from D342. The old pull spread is gone; pull writes the chain, including `.where` and `.ops`. Duplicate indexes are OKM2104. A prefix of another index is OKM2105 after the tenant prefix, and a unique, partial, or expression index is redundant only on a full match. A partial index does not count for OKM2101. It counts for OKM2103 only when a preset `where()` includes the predicate. `filters()` is an allowlist of fields, so a partial index does not count for it. An expression index stays undecidable. OKM2106 warns when a partial-index column is also a `filters()` field or a preset field. Preset compilation is documented; inlining constants is later. Case-insensitive text is `citext`. An expression index on lower() is for uniqueness only. There is no `ieq`. `comment` is a catalog field, omitted when absent, so a comment-only change is not a new definition. `COMMENT ON … IS` runs after the object exists, in the same transaction, and again after a drop-and-create. A concurrent index cannot share that transaction, so its comment is the next transactional step. A rename keeps the comment. The lock is `SHARE UPDATE EXCLUSIVE`, measured on PostgreSQL 17. A missing `comment` means unmanaged. `IS NULL` is emitted only when the previous migration snapshot recorded the comment. A DBA comment is left in place, `okm check` reports it as OKM2107, and `okm pull` writes it. Text is verbatim. Newline, tab, and carriage return are allowed. Other control characters are OKM1122. Empty text is refused. Wired for table, column, index, view, materialized view and their columns (`comment` and `comments` on the typed view from D342, which merged first), function, trigger, sequence (the identity options), enum, domain, check, and foreign key. Not wired: unique, primary key, extension, role, schema, and a kind that has no builder yet (policy, procedure, composite, range, event trigger). Registry keys: `index.covering`, `index.ordering`, `index.nullsNotDistinct` (15), `index.storage`, and `comment` per wired kind. Proofs are literal test titles. No new `ErrorKind`. `scripts/size.ts` gates are unchanged. Measured on Bun 1.4.2 against the main that contains D342: runtime entry 5,442 / 2,105 (unchanged), featureless app startup 92,943 / 30,658 to 93,567 / 30,830, postgres.js adapter unchanged. The prompt's own lines were missed and not moved: startup minified +624 against +10, CLI minified chunks from `bun build src/tooling/cli.ts --target node --minify --splitting` 1,783,226 to 1,813,461 (+30,235 against +8,000), tarball `bun pm pack --ignore-scripts` 1,188,513 to 1,278,948 (+90,435 against +12 KB). Moving comments off this branch does not put the index work under those lines. Issue: none (PR only)
