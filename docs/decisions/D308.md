# D308 — Agent files: `okm agents status | update | remove` (I3)

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

Tooling only. No public API, `ErrorKind`, or catalog hash change. `okm agents` and `okm init --agents` manage three kinds of file, and nothing else. (1) A block in `AGENTS.md` between `<!-- BEGIN OKMODEL v<version> -->` and `<!-- END OKMODEL -->`. Text outside the markers is never read for a decision and never changed; the file is created with only the block when absent. (2) `CLAUDE.md`, a thin `@AGENTS.md` import: created when absent; when it exists and has no import line, the import goes inside a managed block after a shown diff; a file that already imports `@AGENTS.md`, or is a link to `AGENTS.md`, is current and untouched. (3) The shipped skill (`skills/okmodel/`) copied from the installed package into `.claude/skills/okmodel/` and `.agents/skills/okmodel/`, only when that tool directory exists or `--agents claude\|agents` names it. The SHA-256 of each file `okm` writes, the choice, the facts the block prints, and the targets are recorded in the `agents` section of `.okm/init.json`. States are `current`, `stale`, `missing`, `modified`. A skill file whose hash no longer matches the record is `modified`: update and remove skip it and say so. `status` exits 1 (OKM1881) on any state but `current` and warns when `CLAUDE.local.md` exists. `update` rewrites only the block and unmodified skill files, and does nothing in a project that never installed them. `remove` deletes the block, and the files whose recorded hash still matches, and records `choice: no`. `okm init --no-agents` records the same choice so init never asks again; init asks only on a terminal, and `--yes` or no terminal never installs agent files unasked. Safety: content comes only from the tarball (markdown only, no symlinks, no hidden characters, else OKM1885), never the network. Every run prints a plan and a diff; `--dry-run` writes nothing; a change to an existing file needs `--yes` or a terminal answer (OKM1884, exit 3); `--plan-hash` pins the plan. A damaged marker is OKM1882 and a repeated block is OKM1883: refused, never repaired. The writable paths are a closed list (`AGENTS.md`, `CLAUDE.md`, the shipped skill files under the two fixed directories, `.okm/init.json`); a link is followed only when it lands on another listed path (OKM1886). `.claude/settings*.json`, hooks, `.vscode/tasks.json`, `.cursor/rules`, and MCP entries are never written. Each write is a temporary file and a rename, and a file that changed after the plan stops the run (OKM1887). A damaged `.okm/init.json` is OKM1888. Codes 1881 to 1888; 1868 to 1879 stay reserved for dialect refusals. Size: tooling only, no runtime or adapter byte moves.
