# D311 — `aggregate({ select })` names aggregates (F8-3)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`aggregate()` takes `select: { name: { fn: arg } }`. Each entry is exactly one of `count: true`, `countDistinct: field`, `sum: field`, `avg: field`, `min: field`, `max: field`, and gives one flat result key `name`, so one call can hold several aggregates of the same function and column. The list forms (`count: true`, `sum: [...]`, and the rest) keep their result shape and may sit in the same call. The value types follow the call: `count` and `countDistinct` are `number`, and the rest are the field type or `null`, as in the list forms. SQL, decode, and column-type checks (OKM1124) are the list forms' own code path. Refused with OKM1120 before any SQL: `select` that is not an object, an entry with no function or more than one, `count` that is not `true`, an unknown or hidden field, a field list where one field is expected, and a name that is a `groupBy` field, a bucket `as`, `count`, `countDistinct`, `sum`, `avg`, `min`, `max`, or a prototype key (the shared `refusePrototypeKey`). The plan mark carries each name, so two calls that differ only by name never share a cached plan. The names are the aggregate names F8-4 `having` will read. Ordering by an aggregate stays out of scope. Dialects: standard aggregate functions on Postgres, SQLite, and MySQL/MariaDB; Postgres is the only dialect in this repository. Capability key `query.namedAggregates`. All the code is in the lazy `aggregate` chunk; the startup graphs do not move (featureless app 88,437 / 28,440, runtime entry 5,288 / 2,026). Types: `select` is not in `AggregateOptions`. A typed `select` there measured 26,321 instantiations on `query-200+page+aggregate+through`, over the 24,792 ceiling, so `aggregate` has two more overloads that take `select` (typed fields, same `limit` and `.all(reason)` rule) and the first two refuse it with `select?: undefined`. A call without `select` stops at the first overload. The probe goes from 24,580 / 6,973 to 24,632 / 6,993, and no ceiling moves. No new ErrorKind. No catalog hash change. No decision is reversed.
