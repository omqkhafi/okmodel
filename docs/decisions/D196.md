# D196 — P53 is `okm migrate check`; startup compatibility is P53b

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

P53 is migrate tooling only. `okm migrate check` replays every migration into a scratch schema through the normal apply path, plans the introspected schema back to that file's catalog, checks that the previous catalog is still satisfied unless the recomputed class is `contract`, requires the last catalog to match the schema, and lints the history. The class is recomputed from step kinds, or by planning again when a step has no kind. A hand-edited `-- class:` line is not trusted. `defineConfig({ lintFrom })` is the adoption baseline: files before that id are not linted by this command. Apply still lints pending migrations only. A protected target is refused, because the scratch schema is a write, and `--allow-protected` does not apply. A fork is the replay failure `migration X was generated from a different parent than Y` (OKM1547), not a separate commutativity algorithm. OKM1521 stays reserved for P53A. P53b is a separate branch: the startup compatibility states in `connect()`, `okm migrate status` states, and loading the serialised catalog in production. P53b touches the connect entries, whose byte budget is nearly zero, so it does not share a pull request with P53. No byte moves on the runtime entry, the featureless app, or the connect entries, and no type-cost ceiling moves. Found in P53. Issue #81
