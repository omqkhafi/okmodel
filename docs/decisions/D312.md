# D312 — Transaction-local session settings (`okmodel/session`) (G-1)

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

Decided with Ali on 2026-10-21, public API approved. Issue #512. Postgres only. `sessionSettings({ key: { name, type, required? } })` declares settings. Types are `text`, `uuid`, `int`, and `bool`. `connect({ schema, session })` adds `db.with({ ...values })`, which returns a typed client: every `required` key is required and the rest are optional. `with()` composes with `for()` and `unscoped()` in any order, and a later `with()` adds to an earlier one. (1) Placement: one `select set_config($1, $2, true), set_config(...)` is the first statement of the transaction a unit runs in, before any savepoint. A nested `tx()` never sets again. A read runs in `BEGIN READ ONLY` on its routed endpoint, `batch()` starts with the statement, and Neon over HTTP puts it first in the same `transaction([...])` array. `is_local` is always true and there is no session-level option, so a transaction-mode pooler cannot hand a value to the next client. (2) The values join the scope key as the tenant does (D241): a statement whose settings differ from the last one set in that transaction sets again before it runs. `rlsTenancy()` and `sessionSettings()` share one pool wrapper, so a unit under both sets `app.tenant` and the settings in one statement. A queued set marks its scope as set, so the first statement does not repeat it, and a rollback to a savepoint forgets the scope only when a set ran inside that savepoint. (3) Validation is OKM1709 (the next free code after OKM1708). A name needs a dot, cannot start with `app.tenant` or `app.unscoped`, and cannot be a built-in setting (`plpgsql`, `pg_stat_statements`, and the other bundled extensions). Each value is checked against its declared type before any statement, an unknown key is refused, a missing required key is refused before any statement, and an optional key that is not given is not set. A client that never called `with()` while a key is required refuses every statement. (4) Dialects: the capability registry has `session.local` (native on Postgres) and `SESSION_SETTINGS` reports `transaction` for Postgres, `session` for the MySQL family, and `none` for SQLite. The MySQL family and SQLite refuse (OKM1860) with the alternative column, composite, or path tenancy. No MySQL or SQLite pack exists in this repository yet, so the refusal is `assertSessionSettings(dialect)` in the registry module, to be called by those packs. (5) A policy reads a setting as `NULLIF(current_setting('app.user_id', true), '')` before any cast, because the setting reads as an empty string, not NULL, after the transaction. (6) It does not authenticate. A role that can run SQL can set the same names, exactly as it can set `app.tenant` (D241). No `ErrorKind` change and no catalog hash change. The runtime entry stays 5,288 / 2,026. The startup graphs grew by 224 bytes minified and 83 gzip, and no gate moved. Issue #512
