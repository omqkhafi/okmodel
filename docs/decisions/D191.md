# D191 — Column type spellings compare equal in the diff

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

A plan compared the schema spelling with `format_type` as text, so `timestamptz` and `timestamp with time zone` were a type change. Plain `t.timestamptz()` and `timestamps()` columns both store the builder spelling through `compileColumn`; there was no column normaliser. Domain bases already store the long spelling when the domain is built, and that path is not the column diff. Decision: one function, `canonicalTypeName`, used on both sides of the comparison only. The catalog field stays as written. `timestamptz`, `timestamp`, `time`, `timetz`, `varchar(n)`, `char(n)`, and the integer, boolean, float, and `decimal`/`numeric` aliases map to the long spelling, with length, precision, scale, and `[]` kept. An unknown name is compared as written. `varchar(20)` to `varchar(30)`, and `timestamp` to `timestamptz`, still alter. No gate, cap, or ceiling moves. Found in P44
