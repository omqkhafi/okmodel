# D228 — Composite and path tenancy (P82)

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

`columnTenancy({ key: ["organizationId", "workspaceId"], type: "uuid" })` is the composite shape. §9.1 already writes the key as that list. An object map is refused. `for()` takes every key. A missing or extra key is OKM1701. The primary key, the extra unique (D223, tenant fields joined by `_`), `.unique()`, foreign keys, and `onConflict` (D221) use every key in order. Changing any key is OKM1704. A path is `tenancy: { via: "project.organization" }`, at most three to-one relations, resolved at build. A longer path, a missing relation, a cycle, or a path that does not end at a tenant table is OKM1705. Reads and writes add `EXISTS`. An insert checks the parent in the same statement (`FOR SHARE`) and throws OKM1705 when the parent is in another tenant. The endpoint table gains `UNIQUE` on its declared primary key, so the child can reference it, and two tenants cannot share that key. `onConflict` on a path table is OKM1120. `readTenancy` accepts any object with a `rewrite` function and does not name `composite` or `path`. The planner was already that check plus `strategy === "column"`. Dropping the strategy comparison is what keeps the name out of startup.
