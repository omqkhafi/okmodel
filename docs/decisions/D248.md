# D248 — Startup gates measure static code, with dynamic imports stubbed (P95S)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

A lazy chunk in the same build spends the minifier's short names, so a connect entry and the featureless app grow by about 20 gzip when the startup source does not (D247). The remaining 0.7 steps would use the gates on that pressure. The gate now builds each startup graph with a `Bun.build` plugin that replaces every relative dynamic `import()` with an empty module. One plugin, not a stub file per target. `bun build` has no plugin flag. `build.resolve` is not implemented, so the stub key is the importer plus the specifier; the specifier alone would merge `./batch.js` from two directories. The modules in that graph match the modules a cold import of the full build loads. The bytes are one file, because empty targets share nothing and the shared startup chunk is inlined. The full `bun build` numbers stay printed as `reference` and are not gated. Gates, caps, and ceilings do not move. The runtime entry has no dynamic import. An `onResolve` hook changes its mangling even when it stubs nothing (gzip 2,026 to 2,025), so that entry stays on the single-file `bun build`. Adapter incremental bytes stay the full adapter build: lazy adapter chunks count (D245), and that gate stays 15,093 and 12,010. No file under `src/` changes behavior. No new error kind. No catalog hash change. Two stubbed runs matched. An empty chunk imported from `aggregate.ts`, then removed, left every gated number unchanged; the full-build total grew by 76 and the full-build startup bytes did not. A 400-binding chunk on that same import also left the gated numbers unchanged. Gated baselines, then headroom under the unchanged gates: runtime entry 5,288 / 2,026 (812 / 224 under 6,100 / 2,250).
