# D189 — P40 splits: extensions now, domains in P40b; gzip measured without chunk ids; startup share +200 / +70

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

P40 stopped after the extension commit (`9b8f8e3`). (1) The +1 to +4 gzip bytes on connect entries in the first attempt were the lazy chunk id (a content hash) changing, not code. `scripts/size.ts` now replaces each lazy chunk id with a fixed-length constant before gzip; minified size is the real size. The normalised baseline on main's code is 88,938 / 29,609 for the featureless app (was 29,770), postgres.js 14,443, PGlite 13,825, `pg` 14,619, Bun.sql 14,136, runtime entry 2,026. Gates, caps and ceilings are unchanged, so the real headroom under the app gate (90,900 / 30,000) is 1,962 min and 391 gzip, and 157 / 155 / 301 / 334 gzip on the four connect entries. (2) Extensions follow D162, D171: `extension()` lives on `okmodel/ext`, the definition object carries its own catalog record, `schema()` only calls `contribute(peers, built)` on each declared object when `.catalog` is first read, the document reader and the plan live in the lazy tooling chunk. Cost +146 / +60 on the featureless app, 0 on the runtime entry and the connect entries. Errors OKM1810 (undeclared use), OKM1811 (not available on the server), OKM1813 (duplicate), OKM1814 (downgrade or non-relocatable move); an upgrade plans offline as `path-unverified` and apply checks `pg_available_extensions` and `pg_extension_update_paths` before any statement. Provides are methods on the object and are not stored on the record (a stored list would drift against introspection). (3) The startup share for P40 is +200 / +70 (was +150 / +60) so that `pgTrgm.gin()` and `gist()` can carry their index method and operator class into the catalog index and the plan: that line measured +54 / +10, and without it a trigram index would be planned as a btree, which is wrong. It ships working with a Postgres test that the index is created `USING gin (...) gin_trgm_ops` and round-trips through introspection with no drift, or it does not ship and `gin()` / `gist()` throw. The gate does not move. (4) Domains are a catalog `type` subkind and measured +902 / +235 on the featureless app through the enum path (`domainType`, `pushDomain`), which leaves 96 gzip under the gate for P41 to P43. That is too much for one subkind, so domains leave P40 and become P40b, its own branch after P40 merges; `t.domain` stays on OKM1061 until then. P40b is a design pass first: the target is a domain that rides the generic `contribute` path or shares the enum emission, at most +60 / +25 on the startup graph. If it cannot, it stops with the exact bytes and the cap question goes to Ali. Not planned in P40: ordering by `similarity()` (planner code on the connect graph, budget 0). Found in P40
