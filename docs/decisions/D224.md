# D224 — The Bun.sql and PGlite in-flight timeout stays a known limit (P81, QA-M3)

- **Status:** accepted
- **Area:** adapters
- **Supersedes:** none

---

D216 built the behaviour and removed it: a client-side race settled at the deadline, the connection stayed busy until the statement ended, a reserved connection was destroyed on release, and a PGlite call on the outer client inside `tx()` threw OKM1192. That fix grew Bun.sql by 108 / 39 and PGlite by 191 / 92. P81's gate is stricter for Bun.sql: it must not grow. The smallest hook in the lazy watch chunk shrinks every connect graph by 45 minified and is not that fix (D218). PGlite blocks the JavaScript event loop while a statement runs, so a timer in that chunk cannot beat an in-flight statement. The fix is not rebuilt on top of the hook, because the measured Bun.sql growth already misses the gate. No gate moves. `timeout` and `signal` still settle when the statement ends. OKM1192 stays reserved. Issue #161
