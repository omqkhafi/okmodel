# D348 — Composite types

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`t.composite(name, fields, options?)` sits next to `t.enum` and `t.domain`. An unused composite is not a catalog object; a column or a parent field is what declares it. Nested composites, arrays of one rank, and enum and domain fields are allowed. A type on its own path is OKM1060 (42P16). A domain over a composite is OKM1060 because `jsonb_populate_record` does not survive that domain. A virtual generated composite column is OKM1060 (0A000). Reads project `to_jsonb` when every field is safe, otherwise `jsonb_build_object` with `::text` for bigint and numeric, then the existing codecs. Writes encode each field (unknown keys, a missing key, and a number in a text field are OKM1210) and bind `jsonb_populate_record(null::type, $n::jsonb)`. SQL NULL is a null value, never JSON null. A column default is a positional `row(...)::type` in catalog order; a raw positional write breaks after `ADD ATTRIBUTE` (42846) and the jsonb path does not. PostgreSQL has no NOT NULL inside a composite, so each column gets one check (`(home).street IS NOT NULL AND ...`; a nullable column is `home IS NOT DISTINCT FROM NULL OR (...)`; an array is `NOT EXISTS (unnest ...)`). Check parts are sorted by text. `where: { col: null }` on a composite is `IS NOT DISTINCT FROM NULL`; `not(null)` is `IS DISTINCT FROM NULL`. A composite whose fields are all null is an object, not null. `field(col, name)` is the expression for indexes, checks, and generated columns. Dotted `db.*` keys for where, select, orderBy, and groupBy stay out of `src/runtime/plan.ts`: that file is on the app startup graph and the gzip gate has 19 bytes of headroom. A dotted update key is `SET "home"."city"` in the lazy writer (`(home).city` is 42601 in SET). Field order is ignored in the diff. Add is `ALTER TYPE ... ADD ATTRIBUTE`. A new non-null field on a column that already exists needs a fill (`UPDATE ... SET "col"."field" = ...`) or OKM1915. Rename is `RENAME ATTRIBUTE` through `type.field.old=new` and `.renamedFrom`; checks whose sorted text changes are dropped and re-added. Drop is a contract step (`--allow-protected`). A field type change is `ALTER ATTRIBUTE TYPE` when nothing uses the type, a confirmed column swap (`USING col::text::new`, `weight: "rewrite"`, about 1.3 s per million rows) when only plain columns use it, and OKM1915 with no SQL when an array, a nested composite, or a function uses it. Drop type stays after the columns. Nested types are created before the outer type. Introspection reads `pg_type` `typtype = 'c'` joined to `pg_class` `relkind = 'c'`, skips dropped attributes, and orders by `attnum`. Pull writes `t.composite` and skips the generated `cf_` check. `grants: { app: "read" }` is USAGE on the type, and the same slot covers enum, domain, and schema (usage and create). Comments use the existing comment path for the type and each field. Registry keys: `type.composite`, `comment.composite`, `grants.type`. Range types, exclusion constraints, and temporal keys are a later pull request: they are a separate catalog kind and constraint, and this change already exceeds the app startup gates. No new `ErrorKind`. OKM1915 is kind `invalid`. Measured on Bun 1.4.2 against `5a91c8ca`: runtime entry `measureRuntimeEntry` 5,442 / 2,105 before and after. The gates are not raised here. `bun run type-cost` is unchanged (inferred 200 tables: 14,355 instantiations and 4,669 types).
