# D232 — Column grants, a reporting role, ownership marks, and select on `okm_meta` (P84)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`roles.columns` is `{ role, on, select?, update? }`. The privilege string is `SELECT(email,status)` or `UPDATE(...)`, columns sorted, no spaces. The grant key stays `(role, object, privilege)`. `GrantObjectRef` and `GrantDefinition` are unchanged (D116). `roles.reporting` receives `SELECT` on tables, views, and materialized views, `USAGE` on schemas, and default `SELECT` on later tables. It does not receive `INSERT`, `UPDATE`, `DELETE`, or `EXECUTE`. A table with a hidden column gets column `SELECT` of the visible columns. A hidden column is included only when `columns` names it for that role. A view keeps table `SELECT` unless `columns` lists some, and then those replace it. Default privileges would grant table `SELECT`, so a plan that grants column `SELECT` and not table `SELECT` revokes table `SELECT` first. An `UPDATE` for the reporting role, or a reporting name that is also migration or app, is kind `invalid` with `reason` `reporting_write` or `reporting_distinct`. OKM1825 stays the missing privilege. OKM1060 is a column definition. An unknown column or object is OKM1020. The reporting role is not `BYPASSRLS` and does not own tables, so `rlsTenancy` policies apply. Without `app.tenant` it sees no tenant rows. `unscoped()` is the application client's read escape and is not given to this role. A session that sets `app.unscoped` itself can read every tenant row and still cannot write. `withOwner(table(...), "external" \\| "ignored")` lives beside `table()`, not in its options, because an `owner` branch in `compile.ts` was measured at +21 / +12 on the featureless app (D218). `schema()` does not read the mark. Tooling stamps the table and its columns, indexes, constraints, triggers, policies, and dependent sequences. `startupCatalog` writes a non-managed owner back to `managed` and still returns the same reference when every owner is already `managed` and the catalog has no privilege objects. A schema without the new fields plans the same grants as before and hashes the same. A managed table that becomes `external` or `ignored` stays in the database and the plan has no DDL. Removing the declaration while the stored snapshot still says `managed` drops it. After a snapshot stores the mark, removing the declaration does not drop it. Turning it back to managed plans a difference only when the definition differs. Apply grants the application role `SELECT` on `okm_meta` and no other privilege, after the plan, on an empty target and on a database that already has the table.
