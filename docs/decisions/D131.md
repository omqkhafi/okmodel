# D131 — Removing a picklist or enum value

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

The schema never records a replacement for a removed value. `okm generate` detects removals against the last snapshot and requires `--replace table.column.old=new` (`=null` for a nullable column); without it, OKM1541 with a `fix` naming the flag. No prompt: the planner never prompts (spec 19.1), which also keeps CI and coding agents working. The mapping is written into the migration as a `backfill()` step (the sanctioned data statement, so OKM1542 is not triggered): expand moves existing rows and keeps the old constraint; contract does a final sweep and swaps the constraint (`NOT VALID` then `VALIDATE`). `t.enum` follows the same rule with a type recreate in contract. A temporary rewrite trigger that would close the rollout window completely (old release writes the removed value after the expand backfill) is deferred: the window is documented and the contract sweep cleans it. Note: `ADD CONSTRAINT … NOT VALID` takes a brief ACCESS EXCLUSIVE lock, so the runner applies it with `lock_timeout` and retry; `VALIDATE` takes SHARE UPDATE EXCLUSIVE and does not block writes. Open follow-up: `.renamedFrom()` still lives in the schema until `okm check` reports it stale; whether renames should follow the same principle is a separate decision
