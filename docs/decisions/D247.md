# D247 — Aggregate time buckets load in their own chunk (P95)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`bucket(column, unit, { tz, as, weekStart? })` is a tagged helper, like `eq`. It goes in the existing `groupBy` array beside field names. JSON cannot create one (`Symbol.for("okmodel.bucket")`). The aggregate chunk tests that symbol and does not import the helper. Validation and SQL load from `bucket-group.ts` only when `groupBy` contains a bucket. A plain aggregate keeps the old SQL (`group by t."status"`, no `date_trunc`). Units are second, minute, hour, day, week, month, quarter, and year. `as` is required, names the result key, is usable in `orderBy`, and must not clash with a group field, another bucket, or count, sum, avg, min, or max (OKM1120). An empty `as` is refused. Day, week, month, quarter, and year return `Temporal.PlainDate`, the local calendar date the period starts. Second, minute, and hour return `Temporal.Instant`, the period start. A `date` column refuses those three units before any SQL (OKM1120). A nullable column includes null. A NULL timestamp is one group: the `as` key is present and the value is null. `tz` is required on `timestamptz` and refused on `date`. `timestamp` without a zone is refused, and the message names `timestamptz` and `date`. An IANA name is checked with `Intl.DateTimeFormat` before any SQL (OKM1120). `weekStart` is monday (the default, ISO), sunday, or saturday, and only with unit week. Calendar SQL is `(date_trunc(unit, column AT TIME ZONE tz))::date`. A sunday or saturday week shifts in local time before and after the trunc (one day, or two), not inside it. Monday does not shift. A `date` column omits `AT TIME ZONE`. Clock SQL is the three-argument `date_trunc(unit, column, tz)`, which exists on Postgres 12 and later. The zone is one bound parameter. The expression is written once, in the select list, and `GROUP BY` and `ORDER BY` use select-list ordinals, because a second copy would bind a new parameter and Postgres would treat it as a different expression. There is no `having`, no gap filling, and no `onDay` helper. Tool 5 stays deferred. No new error kind. No catalog hash change. No gate move.
