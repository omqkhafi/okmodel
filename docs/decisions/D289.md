# D289 — Push re-applies, hash re-stamps, check handles triggers (0.9.1)

- **Status:** accepted
- **Area:** contracts
- **Supersedes:** none

---

Tooling and dialect introspection only. No new public runtime API. No new error kind. No catalog hash change. No gate or ceiling move. `okm push` plans from the live catalog on the target (not the last migration-file catalog), applies under a fresh `push-<n>` id from `okm_history`, and never prints `nothing to apply` when `okm_meta` differs from the head hash. An empty plan that already matches prints `no changes`. When the plan has no DDL but the stored hash drifted (an external table gained a column after the dependent exported a new snapshot), `okm push` and `okm migrate apply` re-stamp `okm_meta` and append a history row (`push-<n>` or `restamp-<n>`) under the apply lock after `okm check` has verified the snapshot. File apply enables that re-stamp only when `defineConfig({ external })` is set, so a foreign or pre-D208 roles hash without external snapshots stays for connect or the legacy restamp. A stale or missing snapshot stays OKM1841. The ownership mark is outside the startup hash; the external table's columns are inside it (D232, D277). `okm migrate check` maps a trigger's called function to the logical namespace when that function lives in the scratch schema, so `timestamps({ enforce: "trigger" })` and hand-written triggers no longer fail OKM1020. View sealing creates missing catalog extensions before stub tables and drops only those it created after the scratch schema goes away, so a first `okm push` of `citext` (or another extension type) succeeds without leaving the extension for a later `CREATE EXTENSION` step. `okm check`, `okm push`, and `okm migrate check` reprint each domain check on the connected server before they plan (`sealDomainChecks` / `reprintDomainCheck`), so an author spelling such as `VALUE > 0` is not permanent live drift or OKM1547 against `((VALUE > 0))` (B-37). The catalog hash keeps the author text. `okm migrate check` still warns OKM1552 when the stored text differs (D276). After an external re-stamp, status stays current and migrate check does not OKM1549 for external-only catalog drift when generate is empty (B-45). OKM1531 does not fire for `VALIDATE` of a temporary `col IS NOT NULL` check that an earlier step added `NOT VALID`, matching the documented type-change recipe (D285, B-36). An unknown CLI flag is `invalid` with a fix that names `okm <command> --help`; that help lists the flags for that command. Backfill progress prints a 1-based step index. Issue #336
