# D285 — OKM1538 is an expand/contract recipe in 0.9 (P119)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

There is no automatic safe form for a type change that rewrites the heap. The documented answer is five migrations: add the new column, backfill it with a `backfill()` step, dual-write with a trigger, switch reads (the safe `NOT NULL` form), then drop the old column. Each is its own migration. The example is `prices.cents` (`integer`) to `prices.amount` (`numeric(12,2)`) in [`type-change.md`](../type-change.md), and `tests/type-change-pg.test.ts` runs those migrations on Postgres. `okm migrate type-change` is not a command in 0.9. It is built later only if someone asks for it. No new error kind. No public API. No catalog hash change. No gate or ceiling moves. Issue #317
