# D292 — Explicit Postgres parameter limit (B-40)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

A finished statement over 65,535 parameters is OKM1126 (`invalid`, not retryable). The message states the count and the limit and points at chunking or `= any(array)`. The limit is for the whole statement (filters, `inList`, `limit`, values), not `inList` alone. Reads check lazily in `readHandle` before `execute` (dynamic import of the message chunk). Writes check in the lazy write `Sql.statement` / `withParams` path. Insert chunking (`WRITE_PARAM_BUDGET`) is unchanged. Split out of issue #339 / D291 (unknown keys / sensitive causes land separately) when the first wiring grew the featureless app by more than 100 B. Measured: runtime entry 5,288 / 2,026 (unchanged), featureless app +83 minified (90,801 / 29,451 against 90,900 / 30,170). No new public API. No new ErrorKind. No catalog hash change. No gate move.
