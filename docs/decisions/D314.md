# D314 — NULLS FIRST and LAST in `orderBy`: aggregate names (F8-5)

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Audit of every read that orders, on Postgres with NULL rows. `find`, `one`, and `stream` write `order by <col> asc|desc nulls first|last` through `emitOrder`; `page` keeps the keyset predicate and its cursor in step with `nulls` (`page.ts`); a window helper and a top-N `include` use the same `parseOrder`; `distinct` orders by select position. All of them already took `{ dir, nulls }`, with `asc` meaning nulls last and `desc` nulls first when `nulls` is not set. Only `aggregate` was short: `orderBy` took group keys only. It now takes `count` (always a name) and each `select` name (D311), next to group fields and bucket `as` names, in the order given. `src/runtime/aggregate.ts` writes the order clause itself for both the plain and the bucket path: a group key by its column (or by select position when the call has a bucket), an aggregate by its expression, so a `min` or `max` of a timestamp sorts as a timestamp and not as the text the select list returns. The order clause moves out of `bucket-group.ts` (one writer, not two). A name that is not a group key, `count`, or a `select` name is OKM1120 and lists the accepted names; a list-form aggregate (`sum: [...]`) has no name and is not one; `orderBy` without `groupBy` is refused as before. `nulls` other than `first` or `last` is OKM1120 for every read. No new option and no new ErrorKind. Dialects: `NULLS FIRST` and `NULLS LAST` are native on Postgres; SQLite 3.30 and later has them; MySQL and MariaDB do not, and would refuse a `nulls` that differs from their default with a stable code and no emulation. Postgres is the only dialect in this repository, so there is no refusal path to write. Capability key `query.orderNulls`. Tests: `tests/nulls-order-pg.test.ts` runs the four direction and NULL combinations through `find`, `one`, `page` (across a cursor), `stream`, a window helper, and `aggregate`; `include` is covered in `tests/relations-pg.test.ts`. No catalog hash change. No decision is reversed. Issue #510
