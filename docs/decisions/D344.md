# D344 — Roles are cluster objects with keyed grants; one pooler detector; passwords never enter a migration

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Amends D55. `roles` entries are `{ name, env?, connectionLimit?, validUntil?, memberOf?, bypassRls? }`. Keys are free; `migration`, `app`, and `reporting` keep their meaning. A string name is OKM1910. `env` names the variable that holds the role URL: the role is created with login when it is missing. No `env` creates a NOLOGIN group. There is no `login`, `external`, `superuser`, `createRole`, `createDb`, `replication`, or password field. `bypassRls` is a non-empty reason. `memberOf` options need PostgreSQL 16 and are OKM1914 on 15 before any SQL. Declared roles are catalog objects with `owner: "external"`, so a migration does not `CREATE ROLE` or `ALTER DEFAULT PRIVILEGES`. `okm roles apply --admin-env NAME` creates only missing roles and aligns only a declared `connectionLimit` and `validUntil`. It never changes a password and never drops a role. `okm migrate apply` refuses with OKM1911 until every named role exists. `okm roles set-password` is the only password change. The password is a client SCRAM-SHA-256 verifier. A server that refuses a client verifier (XX000, plaintext only) is OKM1912 and requires `--plain`; there is no silent plaintext fallback. Grants are an option on table, view, materialized view, and `fn`, keyed by role key. `"all"` is OKM1910. Declared grants are the truth for a managed role on an object OKM manages; extras are revoked in the plan and each revoke is re-read with `aclexplode`. A privilege that remains is OKM1913 and names the grantor. PUBLIC is explicit and needs `--allow-protected`, except the generated `okm_refresh_*` function, which revokes its own PUBLIC execute. Objects without `grants` keep the baseline. `detectPooler` is the one detector: host (`-pooler`, `.pooler.supabase.com`, `pooler`, `pgbouncer`), port 6543 or 6432, `pgbouncer=true`, `allowPooler`, an idle pid change, or eight overlapping clients. A stable idle pid is not direct. Proven direct is one stable pid per client and no URL or config signal. The eight clients run only when no URL signal matched and apply has a step outside a transaction, or for doctor, or when a login result is otherwise unknown. Session `set_config(..., false)` is used only when proven direct. A non-transactional step on any other URL is OKM1854 and names the signal. No new `ErrorKind`. No catalog hash change for a schema that declares no roles. No gate or ceiling moves. The startup graph grew by 5 minified bytes. CLI input bytes grew by 34,403 (1,113,747 to 1,148,150), over the +25,000 stop; the concurrent probe is the new `probeConcurrent` in `pooler-probe.ts` (recorded here as 2,733 minified bytes; D345 measures 611, and the file did not exist on main).
