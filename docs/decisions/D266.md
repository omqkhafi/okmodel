# D266 — Composed SQL fragments are a tagged operator (P102)

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

Rule 15 names composed `sql` fragments and the spec had no builder section. The check-constraint `sql` tag stays a string, so the query form is `fragment`. It is a tagged operator named `sql`. The app imports `fragment` and `ident` the way it imports any other operator. `emitLazy` already sends that name to the operator compiler, so `plan.ts` grows no branch. The compiler is `sql-fragment.ts`, loaded with the operator chunk and with a `select` that contains a fragment. A string, number, boolean, or null is a parameter. `ident(name)` is the TypeScript field, the same name `where` uses. The compiler quotes `column.sql`, so casing and `sqlName` apply. A hidden field is OKM1120 with the same fix as `where`. `hidden({ filterable: true })` is allowed in `where` only; a select fragment refuses every hidden field. An unknown name is OKM1120. The table reaches the compiler through the existing operator emit and the select compiler. `plan.ts` grows no branch. `fragment.column` is the where field. A nested fragment is parenthesized. The literal cannot carry a comment, a semicolon, a `$`, or an unbalanced quote or parenthesis (OKM1125), so it cannot close the tenant predicate. The tenant predicate is still applied first. `.as(name)` is the `select` form on `find` or `one`. The result reuses the window slot, so the key is a number, and a non-numeric wire value is OKM1125. An empty identifier is OKM1122. No new error kind. No catalog hash change. No gate or ceiling moves. Measured on this branch: featureless app 90,831 / 29,435 (gate 90,900 / 30,170, 69 minified left). P103 and P104 start from 69, not 77. Runtime entry 5,288 / 2,026, postgres.js incremental 15,953 (gate 16,000), composite types 6,931 of 6,931.
