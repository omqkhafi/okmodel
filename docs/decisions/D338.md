# D338 — The `--json` fields for a lock, and the holder's query text

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

Additive only. A run that never waits prints what it printed before (checked byte for byte against `main` on four runs). A run that waited and finished adds `attempts` and `waitedMs` to `data`. A step that gave up adds `attempts`, `waitedMs`, and `blockedBy` (`pid`, `application`, `state`, `ageMs`, `kind`) to its `errors` entry, with `retryable: true` as before. Exit codes, the code (`invalid`), and `okm.cli/1` do not change, and no `ErrorKind` is added. The holder's last query is kept on the error out of sight and printed only in a pretty terminal, cut to one line. It is never in `--json`, never in the message, and never in a log. A role that cannot read another role's query is told so and the command does not fail. Tooling only: runtime entry, app startup, connect entries, and adapters grow by 0 bytes. No gate, cap, or ceiling moves. Issue: none filed
