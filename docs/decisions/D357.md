# D357 — Range types, exclusion constraints, and temporal keys

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`t.range(name, { subtype, subtypeDiff?, collation?, multirangeName?, comment?, grants? })` sits next to `t.enum` and `t.composite`. An unused range is not a catalog object. Built-in subtype diffs are filled in. There is no `canonical` and no `tsrange`. A rename moves the range and its multirange together. A subtype, diff, or collation change swaps plain columns with `USING col::text::new` after `DROP DEFAULT`, behind `confirmTypeChanges`, `weight: rewrite`. An array or a function is OKM1915. Reads are `{ empty, lower, upper, lowerInclusive, upperInclusive }`. Writes and filters also accept a `[lower, upper)` tuple. Null is unbounded. `contains` takes an element, cast to the subtype, or a range. `adjacent`, `before`, `after`, and `isEmpty` are where operators. The operator SQL and the tuple codec load with the operator compiler, the same lazy bit as other 0.2 operators. `okmodel/expr` adds `range`, range `lower` and `upper` (the text overloads stay), `isEmpty`, and `rangeAgg`. Constructors are immutable. `rangeAgg` is an aggregate. `exclusions` is a table option. Ops are `eq`, `overlaps`, and `adjacent`. A tenant key is prefixed as `eq`. A `via()` table must name a scope column. Scalar `eq` adds `btree_gist` without a dependency edge. `where` is immutable. The stored name is `{table}_{key}_excl`. A start/end pair without an order check is OKM2128. Adding an exclusion is `weight: blocking`. The labelled estimate is 44.7 s per million rows. There is no `NOT VALID` and no online path. A bounded overlap probe runs before the lock and stops with OKM1922 and "Nothing was changed." A change is drop plus add in one transaction. The lock timeout covers acquisition only. A partitioned table that omits a partition column is OKM1020 before SQL. Round trip reads `pg_constraint` `contype = 'x'`. An undeclared exclusion is drift and pull emits it. PostgreSQL 18 `withoutOverlaps` and `period` are refused before SQL on an older server (OKM1812), and the message names `exclusions`. `UNIQUE ... WITHOUT OVERLAPS` is not a separate API. `23P01` maps to the existing `exclusion` kind and carries the constraint name, including a deferred failure at COMMIT and a temporal primary key. `ON CONFLICT DO NOTHING` works. `DO UPDATE` cannot absorb an exclusion. `40001` uses the existing `tx()` retry. Grants are USAGE. Comments use the type comment path. The five range constructors stay out of pull and check (`deptype` `i`, `a`, and `e`). PostgreSQL 19.0 has no `FOR PORTION OF` and this API does not offer it. Registry keys: `comment.range`, `grants.range`, `constraint.exclusion`, `range.operators`, `temporal.keys`. `type.range` was already registered. No new `ErrorKind`.
