# D242 — 0.6.0 blockers from the third QA pass

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`okm migrate check` no longer revokes `public` or updates `pg_namespace`. The replay creates the scratch schema inside one transaction, sets `search_path` to it, and ends with `ROLLBACK`. `pg_current_xact_id()` must be unchanged. OKM1551 flags `COMMIT`, `END`, `ABORT`, `ROLLBACK`, `BEGIN`, `START TRANSACTION`, `PREPARE TRANSACTION`, and `COMMIT PREPARED` in a step, including a `COMMIT` inside a `DO` body. A bare plpgsql `BEGIN` or `END`, `END IF`, and `ROLLBACK TO` do not match. `-- okm-allow OKM1551: reason` lets apply run the step. Check still refuses it. `VACUUM`, `CREATE DATABASE`, `DROP DATABASE`, and `ALTER SYSTEM` are skipped and named. Concurrent index, reindex, and refresh run without `CONCURRENTLY`. `ALTER TYPE … ADD VALUE` runs in the transaction. A check passes as a superuser and as a `NOSUPERUSER` `NOBYPASSRLS` owner. A postgres.js reserved connection installs `onclose` on the first statement. A later statement, savepoint, or `COMMIT` after the socket closes is not written. The error is `unavailable`, or OKM1401 when a `COMMIT` may have happened. A node-postgres or Bun.sql stream interrupted by a lost connection is `unavailable`. A postgres.js `stream()` can still end a page early with no error, and a later `cursor.next()` on a dead socket can throw outside the promise. That loop is about 264 minified bytes and waits on 0.7, after adapter and featureless-app bytes are reclaimed. No catalog hash change. No public API change. package.json stays 0.6.0. No tag and no publish. Measured: runtime entry 5,288 / 2,026, cold import 1.904 ms. Featureless app 90,824 / 30,158, cold 11.982 ms, stubbed 6.017 ms, total graph 208,986 / 67,027 (76 minified and 12 gzip under 90,900 / 30,170). postgres.js connect 42,162 / 14,870, stubbed cold 3.027 ms. The postgres.js adapter adds 15,052 minified bytes over the runtime entry, under 15,093. Issue #200
