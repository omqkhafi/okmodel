# D163 — P23 ships over the gzip line, and the cap will need a decision

- **Status:** historical
- **Area:** docs
- **Supersedes:** none

---

Traits were redesigned so the logic travels with the trait (`apply(model, ctx)` on the object `timestamps()` and `trait()` return) and `schema()` keeps only a loop. Measured on the built no-trait app: +661 minified and +312 gzip over `main` (85,568 / 28,329), down from +1,463 / +518; 657 of the 661 bytes are that loop. An app that uses `timestamps()` pays 88,273 / 29,144 in total, and the trait module itself is +2,705 / +815, paid only by apps that import it. The step is 62 gzip bytes over the D162 stop line (about 250) and under it in minified; it is accepted because a smaller version would only move checks out of one place into another. After P23 the room under 91,000 / 30,000 is 5,432 minified and 1,671 gzip for P24 to P29, about 905 and 278 each, and the heavy steps (tenancy, archivable, validation, relations, transactions) will not fit that if each one costs 300 gzip. Before P24 starts, either a size audit finds savings in what already ships (message text, duplicated helpers, error registry) or the cap is raised by an explicit decision with Ali; features are not squeezed to fit.
