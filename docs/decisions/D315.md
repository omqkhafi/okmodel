# D315 — `okm doctor --production` (X4)

- **Status:** accepted
- **Area:** tooling
- **Supersedes:** none

---

Decided with Ali on 2026-10-21. Tooling only. No public API, `ErrorKind`, or catalog hash change. No gate move. (1) `okm doctor --production` is a long-only flag. It needs one selected target: several targets and no `--target` is OKM1853 (exit 2), not a skip. It is exclusive with an error code and with `--bundle`, and `--allow-pooler` on `doctor` needs it. (2) Every query runs in one `READ ONLY` transaction on one fresh session. A connection or query failure is "Could not read target `<name>`" (exit 5). When the driver message contains ECONNREFUSED, ENOTFOUND, ETIMEDOUT, ECONNRESET, EHOSTUNREACH, 28P01, 28000, 3D000, or 57P03, that token is appended in parentheses. No output holds the URL, host, user, or password. A test scans for them. (3) Findings keep a fixed order and stable ids: `target-protection`, `pooler`, `okm-meta`, `role-privilege`, `role-owns-tables`, `role-config` (only when `config.roles` is set), `lock-timeout`, `statement-timeout`, `server-version`, `extensions`. Severity is `fail`, `warn`, or `ok`. Any `fail` exits 1 with OKM2204. (4) Rules. Protection passes only with `protected: true` in config: a name, `NODE_ENV`, and a store fingerprint (one machine) do not count. The pooler finding reuses the patterns apply refuses (`poolerSignal` in `policy.ts`, one source with `assertDirectConnection`): warn, and fail when `--allow-pooler` or `allowPooler` is on. `okm_meta` missing is a fail (OKM1520); the doctor cannot see `connect()` options such as `requireMeta` and says so. A superuser or `BYPASSRLS` login is a fail and a login that owns or inherits the catalog tables is a warn (OKM1707); with `config.roles`, `assertRoleHealth` is reused. `lock_timeout` is reported from apply's own value (5000 ms or `timeouts.lock`) because apply sets it on its session; `statement_timeout` is reported from the role's fresh session with apply's value beside it; a zero is a warn (OKM2201). The server major is a fail below 15 or below the schema floor (OKM1802, OKM1803) and a warn above 18. Required extensions reuse the OKM1811 check and print their versions. (5) New codes: OKM2201 timeouts, OKM2202 target not protected, OKM2203 pooler target, OKM2204 production check failed. (6) Not built: an exposure finding. The catalog does not record whether an exposed table has validation off (`validation` is a `schema()` option the catalog does not carry), so the check is skipped and `docs/known-limits.md` says so. The AGENTS.md block is unchanged (AX freeze). (7) Follow-up, not built here: the doctor reports `connect()` limits and intent once L-1 is merged. **Amended by D320 (a failed connection may append a driver token).**
