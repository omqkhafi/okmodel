# D206 — GitHub issues and pull requests follow one standard

- **Status:** accepted
- **Area:** ci
- **Supersedes:** none

---

Labels are `type:` (`feat`, `fix`, `perf`, `docs`, `test`, `chore`, `refactor`, `security`), `area:` (`contracts`, `dialects`, `adapters`, `runtime`, `tooling`, from the directories under `src/`, plus `ci` and `docs`), and `needs:` (`decision`, `repro`, `design`). The GitHub defaults are removed. Every issue and pull request has exactly one `type:` label and at least one `area:` label. A pull request title is `type(scope): summary`. The branch is `pNN-short-name`. The body ends with `Closes #N`. The pull request milestone is the issue milestone. One milestone per release train, closed when that release ships. The project board has a Step field, saved views by status, by milestone, and a roadmap, and every item links its pull request. Merges are squash only and the branch is deleted. Issue forms set the type. `.github/workflows/pr-meta.yml` has two jobs: `labeler` sets `area:` from paths (`.github/labeler.yml`) on opened, reopened, and synchronize, then `lint` checks out the base and runs `scripts/pr-lint.ts`. They share one file because a label added with `GITHUB_TOKEN` does not start another workflow, so a separate lint workflow could run before the `area:` label exists. `lint` runs when `labeler` succeeded or was skipped. A `dependabot[bot]` pull request skips the closing line and the milestone; its title and labels are still checked. Dependabot groups GitHub Actions and npm updates weekly, with a `chore(deps)` prefix and the `type: chore` and `area: ci` labels. `.github/release.yml` groups generated notes by `type:`. The release workflow is unchanged: it still publishes from `changelog.md`, and its `github release` job closes the milestone through `scripts/github-release.ts`. No change under `src/` or `packages/`. The written standard is `docs/github.md`. Found in P64A. Current status: a pull request has no `Closes #N` line and no milestone. Agents do not open issues.
