# D334 — A column that becomes required asks for a fill, then checks it

- **Status:** accepted
- **Area:** dialects
- **Supersedes:** none

---

On a terminal, every nullable-to-required change, and every new required column without a default on a table that already exists, asks what the empty rows get. A table created in the same plan does not. `--fill table.column=<sql>` answers it. The expression is checked read-only: the column's type, not null on the empty rows, checks, `varchar(n)` length, a constant foreign key, and a constant on a unique column. `;` and comments are refused. The steps are a D195 backfill (`where col is null`), `CHECK NOT VALID`, the same backfill, validate, set not null, drop the check. No primary key stays OKM1546. No terminal and empty rows are OKM1525, exit 1, and `--json` adds `data.needs`. No empty rows, or an unreachable target, writes the safe plan and notes that apply will stop if rows are left. Issue: none filed
