# D302 — Validated writes keep `~plan` for `batch` and `isolation` (Q1)

- **Status:** accepted
- **Area:** runtime
- **Supersedes:** none

---

`guardWrite` returned a chain handle with `sql` / `expect` / `all` and no `~plan`. `batch` requires `~plan` (OKM1121 otherwise), and `isolation()` calls `client.batch([handle.update(...)])`, so `validation: true` broke both. Decision: the chain exposes `~plan` (and `sql` / `inspect`) after the same validation step; batched validation runs before the plan executes; a failing rule rolls the whole batch back and reports OKM1200 with `issues` and `batchIndex`. `{ validate: false }`, delete, and archive stay unchanged. Unknown-key handling is R1 / D304. No new ErrorKind. No public API change. No catalog hash change. No gate or ceiling moves. Issue #388
