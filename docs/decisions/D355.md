# D355 — Typed dotted paths, composite RETURNING, round 4 lock proofs, and the session roles split

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

Amends D350 and D352. `"home.city"`, `"work.city"`, and `"project.name"` are keys of `where`, `select`, `orderBy`, and `groupBy`, and a composite field is a key of `update` `set`. The maps are not added to `FiltersOf` or `RowOf`. A seal that already has no extra key stays the featureless path. A later overload matches only when a key or a `groupBy` entry contains a dot, then checks the value. `CompositeRow` carries a type-only optional brand so a jsonb object is not a composite. Path resolution is `src/dialects/pg/path-types.ts`. A featureless `find` no longer walks keys twice: `whereMarks` records the operator bit and the dot bit in one walk, and `orderScan` reads keys. `INSERT` and `UPDATE` `RETURNING`, the version write, and the conflict follow-up select project a composite with the same `read` as a select (`to_jsonb`, or `jsonb_build_object` when a field is unsafe or nested). An array field is projected as text so the field codec reads a Postgres array literal. A counter body whose text contains `$okm$` quotes with `$okm1$`, then `$okm2$`, until the tag is absent. The next-function marker stores the column name, so it names that column's assign function, and `foldSeries` still drops both functions. On PostgreSQL 17, `pg_locks` shows `ALTER SEQUENCE ... INCREMENT` takes `ShareRowExclusiveLock` (and `RowExclusiveLock`), not `AccessExclusiveLock`, so it does not block readers. The step's lock is `SHARE ROW EXCLUSIVE` and it has no `weight`. `CREATE TRIGGER` on an existing table takes `ShareRowExclusiveLock` and `CREATE UNIQUE INDEX` takes `ShareLock`. Neither has `weight: blocking`. `SET EXPRESSION` on PostgreSQL 17 and later still takes `AccessExclusiveLock` and stays `weight: rewrite`. Widening an existing policy to `PUBLIC` is `policy-public`, class `contract`. `okmodel/session` no longer imports the roles config. `bindSessionRoles()` from `okmodel/session/role` installs it. `sessionSettings(..., { roles })` without that call is OKM1929. A role string with no `roles` map is unchanged. `setting()` and `settingList` stay in one module: the list is one function beside `setting`, which every session uses. The named foreign-key loop and the index chain stay in `schema()` and `table.ts`. The catalog getter is synchronous, `.references()` is on the featureless graph, and those helpers are what the named keys and `index()` share. `src/contracts/catalog/identity.ts` on that graph is namespace identity, not sequence bounds. `paths.ts` stays a lazy import. The planner dispatch stays in `plan.ts` because compile is synchronous.
