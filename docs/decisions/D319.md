# D319 — Safe rewrites are produced by `table-safe` from tooling on purpose

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

`notNullSteps` in `src/dialects/pg/table-safe.ts` is the `SET NOT NULL` rewrite: add `CHECK (col IS NOT NULL) NOT VALID`, validate, set not null, drop the check. Tooling calls it from `stepsForExistingTable` in `src/tooling/migrate/safe.ts` for a column or constraint on a table that already exists, before `DdlDialect.lower`. That call stays in tooling on purpose. Those statements are not moved behind `lower()` as their only producer. `lower()` also calls `notNullSteps` when an existing column changes to not null, and it marks a concurrent index create or drop `safeRewrite`. Lint covers the rewrite. OKM1531 does not fire for the temporary not-null validate (D289) or for the planner's own `NOT VALID` then `VALIDATE` pair on a column added in the same migration (D301). No refactor. No new ErrorKind. No catalog hash change. No gate move. Issue: none filed
