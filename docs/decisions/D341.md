# D341 — Introspection leaves out internal functions and does not call another language plpgsql; the proof scan reads `postgresTest` titles

- **Status:** accepted
- **Area:** product
- **Supersedes:** none

---

The function query excluded only extension members (`deptype 'e'`). It now also excludes `i` and `a`, so the five constructors of a custom range type are not the user's functions (btree_gist stays out through `e`). A function whose language is not `sql` or `plpgsql` was read as `plpgsql`; it is now left out of the catalog and reported as `not pulled yet: language <name>` through `IntrospectOptions.notPulled`, which `okm pull` lists with its other skips. New registry keys `expr.core`, `expr.where`, `step.blocking`, and `tooling.scratchCheck` have proof tests on real Postgres. A proof is a literal test title, and a Postgres-gated proof is written `postgresTest(gate, "proof:...", ...)`, so the title scan (`collectTestTitles`) now reads that call too, including when a formatter splits it across lines; a registry key with no such title still fails `registryProblems`. Docs: the pages already said "PostgreSQL 15 and later; tested on 15 to 19"; the one stale comment (`ops/lane.ts`) is fixed. Measured with `bun run size` and the build: runtime entry 5,442 / 2,105 (unchanged), featureless app startup 92,943 / 30,657 (unchanged), postgres.js adapter 22,153 / 8,139 (unchanged), type-cost unchanged on every row, CLI chunks +11,778 minified (2,041,449 to 2,053,227 over the files `tooling/cli.js` reaches), `dist` JavaScript +16,777 (the lazy `okmodel/expr` entry is 4,661 of it), tarball +7,011 bytes (1,246,065 to 1,253,076). No gate or ceiling moves. Issue: none (PR only)
