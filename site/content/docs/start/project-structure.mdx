See the files in the project and what each one is for.

You have followed [Installation](/docs/start/installation) and [First schema](/docs/start/first-schema), or you have a directory with `package.json` and a Bun lockfile.

Use the tutorial layout when the files stay flat, the driver is postgres.js, you apply with [`okm push`](/docs/reference/cli/migrate#push), and the database can be recreated. Use the `okm init` layout when the schema and the client live in `db/`, the SQL files live in `migrations/`, and the scripts are check, plan, apply, and status.

<Steps>

<Step>
### Tutorial files

The tutorial writes these files in the project directory. `schema.ts` default-exports the notes schema. `okmodel.config.ts` is the file `okm push` reads. `db.ts` is the client. `check.ts` waits until the startup check finishes. `insert.ts`, `find.ts`, `one.ts`, `count.ts`, `exists.ts`, `update.ts`, and `delete.ts` are the calls. `find-without-limit.ts` and `update-without-where.ts` are the calls that throw OKM1101 and OKM1102.

</Step>

<Step>
### `okm init`

`okm init` writes starter files. It does not connect. In a directory whose `package.json` name is `notes`, with a `bun.lock` and no driver package, and with no terminal, `bunx okm init` writes this tree. A Bun project with no driver package selects `bun-sql`. The tutorial installs postgres.js and imports `okmodel/pg/postgresjs`.

```sh
bunx okm init
```

```text title="init.tree"
.
├── .env.example
├── .gitattributes
├── .gitignore
├── .okm
│   └── init.json
├── db
│   ├── client.ts
│   └── schema.ts
├── migrations
│   └── .gitkeep
├── okmodel.config.ts
└── package.json
```

</Step>

<Step>
### Files `okm init` writes

| File | What it is for |
| --- | --- |
| `db/schema.ts` | Example `users` table. `t.id()`, `minPostgres: 15`, and a named `app` schema. |
| `db/client.ts` | The client. An empty `DATABASE_URL` is refused. This run imports `okmodel/pg/bun`. |
| `okmodel.config.ts` | `schema` is `./db/schema.ts`. `migrations` is `./migrations`. `database` is set only when `DATABASE_URL` is a non-empty string. |
| `migrations/.gitkeep` | The migrations directory. |
| `.env.example` | `DATABASE_URL=` with no value. Init does not write `.env`. |
| `.gitattributes` | Line endings for migration SQL, catalog JSON, and `.okm`. |
| `.gitignore` | `.env` and `.env.local`. |
| `package.json` | Adds the `okmodel` dependency and `db:check`, `db:plan`, `db:apply`, and `db:status`. |
| `.okm/init.json` | The choices and the hash of each file init wrote. |

The command ends with the next three commands.

```text title="init.next"
bun run --bun okm check
bun run --bun okm migrate plan init
bun run --bun okm migrate apply
```

[`okm generate init`](/docs/reference/cli/migrate#generate) writes the first migration. That is a different command. The tutorial uses [`okm push`](/docs/reference/cli/migrate#push).

</Step>
