---
title: "Warnings"
description: "Development advice for a query. The level is configuration. The code number is the subject."
---

`okmodel/warnings` exports `warnings`. Pass it to `connect`. Production reports nothing until a level is set. Development reports a hint for low severity and a warn for medium or high. `error` throws and is meant for a test.

An ignore needs a reason. `okm check` lists project ignores. It does not run the query rules.

```ts title="warnings.ts"
import { connect } from "okmodel/pg/postgresjs";
import { id, schema, table, text } from "okmodel/pg";
import { warnings } from "okmodel/warnings";

const notes = table("notes", { id: id(), title: text() });
const app = schema({ tables: [notes] });

export const db = connect(process.env.DATABASE_URL ?? "", {
  schema: app,
  warnings: warnings({
    levels: { "deep-offset": "warn" },
    ignore: [{ rule: "unordered-limit", reason: "one row" }],
  }),
});
```

`offset` above 1,000 is OKM2004. A `limit` whose order does not end in a unique key is OKM2005. A value list above 500 elements is OKM2007. An include whose row product is above 10,000 is OKM2008. `page()` is the cursor alternative to a deep offset.
