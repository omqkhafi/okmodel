title: "Errors"
description: "OkmError carries a kind, a category, and a code. okm doctor prints each OKM code."
---
A failure from the client is an `OkmError`. Import the class from `okmodel`.

```ts title="catch.ts"
import { OkmError } from "okmodel";

export function respond(error: unknown) {
  const err = OkmError.from(error); // [!code focus]
  return err.toHttp();
}
```

`code` is an `OKM1xxx` guard, or the kind name when that kind has no number. `kind` selects the category. `summary` is the same text as `message`.

## Fields

| Field | What it holds |
| --- | --- |
| `code` | `OKM1xxx`, or the kind when that kind has no number. |
| `kind` | One of the kinds below. |
| `category` | The category of that kind. |
| `summary` | What failed. Same string as `message`. |
| `retryable` | Whether a declared retry may run the call again. |
| `fix` | `{ summary, suggestion? }`. `suggestion` is a nearer accepted name. |
| `table` | Table the database named, when it named one. |
| `columns` | Columns the failure names. Empty when it names none. |
| `constraint` | Constraint name the database sent. |
| `sqlstate` | SQLSTATE the database sent. |
| `batchIndex` | Statement index inside a batch, or `null` on one statement and at commit. |
| `issues` | Validation checks. Present on OKM1200. |

`fields()` maps each column to a reason. The same object comes back on later calls. It has no row values.

`values()` returns row values only when the error was built with `includeValues`. [Errors](/docs/define/connect/errors) on connect is where that flag is set. `log()` returns the structured record: name, code, kind, category, summary, retryable, batch index, fix, fields, and table, columns, constraint, SQLSTATE, and issues when they are set. It leaves the row values out, and so does `toHttp()`. The logger on the client receives `{ code, summary }`.

`toHttp()` returns `{ status, body }`. The body is `{ code, reason, fields }`. `reason` is the summary. A category missing from the status map keeps the default in the table below.

`match` runs the handler for this category. `_` runs when that category is omitted.

```ts title="match.ts"
import { OkmError } from "okmodel";

export function formOrHttp(error: OkmError) {
  return error.match({
    input: (item) => item.fields(), // [!code focus]
    conflict: (item) => item.fields(), // [!code focus]
    _: (item) => item.toHttp(), // [!code focus]
  });
}
```

`OkmError.is` narrows the kind, and the table when you pass one.

```ts title="unique.ts"
import { OkmError } from "okmodel";

export function emailTaken(error: unknown): boolean {
  return OkmError.is(error, "unique", "notes"); // [!code focus]
}
```

`OkmError.from` returns an `OkmError` unchanged. A `DriverError` whose kind is `timeout`, `cancelled`, or `outcome_unknown` keeps that kind. Any other thrown value becomes kind `driver` and code `driver`. `from` does not read constraint SQLSTATEs. The client does that before a query rejects.

A query exposes the same settlement as `safe` from `okmodel`.

```ts title="insert.ts"
import { db } from "./db.ts";

export async function addNote(title: string) {
  const result = await db.notes.insert({ title }).safe(); // [!code focus]
  if (!result.ok) return result.error.summary;
  return result.value;
}
```

`{ ok: true, value }` is success. `{ ok: false, error }` is the mapped `OkmError`.

<Callout type="info" title="Row values">
The summary drops `=(...)` from a server message, and turns `contains (...)` into `contains (…)`. With `includeValues: true`, `values()` still returns the row. The log line does not.
</Callout>

## Kinds

`ERROR_KINDS` and `ERROR_CATEGORIES` are exported from `okmodel`. The constructor derives the category from the kind. A transient kind retries, except `cancelled`. `outcome_unknown` is internal, and it does not retry.

| Kind | Category | Status | Retries |
| --- | --- | --- | --- |
| `invalid` | `input` | 422 | no |
| `not_null` | `input` | 422 | no |
| `check` | `input` | 422 | no |
| `foreign_key` | `input` | 422 | no |
| `unique` | `conflict` | 409 | no |
| `exclusion` | `conflict` | 409 | no |
| `conflict` | `conflict` | 409 | no |
| `not_found` | `not_found` | 404 | no |
| `not_unique` | `not_found` | 404 | no |
| `forbidden` | `forbidden` | 403 | no |
| `serialization` | `transient` | 503 | yes |
| `deadlock` | `transient` | 503 | yes |
| `lock_timeout` | `transient` | 503 | yes |
| `timeout` | `transient` | 503 | yes |
| `cancelled` | `transient` | 503 | no |
| `unavailable` | `transient` | 503 | yes |
| `schema_drift` | `internal` | 500 | no |
| `driver` | `internal` | 500 | no |
| `read_only` | `internal` | 500 | no |
| `outcome_unknown` | `internal` | 500 | no |

Pass `http` on connect, or pass statuses to `toHttp(statuses)`, to replace one of these. A category you leave out keeps the status in the table. The connect page is [Errors](/docs/define/connect/errors).

When the constructor is given no `fix`, the kind supplies one sentence.

| Kinds | Default fix |
| --- | --- |
| `cancelled` | Do not retry. The caller aborted the call. |
| `outcome_unknown` | Check whether the write landed, using an idempotency key, before retrying. |
| `timeout`, `serialization`, `deadlock`, `lock_timeout`, `unavailable` | Retry the call. |
| `unique`, `exclusion`, `conflict` | Change the conflicting value, or update the existing row. |
| `not_null` | Provide a value for the column. |
| `check`, `invalid` | Change the value so it passes the check. |
| `foreign_key` | Use a key that exists, or insert the referenced row first. |
| `not_found` | Look up a row that exists. |
| `not_unique` | Narrow the filter so it matches one row. |
| `forbidden` | Use a role that is allowed to perform this operation. |
| `read_only` | Run the write on the primary. |
| `schema_drift` | Apply the migrations that match this build. |
| `driver` | Read the summary and correct the call. |

A fix passed in replaces that sentence. A rejected name that is close to an accepted one appends a did-you-mean hint to the summary and sets `fix.suggestion` to that name.

## Which code, which kind

Three codes pick a kind when the caller does not pass one.

| Code | Kind |
| --- | --- |
| `OKM1401` | `outcome_unknown` |
| `OKM1846` | `timeout` |
| `OKM1520` | `schema_drift` |

A code that is itself a kind name uses that kind. A mapped database error does this for every kind except `outcome_unknown`. The client also raises `invalid`, `not_found`, `not_unique`, `timeout`, `cancelled`, `unavailable`, and `forbidden` with the kind as the code. Every other `OKM1xxx`, with no `kind` passed, is `invalid`.

Four codes pass a kind other than that default.

| Code | Kind |
| --- | --- |
| `OKM1522` | `conflict` |
| `OKM1825` | `forbidden` |
| `OKM1850` | `forbidden` |
| `OKM1851` | `forbidden` |

## Driver failures

The adapter normalises the driver exception into `DriverError`. postgres.js and node-postgres put the SQLSTATE on `code`. Bun.sql puts `ERR_POSTGRES_SERVER_ERROR` on `code` and the SQLSTATE on `errno`. The copied fields are `sqlstate`, `constraint` (`constraint_name` or `constraint`), `table` (`table_name` or `table`), `column` (`column_name` or `column`), `detail`, and `batchIndex`.

`cancelled()` is the caller's signal. `timedOut()` is a statement, transaction, or batch deadline. `outcomeUnknown()` is a commit whose result never arrived. Those three stay `DriverError` until the client maps them. `acquireTimeout()` is already `OkmError` `OKM1846`. A closed pool is a `DriverError` with SQLSTATE `08006`.

The client maps that error. An `OkmError` passes through. A driver kind of `timeout`, `cancelled`, or `outcome_unknown` wins over the SQLSTATE. `57014` without one of those kinds is `timeout`, because `cancelled` comes only from the signal.

| SQLSTATE | Kind |
| --- | --- |
| `23505` | `unique` |
| `23502` | `not_null` |
| `23514` | `check` |
| `23503`, `23001` | `foreign_key` |
| `23P01` | `exclusion` |
| `23000` | `conflict` |
| `40001` | `serialization` |
| `40P01` | `deadlock` |
| `55P03` | `lock_timeout` |
| `57014` | `timeout` |
| `40003` | `outcome_unknown` |
| `25006` | `read_only` |
| class `08`, `53300`, `57P01`, `57P02`, `57P03` | `unavailable` |
| class `22` | `invalid` |
| class `53` | `unavailable` |

Anything else is kind `driver`. With no SQLSTATE, a TLS failure or a dropped connection is `unavailable`.

The connection codes are `ECONNRESET`, `ECONNREFUSED`, `EPIPE`, `ENOTFOUND`, `ETIMEDOUT`, `CONNECT_TIMEOUT`, `EHOSTUNREACH`, `ENETUNREACH`, `EAI_AGAIN`, `CONNECTION_CLOSED`, `CONNECTION_ENDED`, `CONNECTION_DESTROYED`, and `ERR_POSTGRES_CONNECTION_CLOSED`. Classification reads the code, the errno, or the SQLSTATE. It does not read the message. A TLS cause starts with `ERR_TLS_`, `ERR_POSTGRES_TLS_`, or `SELF_SIGNED_CERT_`, or is exactly `DEPTH_ZERO_SELF_SIGNED_CERT` or `UNABLE_TO_VERIFY_LEAF_SIGNATURE`.

These SQLSTATEs keep their kind and add a reason.

| SQLSTATE | Kind stays | Reason |
| --- | --- | --- |
| `42P01` | `driver` | `undefined_table` |
| `42703` | `driver` | `undefined_column` |
| `0A000`, message contains `materialized view is not populated` | `driver` | `not_populated` |
| `55000`, message contains `cannot refresh materialized view` and `concurrently` | `driver` | `no_unique_index` |
| `42501`, message contains `materialized view` | `driver` | `not_owner` |
| no SQLSTATE, TLS cause | `unavailable` | `tls` |

`fields()` uses that reason. With a schema, the reason is the catalog object's name key for the columns the error names. With no schema, `table_pkey` becomes `pkey`, and a trailing `_fkey`, `_check`, or `_key` is removed. No constraint name leaves the kind as the reason.

Bun.sql and PGlite reject a positive `timeout` as `OKM1120`. The message is `timeout`. The kind is `invalid`. They cannot cancel a statement that is already running.

## Doctor

`okm doctor OKM1020` prints the registry entry: the code, the title, the summary, and the fix.

```text title="okm doctor OKM1020"
OKM1020: Unknown table
A table, dependency, or catalog object is missing or does not match its identity.
Use a name that is in the schema. The error lists the accepted names and a nearest-name hint when one is close.
```

An unknown code throws `OkmError` with code `invalid`. The message is `Unknown code`, then the argument, then a period. The fix says to pass a code from the registry, or to run `okm doctor` with no argument.

With no code, the command lists each table's triggers, one line per table, or `no triggers`. When the config sets `roles`, it also connects and checks that those roles exist, that a managed role can be created, and that the application role can reach each managed object. The command does not change the database.

The registry is not on the runtime entry. A process that never explains a code does not load it.
