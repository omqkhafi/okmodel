The agent skills in this repository, and when to run each one.

A skill is a file an agent reads and follows. Skills live at `.agents/skills/<name>/SKILL.md`. The `description` in that file says when it applies. This repository ships one skill.

The site publishes one skill for agents that are not in this repository. The index is [`/.well-known/agent-skills/index.json`](/.well-known/agent-skills/index.json). The file is [`/.well-known/agent-skills/okmodel/SKILL.md`](/.well-known/agent-skills/okmodel/SKILL.md). Those bytes are `skills/okmodel/SKILL.md` in the repository, the same file the npm tarball ships. It points at `node_modules/okmodel/docs/index.md` and the safe `okm` command order. The index pins that file with a SHA-256 digest.

In your own project, `okm init --agents` and `okm agents update` copy that skill into `.claude/skills/okmodel/` and `.agents/skills/okmodel/` and keep the AGENTS.md block current. See [agents](/docs/reference/cli#agents).

## okm-ship

`.agents/skills/okm-ship/SKILL.md` is for a release. Do not run it to finish a pull request. A pull request does not edit `changelog.md` and does not bump `package.json`.

Finish the work, run `bun run verify:fast` once, push once, and `gh pr merge --auto --squash`. Then stop.

### When it applies

- `bun run bump release` when publishing a release. An empty `## Unreleased` is filled from squash-merge subjects since the last `vX.Y.Z` tag, then promoted to `## vX.Y.Z — <date>`.
- `bun run bump next --publish` when publishing a prerelease. The version becomes `<next minor>-next.N`. The changelog stays as it is. Without `--publish` the command refuses.

`patch`, `minor`, `major`, and `--set` still promote the changelog. `--dry-run` prints the plan and writes nothing.

### Notes the release writes

Merged titles use `type(scope): summary`.

| Title | Changelog group |
| --- | --- |
| `feat` | `### ✨ Added` |
| `fix` | `### 🐛 Fixed` |
| `perf`, `refactor` | `### ♻️ Changed` |
| `security` | `### 🔒 Security` |
| `type(scope)!:` or a `BREAKING CHANGE:` body line | `### 💥 Breaking Changes` |
| `docs`, `test`, `chore` | omitted |

A group with eight or more bullets gains `####` headings in this order: `contracts`, `dialects`, `adapters`, `runtime`, `tooling`, `docs`. Hand-written bullets already under `## Unreleased` are kept.

### What it must not do

- Append a changelog bullet on a feature pull request.
- Run `bun run bump next` to mark a pull request as shipped.
- Update the pack snapshot or `docs/size-audit.md` as pull-request bookkeeping.
