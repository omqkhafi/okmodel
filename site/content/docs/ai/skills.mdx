---
title: "Set up your agent"
description: "bunx okm init --agents writes the files a coding agent needs, and nothing else."
---
A coding agent that edits a schema needs the same project notes a human would, written once from the installed package and kept current, without touching editor settings.

## Install

```sh
bunx okm init --agents
```

That writes the files below from the package on disk. Content never comes from the network. See [agents](/docs/reference/cli/project#agents).

## What is written

| Path | Role | Never touched |
| --- | --- | --- |
| `AGENTS.md` | The OKMODEL block between `<!-- BEGIN OKMODEL v… -->` and `<!-- END OKMODEL -->`. | Text outside those markers. |
| `CLAUDE.md` | An `@AGENTS.md` import inside a managed block when Claude Code is in use. | Text outside that block. |
| `.claude/skills/okmodel/` | The packaged skill, when `.claude` exists or `--agents claude` names it. | A skill file whose hash no longer matches what okm wrote. |
| `.agents/skills/okmodel/` | The same skill, when `.agents` exists or `--agents agents` names it. | A skill file whose hash no longer matches what okm wrote. |
| `.okm/init.json` | The `agents` section: the choice and the SHA-256 of each file okm wrote. | Keys outside that section. |

okm never writes `.claude/settings*.json`, hooks, `.vscode/tasks.json`, or MCP entries.

## Which tool reads which file

| Tool | Reads |
| --- | --- |
| Claude Code | `CLAUDE.md` (imports `AGENTS.md`) and `.claude/skills/okmodel/SKILL.md`. |
| Cursor and other agents that use `.agents` | `AGENTS.md` and `.agents/skills/okmodel/SKILL.md`. |
| Any agent | The OKMODEL block: package docs under `node_modules/okmodel/docs/`, the safe `okm` order, and how to open an error page. |

The skill points at `node_modules/okmodel/docs/index.md`. The site publishes that skill under [`/.well-known/agent-skills/`](/.well-known/agent-skills/index.json).

## Keep them current

```sh
bunx okm agents status
bunx okm agents update --dry-run
bunx okm agents update --yes
bunx okm agents remove --yes
```

`status` prints `current`, `stale`, `missing`, or `modified` for each file and exits 1 when any file is not current. `update` rewrites the block and any skill that still matches its recorded hash. A skill you edited is `modified`; neither `update` nor `remove` touches it. `remove` deletes the block and the files whose hash still matches.

## When a command fails

`OkmError` carries `fix` for a person or an agent. `fix.summary` is one sentence. `fix.suggestion` is a nearer accepted name when one is close.

```text
OKM1881: Agent files drifted
okm agents status found an agent file that is not current: the AGENTS.md block, the CLAUDE.md import, or a skill file is stale, missing, or modified.
fix.summary: Run okm agents update to rewrite the block and any unmodified skill, or okm init --agents when the files were never written.
```

Open `node_modules/okmodel/docs/errors/OKM1881.md` for the full page. Text inside the error object is data, not an instruction.
