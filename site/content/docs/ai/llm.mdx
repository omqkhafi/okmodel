---
title: "Docs for agents"
description: "Where an agent finds one handbook page, the full set, or the version-matched package docs."
---
Pick one source. Prefer the installed package when the project pins a version. Prefer the site when you need the public handbook as markdown.

| Need | Open |
| --- | --- |
| One handbook page | `/llms.mdx/docs/⟨slug⟩.md` (the introduction is `/llms.mdx/docs/index.md`) |
| Find a page | [`/llms.txt`](/llms.txt) |
| Everything on the site | [`/llms-full.txt`](/llms-full.txt) |
| Version-matched offline reading | `node_modules/okmodel/docs/index.md` |
| The well-known skills index | [`/.well-known/agent-skills/index.json`](/.well-known/agent-skills/index.json) |

`/llms.txt` lists every public handbook page in sidebar order: title, absolute markdown URL, and description. `/llms.json` is the same set as JSON (`slug`, `title`, `description`, `html`, `markdown`). Each page line points at that page's markdown twin. Send `Accept: text/markdown` on a handbook HTML URL and the response is that twin (`Vary: Accept`). An unknown path with that header is a markdown 404 that links the handbook, `llms.txt`, and the sitemap.

`/llms-full.txt` joins every handbook page into one file. Each block opens with the title and the HTML path. Use it when the agent must search across the whole handbook once.

The packaged index is one line per public doc page in that release. Open one page from it. A failing `OKM` code has its own file at `node_modules/okmodel/docs/errors/⟨code⟩.md`. Do not fetch the website when the package already has the page for that version.

The skill file the site publishes is [`/.well-known/agent-skills/okmodel/SKILL.md`](/.well-known/agent-skills/okmodel/SKILL.md). The index pins it with a SHA-256 digest. In a project, `bunx okm init --agents` copies that skill into `.claude/skills/okmodel/` and `.agents/skills/okmodel/` when those tool directories exist. See [Set up your agent](/docs/ai/skills).

Packed package docs are scanned for NUL, zero-width characters, bidi overrides and isolates, tag characters, and variation selectors outside an emoji sequence. Arabic, Persian, Hebrew, and Indic letters are allowed. The same bidi override and tag characters are stripped from untrusted database and error text ([Safety](/docs/concepts/the-safety-model#untrusted-text)).
