Pick one source. Prefer the installed package when the project pins a version. Prefer the site when you need the public handbook as markdown.

| Need | Open |
| --- | --- |
| One handbook page | `/llms.mdx/docs/⟨slug⟩.md` (the introduction is `/llms.mdx/docs/index.md`) |
| Find a page | [`/llms.txt`](/llms.txt) |
| A section you can read in one fetch | The Optional section of [`/llms.txt`](/llms.txt) names `llms-core` and one file per section |
| Search | [`/api/search?query=OKM1101`](/api/search?query=OKM1101) |
| Version-matched offline reading | `node_modules/okmodel/docs/index.md` |
| The well-known skills index | [`/.well-known/agent-skills/index.json`](/.well-known/agent-skills/index.json) |

`/llms.txt` lists every public handbook page in sidebar order: title, absolute markdown URL, and a one-line description. The Optional section lists every agent file. `llms-core` is Get started, Concepts, the query calls you use first, and the "I want to…" index. Each other file is one section. A file longer than 100,000 characters is split, and the parts are numbered. `/llms.json` is the same page set as JSON (`slug`, `title`, `description`, `html`, `markdown`) plus the `files` list. Each page line points at that page's markdown twin. Send `Accept: text/markdown` on a handbook HTML URL and the response is that twin (`Vary: Accept`). An unknown path is a 404, in HTML and in markdown, with the closest pages.

The Errors page markdown is an index: one line per code. One code is `GET /docs/reference/errors/OKM1101.md`. The same body is `Accept: text/markdown` on `/docs/reference/errors/OKM1101`. A browser request to that extensionless URL redirects to `/docs/reference/errors#okm1101`. An unknown code is a 404 with the closest pages. There is no `llms-errors.txt`. The reference section file includes the index, and a second file would repeat it.

## Search

`GET /api/search?query=` returns JSON:

```json
{
  "query": "OKM1101",
  "results": [
    {
      "title": "OKM1101",
      "url": "/docs/reference/errors#okm1101",
      "markdown": "https://okm.omqkhafi.dev/docs/reference/errors/OKM1101.md",
      "summary": "find, descendants, or ancestors was called without a limit, or a limit is above limits.max. connect({ limits }) can set a default for find, descendants, ancestors, page, and groupBy.",
      "section": "Reference",
      "chip": ""
    }
  ]
}
```

`title` is the page title, or the code when the query is one registry code. `url` is the HTML path, or `/docs/reference/errors#okm####` for that code. `markdown` is the absolute `.md` URL. `summary` is the page summary, or the registry summary for a code. `section` is the sidebar section. `chip` is the support line when the page names a feature, and empty otherwise. The same index answers [`/search`](/search) as HTML, without JavaScript.

The packaged index is one line per public doc page in that release. Open one page from it. A failing `OKM` code has its own file at `node_modules/okmodel/docs/errors/⟨code⟩.md`. Do not fetch the website when the package already has the page for that version.

The skill file the site publishes is [`/.well-known/agent-skills/okmodel/SKILL.md`](/.well-known/agent-skills/okmodel/SKILL.md). The index pins it with a SHA-256 digest. In a project, `bunx okm init --agents` copies that skill into `.claude/skills/okmodel/` and `.agents/skills/okmodel/` when those tool directories exist. See [Set up your agent](/docs/ai/skills).

Packed package docs are scanned for NUL, zero-width characters, bidi overrides and isolates, tag characters, and variation selectors outside an emoji sequence. Arabic, Persian, Hebrew, and Indic letters are allowed. The same bidi override and tag characters are stripped from untrusted database and error text ([Safety](/docs/concepts/the-safety-model#untrusted-text)).
