A `table()` call is one relation: columns, a [key](/docs/schema/keys-and-identity#keys) (the primary key), and optional indexes and other options. Here is a complete `notes` table, then the SQL `okm generate init` writes for it.

```ts title="notes.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    published: t.boolean().default(false),
  },
  { indexes: (columns) => [index(columns.title)] },
);
```

`t` is the column [builder](/docs/schema/columns): one helper per Postgres type. Import a single builder when a file uses only that type. Wrap the table in [`schema()`](/docs/schema/the-schema) and run `bunx okm generate init`. The migration opens with:

```sql title="0001_init.sql"
create table "public"."notes" (
  "id" bigint generated always as identity not null,
  "published" boolean not null default false,
  "title" text not null,
  constraint "notes_pkey" primary key ("id")
);

create index "notes_title_idx" on "public"."notes" ("title");
```
