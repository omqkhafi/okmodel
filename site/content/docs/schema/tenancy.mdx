---
title: "Tenancy"
description: "A tenant key on every table, for() to scope reads and writes, and the SQL that follows."
---
Tenancy keeps one tenant's rows apart from another's. A tenant key is a [guarded uuid](/docs/schema/visibility) column the schema adds — input cannot set it; `for()` supplies it. A predicate is the SQL filter that column adds to every read and write. Importing `okmodel/tenancy` is what loads that predicate.

## The model

Declare schema tenancy with `columnTenancy({ key, type: "uuid" })`. Every table stores that key unless you mark it otherwise. `for({ tenantId })` opens a scoped client for one tenant.

```ts title="model.ts"
import { connect } from "okmodel/pg/postgresjs";
import { schema, table, t } from "okmodel/pg";
import { columnTenancy } from "okmodel/tenancy";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

const app = schema({
  tables: [notes],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
});

export async function add(url: string, title: string) {
  await using db = connect(url, { schema: app });
  const scoped = db.for({ tenantId: "018f3b2c-7a11-7c3a-8e2d-6b4a9c1d0e5f" });
  return scoped.notes.insert({ title });
}
```

`okm generate init` creates the table with the key in the primary key and a unique on `(id, tenantId)`:

```sql title="notes-tenant.sql"
create table "public"."notes" (
  "id" bigint generated always as identity not null,
  "tenantId" uuid not null,
  "title" text not null,
  constraint "notes_pkey" primary key ("id", "tenantId")
);

alter table "public"."notes" add constraint "notes_id_tenantId_key" unique ("id", "tenantId");
```

A scoped insert returns the key the scope set. A scoped find adds `tenantId` to the `where`. `inspect()` shows the SQL and a `tenancy` rule:

```text title="insert.out"
{
  id: "1",
  title: "Hello",
  tenantId: "018f3b2c-7a11-7c3a-8e2d-6b4a9c1d0e5f",
}
```

```text title="find.inspect"
sql: {
  text: "select t.\"id\", t.\"title\", t.\"tenantId\" from \"notes\" t where t.\"tenantId\" = $1 and t.\"id\" = $2 limit $3",
  params: [ "018f3b2c-7a11-7c3a-8e2d-6b4a9c1d0e5f", "1", "1" ],
}
rules: [
  …,
  { rule: "tenancy", contribution: "scoped", provenance: "planner" },
]
```

A scoped update filters the same way. `inspect()` and `describe()` both show the statement:

```text title="update.inspect"
statements: [
  {
    text: "update \"notes\" as t set \"title\" = $1::text where t.\"tenantId\" = $2 and t.\"id\" = $3",
  }
]
```

`unscoped("reason")` drops the predicate for that client. Insert still needs `for()`. A call with no scope is refused (see [Errors](#errors-on-a-table)).

## On a table

Omitted, the table stores the schema key. `global` and `via` come from `okmodel/tenancy`.

### Key

The key is a guarded uuid. Insert fills it from `for()`. A read or a write filters on it. Input cannot set it.

A unique includes the key. The primary key does too. An index is prefixed with the key, so a unique index is unique per tenant and two tenants may share a value. `tenantIndexes: false` turns the prefix off for this table. One index can opt out with `.global("reason")` or opt in with `.scoped()`. Nearest level wins: an index option overrides the table's `tenantIndexes`, which overrides the schema's `indexes`. With the prefix off, an index that does not start with the key is refused. A `using` tail is not prefixed that way — `index().global("reason")` is the option that works for it. A foreign key to another tenant table includes the key, so `set null` and `set default` are refused. See [references](/docs/schema/references).

#### unique

`.unique({ global: "reason" })` leaves the key out of that one constraint. `{ global: true, reason }` is the same opt-out.

```ts title="unique.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  email: t.text().unique({ global: "login email" }),
  title: t.text().unique(),
});
```

`email` is unique across tenants. `title` is unique inside one tenant.

### Global

`global("reason")` leaves the tenant column off this table. The reason is stored and `inspect()` shows it on the `tenancy` rule as `contribution: "global <reason>"`.

```ts title="global.ts"
import { table, t } from "okmodel/pg";
import { global } from "okmodel/tenancy";

export const plans = table(
  "plans",
  { id: t.identity(), code: t.text() },
  { tenancy: global("plans are shared") },
);
```

```text title="global.inspect"
rules: [
  …,
  {
    rule: "tenancy",
    contribution: "global plans are shared",
    provenance: "catalog",
  },
]
sql: {
  text: "select t.\"id\", t.\"code\" from \"plans\" t limit $1",
  params: [ "1" ],
}
```

### Path

`via("project.organization")` follows to-one relations (each step is a `one(...)` relation name), separated by `.`, up to three. The last table stores the tenant key. This table does not. A read or a write adds `exists` along that path. Explain `via()` once here; the schema section links back.

```ts title="path.ts"
import { one, table, t } from "okmodel/pg";
import { via } from "okmodel/tenancy";

export const organizations = table("organizations", {
  id: t.identity(),
  name: t.text(),
});

export const projects = table(
  "projects",
  {
    id: t.identity(),
    organizationId: t.bigint().references("organizations"),
    name: t.text(),
  },
  { relations: { organization: one("organizations") } },
);

export const tasks = table(
  "tasks",
  {
    id: t.identity(),
    projectId: t.bigint().references("projects"),
    title: t.text(),
  },
  {
    relations: { project: one("projects") },
    tenancy: via("project.organization"),
  },
);
```

### Calls

`for({ tenantId })` opens a client for one tenant. The value is a uuid. `unscoped("reason")` drops the predicate. Insert still needs `for()`.

#### simple

One tenant table. Insert sets `title`. The scope sets `tenantId`.

```ts title="simple.ts"
import { connect } from "okmodel/pg/postgresjs";
import { schema, table, t } from "okmodel/pg";
import { columnTenancy } from "okmodel/tenancy";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

const app = schema({
  tables: [notes],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
});

export async function add(url: string, title: string) {
  await using db = connect(url, { schema: app });
  const scoped = db.for({ tenantId: "018f3b2c-7a11-7c3a-8e2d-6b4a9c1d0e5f" });
  return scoped.notes.insert({ title });
}
```

#### complex

`organizations` stores the key. `projects` follows `organization`. `tasks` follows `project.organization`. `plans` is global, so the root client can insert it. The scoped client inserts the rest.

```ts title="complex.ts"
import { connect } from "okmodel/pg/postgresjs";
import { one, schema, table, t } from "okmodel/pg";
import { columnTenancy, global, via } from "okmodel/tenancy";

const organizations = table("organizations", {
  id: t.identity(),
  name: t.text(),
});

const projects = table(
  "projects",
  {
    id: t.identity(),
    organizationId: t.bigint().references("organizations"),
    name: t.text(),
  },
  {
    relations: { organization: one("organizations") },
    tenancy: via("organization"),
  },
);

const tasks = table(
  "tasks",
  {
    id: t.identity(),
    projectId: t.bigint().references("projects"),
    title: t.text(),
  },
  {
    relations: { project: one("projects") },
    tenancy: via("project.organization"),
  },
);

const plans = table(
  "plans",
  { id: t.identity(), code: t.text() },
  { tenancy: global("plans are shared") },
);

const app = schema({
  tables: [organizations, projects, tasks, plans],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
});

export async function open(url: string) {
  await using db = connect(url, { schema: app });
  await db.plans.insert({ code: "free" });
  const scoped = db.for({ tenantId: "018f3b2c-7a11-7c3a-8e2d-6b4a9c1d0e5f" });
  const org = await scoped.organizations.insert({ name: "Acme" });
  const project = await scoped.projects.insert({
    name: "Ship",
    organizationId: org.id,
  });
  return scoped.tasks.insert({ title: "Write", projectId: project.id });
}
```

| Code | When | Message |
| --- | --- | --- |
| [OKM1060](/docs/reference/errors#okm1060) | Tenancy mark is neither `global` nor `via` | `Table notes tenancy must be global("reason") or via().` |
| [OKM1060](/docs/reference/errors#okm1060) | Empty `global` / `via` / unique-global reason | `global() needs a reason.` / `via() needs a relation path.` / `unique() global needs a reason.` |
| [OKM1012](/docs/reference/errors#okm1012) | Table already declares the key column | `Table notes already declares tenantId, which tenancy adds. Rename the field or drop it from the table.` |
| [OKM1190](/docs/reference/errors#okm1190) | Insert names the key | `Field notes.tenantId is the tenant key. The scope sets it. Input cannot.` |
| [OKM1704](/docs/reference/errors#okm1704) | Update or filter names the key | `Field notes.tenantId is the tenant key. An update cannot change it.` / `A filter cannot set it.` |
| [OKM1701](/docs/reference/errors#okm1701) | Call with no scope | `Table notes is tenant-scoped. Call for({ tenantId }).` |
| [OKM1705](/docs/reference/errors#okm1705) | Global table references a tenant table; bad `via` path | `Table plans.code is global and references tenant table notes…` / hop, missing to-one, ends on global, cycle, or parent outside tenant. |
| [OKM1706](/docs/reference/errors#okm1706) | Index does not lead with the key when prefix is off | `Index on notes starts with title. Put tenantId first.` |

## On the schema

`tenancy` is `columnTenancy()`, `compositeTenancy()`, or `rlsTenancy()` from `okmodel/tenancy`. Omitted, no table gains a key.

Each key is a guarded uuid. Insert fills it from `for()`. Reads and writes filter on it. Input cannot set it. A unique, a unique index, and the primary key include every key. Another index is prefixed with the first key unless `indexes: false`. `global("reason")` and [`via()`](#path) are the table marks.

### omitted

No tenant column, and `for()` is not on the client. A table that still sets `tenancy` is refused.

```ts title="omitted.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
});
```

### column

`columnTenancy({ key, type: "uuid" })` adds one key. `type` is `"uuid"`.

```ts title="column.ts"
import { columnTenancy } from "okmodel/tenancy";
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
});
```

`for({ tenantId })` opens a client for one tenant. The value is a uuid. `unscoped("reason")` drops the predicate. Insert still needs `for()`. The root client keeps a global table and hides a tenant table.

```ts title="for.ts"
import { connect } from "okmodel/pg/postgresjs";
import { columnTenancy, global } from "okmodel/tenancy";
import { schema, table, t } from "okmodel/pg";

const plans = table(
  "plans",
  { id: t.identity(), code: t.text() },
  { tenancy: global("plans are shared") },
);

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

const app = schema({
  tables: [plans, notes],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
});

export async function add(url: string, tenantId: string, title: string) {
  await using db = connect(url, { schema: app });
  await db.plans.find({ limit: 1 });
  return db.for({ tenantId }).notes.insert({ title });
}
```

### indexes

`indexes` defaults to true. Every ordinary index on a tenant table gains the first key as its first column. A unique index gains every key, in order, so two tenants cannot share the value. Under composite tenancy that is the whole key. `indexes: false` leaves each index as written, and OKM1706 applies. A table's `tenantIndexes` overrides this. An index `.global("reason")` or `.scoped()` overrides the table. Nearest level wins. An index that already names the key moves it to the front and does not list it again. Two indexes that become the same one are OKM1023, and the message names both declarations. The catalog, `okm generate`, and `describe()` show those resolved columns.

```ts title="indexes.ts"
import { columnTenancy } from "okmodel/tenancy";
import { index, schema, table, t } from "okmodel/pg";

const notes = table(
  "notes",
  { id: t.identity(), email: t.text(), title: t.text() },
  {
    indexes: (columns) => [
      index(columns.email).unique(),
      index(columns.title).global("shared title"),
    ],
  },
);

export default schema({
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
  tables: [notes],
});
```

`email` is unique inside one tenant: the index is `(tenantId, email)`. `title` stays a global index. `indexes: false` on `columnTenancy()` turns the prefix off. `tenantIndexes: false` turns it off for one table, and `.scoped()` turns it back on for one ordinary index. A `using` index is not prefixed that way: the default and `.scoped()` throw OKM1706 (`A using tail is not prefixed.`), and `.global("reason")` is the call that works.

A project whose indexes already start with the key sees no migration. An index that does not is replaced once: `okm generate` writes `CREATE INDEX CONCURRENTLY` for the new index, then `DROP INDEX CONCURRENTLY` for the old one. That is not a blocking rebuild. `okm migrate check` accepts it. The next `okm generate` writes nothing.

### composite

`compositeTenancy({ key, type: "uuid" })` adds every name, in that order. `for()` takes every key. One name is `columnTenancy()`. A unique index includes every key, so `index(c.email).unique()` stores `(organization_id, workspace_id, email)`. An ordinary index is prefixed with the first key only.

```ts title="composite.ts"
import { connect } from "okmodel/pg/postgresjs";
import { compositeTenancy } from "okmodel/tenancy";
import { schema, table, t } from "okmodel/pg";

const documents = table("documents", {
  id: t.identity(),
  title: t.text(),
});

const app = schema({
  tables: [documents],
  tenancy: compositeTenancy({
    key: ["organizationId", "workspaceId"],
    type: "uuid",
  }),
});

export async function add(
  url: string,
  organizationId: string,
  workspaceId: string,
  title: string,
) {
  await using db = connect(url, { schema: app });
  return db.for({ organizationId, workspaceId }).documents.insert({ title });
}
```

### row level

`rlsTenancy({ key, type: "uuid" })` is one key. The column predicate stays. Policies are the backstop — a second line of defence in Postgres itself: `notes_tenant` and `notes_unscoped_select` on a table named `notes`. A view that exposes the key is `security_invoker`. `via()` and a key list are refused. `unscoped()` can read and cannot write. Row-level security does not stop the application role from running arbitrary SQL that sets `app.tenant` itself. The reporting role can set `app.unscoped` itself and read every tenant through the select policy; it still cannot write.

```ts title="rls.ts"
import { rlsTenancy } from "okmodel/tenancy";
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  tenancy: rlsTenancy({ key: "tenantId", type: "uuid" }),
});
```

A healthy role check is cached for that endpoint until its generation changes. A failed check is not cached. The message names the endpoint.

### Schema path

Use [`via()`](#path) on the table. The last hop stores the key; this table does not. A read or a write adds `exists` along that path.

```ts title="schema-path.ts"
import { columnTenancy, via } from "okmodel/tenancy";
import { one, schema, table, t } from "okmodel/pg";

const organizations = table("organizations", {
  id: t.identity(),
  name: t.text(),
});

const projects = table(
  "projects",
  {
    id: t.identity(),
    organizationId: t.bigint().references("organizations"),
    name: t.text(),
  },
  { relations: { organization: one("organizations") } },
);

const tasks = table(
  "tasks",
  {
    id: t.identity(),
    projectId: t.bigint().references("projects"),
    title: t.text(),
  },
  {
    relations: { project: one("projects") },
    tenancy: via("project.organization"),
  },
);

export default schema({
  tables: [organizations, projects, tasks],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }),
});
```
