```ts title="one-column.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  { indexes: (columns) => [index(columns.title)] }, // [!code focus]
);
```

## What it does

<Callout type="info" title="Where this fits">
The columns exist. This page adds an index the planner can use. A unique constraint stays on [Keys](/docs/schema/keys-and-identity#keys). A rule the row must pass is a [check](/docs/schema/checks).
</Callout>

`indexes` is a function. It receives one handle per column and returns an array of `index()` calls. `schema()` stores those indexes. A return value that is not an array is OKM1060: `Table notes indexes must return an array.`

<Callout type="info" title="SQL name">
The handle's `name` is the SQL name `schema()` will store. A [casing](/docs/schema/names-and-casing#casing) of `"snake"` has already been applied by the time the catalog is written.
</Callout>

<Callout type="error" title="OKM1060">
An empty call is `Index on notes needs a column.` A value that is not a handle is `Index on notes must be built from column handles.` A return value that is not an array is `Table notes indexes must return an array.`
</Callout>

### Index

`index(...)` takes column handles, in index order. One argument may instead be an expression from `okmodel/expr`, or `sql` when the expression has no typed form. Each column argument is `columns.field`. The first argument is the first key of the index. The index is named `{table}_{columns}_idx`, using the SQL column names joined by `_`. `.name("lookup_title")` stores that SQL name instead. A name longer than 63 bytes is OKM1122 when the plan is built. `okm pull` writes `.name()` when the database name is not the generated one.

#### Partial [feature="index.partial"]

`.where()` is a partial index. The argument is a where object, an expression, or `sql`.

#### Expression [feature="index.expression"]

One argument may be an expression from `okmodel/expr`, or `sql` when the expression has no typed form.

#### Covering [feature="index.covering"]

`.include(columns.id)` adds covering columns.

#### Ordering [feature="index.ordering"]

`columns.email.desc()`, `.nullsFirst()`, `.nullsLast()`, and `.ops("text_pattern_ops")` set order and the operator class.

#### Nulls not distinct [feature="index.nullsNotDistinct"]

`.unique({ nullsNotDistinct: true })` stores nulls as not distinct. The chip on this heading is the floor.

#### Storage [feature="index.storage"]

`.with({ fillfactor: 90 })` sets storage parameters. `.using("gin" | "gist" | "brin" | "hash" | "spgist")` sets the access method. btree is the default and is not stored. The keys are typed for btree, gin, gist, and brin. An extension method such as hnsw accepts a record. `.comment("...")` is the index comment.

The planner owns `CONCURRENTLY`. There is no `.concurrently()` on the chain. A new table adds the index with `create index`. A table that already exists adds it with `create index concurrently`. A storage-parameter change rebuilds the index: create a new one concurrently under a temporary name, drop the old one, and rename. `ALTER INDEX ... SET` changes reloptions only and does not rebuild.

`okm check` refuses a non-immutable predicate or expression (OKM1848), including `now()`, `current_date`, `random()`, and a function declared stable or volatile. Unique, descending, and nulls order are btree only. Include is btree, gist, or spgist, and only plain columns. Those method restrictions are OKM1903. A partial index does not satisfy a foreign key (OKM2101). It satisfies a filter column only when a preset's `where()` includes the predicate (OKM2103). `filters()` does not, because it names fields and not values. An expression index is undecidable. A duplicate index is OKM2104. A shorter plain index that is a prefix of another is OKM2105. Unique, partial, and expression indexes are redundant only on a full match. When a partial-index predicate column is also a `filters()` field or a preset field, OKM2106 warns: those filters compile to bound parameters, so a generic plan may ignore the index. Inlining those constants is a later decision.

#### one

One column is one index. This one is `notes_title_idx`.



#### order

Column order is the index order. These two calls are different indexes: `notes_published_title_idx` and `notes_title_published_idx`.

```ts title="order.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    published: t.boolean().default(false),
  },
  {
    indexes: (columns) => [
      index(columns.published, columns.title), // [!code focus]
      index(columns.title, columns.published), // [!code focus]
    ],
  },
);
```

#### several

Several indexes are several calls in the same array. A lookup on `title` and a lookup on `published` then `title` are stored separately.

```ts title="several.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    published: t.boolean().default(false),
  },
  {
    indexes: (columns) => [
      index(columns.title), // [!code focus]
      index(columns.published, columns.title), // [!code focus]
    ],
  },
);
```

#### sql name

A [SQL name](/docs/schema/names-and-casing#sql-name) you set is the name that is joined. Here the table is `note` and the column is `published_at`, so the index is `note_published_at_idx`.

```ts title="sql-name.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    publishedAt: t.boolean().sqlName("published_at"), // [!code focus]
  },
  {
    sqlName: "note", // [!code focus]
    indexes: (columns) => [index(columns.publishedAt)],
  },
);
```

#### casing

[Casing](/docs/schema/names-and-casing#casing) `"snake"` rewrites a name you did not set. `publishedAt` is stored as `published_at`, and the index is `notes_published_at_idx`.

```ts title="casing.ts"
import { index, schema, table, t } from "okmodel/pg";

const notes = table(
  "notes",
  {
    id: t.identity(),
    publishedAt: t.boolean(), // [!code focus]
  },
  { indexes: (columns) => [index(columns.publishedAt)] },
);

export const app = schema({
  tables: [notes],
  casing: "snake", // [!code focus]
});
```

A new table adds the index with `create index`. A table that already exists adds it with `create index concurrently`. That step is not inside a transaction.

### Unique

`.unique()` marks that index unique. The columns and their order stay the ones you passed to `index()`.

Only a btree index can be unique. `.unique()` on a `gin` or `gist` index, such as `trgm.gin(columns.title.name).unique()`, is OKM1903 when the plan is built. The message names the index and its method. For case-insensitive uniqueness, prefer [`citext`](/docs/schema/text-columns#citext). `index(sql\`lower(email)\`)` is for uniqueness of the lowered value, not for case-insensitive lookup.

#### one

One column is the usual case. This index is `users_email_idx`.

```ts title="unique-column.ts"
import { index, table, t } from "okmodel/pg";

export const users = table(
  "users",
  {
    id: t.identity(),
    email: t.text(),
  },
  { indexes: (columns) => [index(columns.email).unique()] }, // [!code focus]
);
```

#### several

Several columns are unique together, in the order you pass. This index is `notes_published_title_idx`.

```ts title="unique-columns.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    published: t.boolean().default(false),
  },
  { indexes: (columns) => [index(columns.published, columns.title).unique()] }, // [!code focus]
);
```

#### beside

A plain index and a unique index can share the array. `title` is `notes_title_idx`. `email` is `notes_email_idx`, and only that one is unique.

```ts title="mixed.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    email: t.text(),
  },
  {
    indexes: (columns) => [
      index(columns.title), // [!code focus]
      index(columns.email).unique(), // [!code focus]
    ],
  },
);
```

<Callout type="warning" title="Not a constraint">
A unique constraint and a unique index are different objects. A constraint belongs on [keys](/docs/schema/keys-and-identity#keys). A foreign key waits for that constraint. `.unique()` here does not create it.
</Callout>

### Tenant tables

On a tenant table an ordinary index leads with the tenant key, unless this index calls `.global("reason")` or the table sets `tenantIndexes: false`. `.scoped()` puts the key first on that ordinary index. A unique index is then unique inside one tenant: two tenants may store the same value. A `using` index is not prefixed. The default and `.scoped()` both throw OKM1706 when the columns do not already lead with the tenant key: `Index on notes starts with title. A using tail is not prefixed.` `.global("reason")` is the call that works. Putting the tenant key first in the declaration does not prefix a `using` tail. An index that already leads with the key is left as written. See [tenancy](/docs/schema/tenancy#on-the-schema).

## When to use it

Read this when a query needs a secondary index: partial, expression, covering, ordered, or with storage options.

## When not to

Use [Keys and identity](/docs/schema/keys-and-identity) for the primary key and unique constraints, and [Checks](/docs/schema/checks) for a predicate that rejects a row.

## What the plan shows

On a new table the step is `create-index`, class expand, lock SHARE. On a table that already exists the same kind runs concurrently, lock SHARE UPDATE EXCLUSIVE, and it is not in the DDL transaction.

## Errors

- [OKM1060](/docs/reference/errors#okm1060): `indexes` that does not return an array is OKM1060.
- [OKM1122](/docs/reference/errors#okm1122): An index name longer than 63 bytes is OKM1122 when the plan is built.
- [OKM1848](/docs/reference/errors#okm1848): `okm check` refuses a non-immutable predicate or expression, including `now()` and `random()`, as OKM1848.
- [OKM1903](/docs/reference/errors#okm1903): An index method this page does not allow is OKM1903.
- [OKM2101](/docs/reference/errors#okm2101): A partial index does not satisfy a foreign key, and that is OKM2101.
- [OKM2103](/docs/reference/errors#okm2103): A filter column is covered only when a preset's `where()` includes the predicate, or the finding is OKM2103.
- [OKM2104](/docs/reference/errors#okm2104): A duplicate index is OKM2104.
- [OKM2105](/docs/reference/errors#okm2105): A shorter plain index that is a prefix of another is OKM2105.
- [OKM2106](/docs/reference/errors#okm2106): A partial-index predicate column that is also a `filters()` or preset field warns OKM2106, because those filters are bound parameters.
- [OKM1706](/docs/reference/errors#okm1706): On a tenant table, an index that does not already lead with the tenant key is OKM1706.
