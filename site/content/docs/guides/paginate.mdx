---
title: "Paginate a list"
description: "Use page() for cursors, or a stable find limit, and know when the last page ends."
---

Goal: page a list with a stable order, see the last page, and avoid an unstable limit.

Detail lives on [Read rows](/docs/queries/read-rows#page), [Query limits](/docs/operate/query-limits), and [Warnings](/docs/reference/warnings).

## 1. Prefer `page()` for a UI list

`page` returns `{ items, next }`. `next` is `null` on the last page. Pass it back as `after` with the same `orderBy`. `limit` is required unless `connect({ limits: { page } })` sets a default.

```ts title="page.ts"
import { connect } from "okmodel/pg/postgresjs";
import { id, schema, table, text } from "okmodel/pg";
import { warnings } from "okmodel/warnings";

const notes = table("notes", { id: id({ default: "none" }), title: text() });
export const app = schema({ tables: [notes] });

export async function list(url: string): Promise<void> {
  await using db = connect(url, {
    schema: app,
    warnings: warnings({
      env: "development",
      onWarning: (notice) => {
        console.log(`${notice.code}: ${notice.summary}`);
        console.log(`Fix: ${notice.fix.summary}`);
      },
    }),
  });
  await db.notes.insert([
    { id: "01890c5a-8f0e-7c3a-9b2d-6e4f1a0b9c01", title: "a" },
    { id: "01890c5a-8f0e-7c3a-9b2d-6e4f1a0b9c02", title: "b" },
    { id: "01890c5a-8f0e-7c3a-9b2d-6e4f1a0b9c03", title: "c" },
  ]);
  const first = await db.notes.page({ orderBy: { title: "asc", id: "asc" }, limit: 2 });
  console.log(JSON.stringify({ items: first.items.map((row) => row.title), next: first.next != null }));
  const second = await db.notes.page({
    orderBy: { title: "asc", id: "asc" },
    limit: 2,
    after: first.next,
  });
  console.log(JSON.stringify({ items: second.items.map((row) => row.title), next: second.next }));
  await db.notes.find({ limit: 2 });
  const rows = await db.notes.find({ orderBy: { title: "asc", id: "asc" }, limit: 2 });
  console.log(JSON.stringify(rows.map((row) => row.title)));
}
```

```text title="page.out"
{"items":["a","b"],"next":true}
{"items":["c"],"next":null}
OKM2005: A limit whose order does not end in a unique key can return a different row set each time. Under for(), the tenant key is ignored, so the rest of that unique counts.
Fix: End orderBy with the primary key or a unique column.
["a","b"]
```

## 2. `page` versus a keyset `find`

| API | Use when |
| --- | --- |
| `page({ orderBy, limit, after })` | A UI that walks forward with a cursor. Last page is `next: null`. |
| `find({ orderBy, limit })` | One bounded slice. End `orderBy` with a unique key. |
| `.stream()` | Walk the set in keyset batches without holding a server cursor. |

Deep `offset` on `find` is the wrong tool for large lists. Above 1,000 it warns as [OKM2004](/docs/reference/errors#okm2004).

## 3. Limits

With no `limit`, `find` and `page` are refused ([OKM1101](/docs/reference/errors#okm1101)) unless `connect({ limits })` supplies a default. A written `limit` above `limits.max` is the same code. `.all(reason)` is the deliberate unbounded read. See [Query limits](/docs/operate/query-limits).

## What can go wrong

- [OKM1101](/docs/reference/errors#okm1101): missing `limit` on `page` or `find`.
- [OKM1130](/docs/reference/errors#okm1130): `after` is not a cursor this call returned, or the key row is gone.
- [OKM2005](/docs/reference/errors#okm2005): `orderBy` under a `limit` does not end in a unique key.
