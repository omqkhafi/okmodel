Goal: translate a Prisma mental model into okmodel tables and queries, then pull an existing database.

This page is a map, not feature parity. Prisma documents models and Client CRUD in its own docs; okmodel keeps limits, tenancy, and reviewed migrations as first-class refusals.

## Concept map

| Prisma | okmodel |
| --- | --- |
| `model` | `table(...)` inside `schema({ tables })` |
| `@relation` / relation fields | `.references(...)` plus `relations: { ... }` with `one` / `many` |
| `findMany` | `find({ where, orderBy, limit })` |
| `findFirst` / `findUnique` | `one({ where })` or `find` with `limit: 1` |
| `create` | `insert` |
| `createMany` | `insert([...])` |
| `update` / `updateMany` | `update({ where, set })` |
| `delete` / `deleteMany` | `delete({ where })` |
| `$transaction` | `tx()` or `batch()` |
| `prisma migrate` | `okm generate` then `okm migrate apply` |
| `prisma db pull` | `okm pull` |

On a relational database Prisma says a model becomes a table. Relations use a link field plus a relation field. Those ideas land as `table`, `references`, and `relations` here. Client names above are the Prisma ORM 7 Client surface (`findMany`, and so on).

## Intentionally different

- **Limits.** A `find` or `page` with no `limit` is refused ([OKM1101](/docs/reference/errors#okm1101)) unless you set `connect({ limits })` or call `.all(reason)`. There is no implicit unbounded list.
- **Tenancy.** `columnTenancy` and `for({ tenantId })` stamp and filter the key. Prisma Client has no built-in tenant scope like `for()`.
- **Soft delete.** Soft delete is the `archivable()` trait plus `archive` / `restore`, not a Client middleware convention.
- **Migrations.** Reviewed SQL files, lint codes, lock lines, and protected targets. There is no down migration.
- **Raw SQL.** Typed raw SQL needs describe and a lock file; a tenant schema refuses raw without `trusted` / `unscoped`.

## What has no equivalent here

Say these plainly: no Prisma Client extension API, no Prisma Accelerate / Pulse product surface, no MongoDB connector, no implicit many-to-many without a join table in the schema, and no `prisma studio`. Middleware-style query hooks are not the write path; use observers and warnings instead.

A Drizzle schema import exists (`okm import drizzle`). There is no `okm import prisma` in this version.

## Adopt an existing database

```sh title="pull.sh"
bunx okm pull
bunx okm generate init
bunx okm migrate baseline
```

`okm pull` writes table files and the schema from the live database. `okm generate init` writes the head snapshot. `okm migrate baseline` records that snapshot as applied history without running DDL. Then develop with generate and apply as usual. The full path is [Existing database](/docs/migrations/adopt-existing-database).

```ts title="pull-config.ts"
import { defineConfig } from "okmodel/migrate";

export default defineConfig({
  schema: "./schema.ts",
  tables: "./tables",
  database: process.env.DATABASE_URL!,
});
```

## What can go wrong

- [OKM1855](/docs/reference/errors#okm1855): pull would replace an existing file.
- [OKM1857](/docs/reference/errors#okm1857): baseline on a database that already has OKModel history.
- [OKM1858](/docs/reference/errors#okm1858): baseline sees managed objects that do not match the pulled schema.
