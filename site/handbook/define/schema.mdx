## Tables

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `tables` | yes | — | Declaration order. A later table can reference an earlier one. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({ tables: [notes] }); // [!code focus]
```

<Callout type="info" title="Export">
The module default-exports the result. [Config](/docs/define/config) points `schema` at this file.
</Callout>

## Casing

`casing` sets the SQL name of a camelCase field.

| Value | Result |
| --- | --- |
| omitted | The SQL name is the field name. |
| `"snake"` | A camelCase field is stored as snake_case. |
| any other value | Refused. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  publishedAt: t.timestamptz().nullable(), // [!code focus]
});

export default schema({
  tables: [notes],
  casing: "snake", // [!code focus]
});
```

<Callout type="info" title="sqlName">
`publishedAt` is stored as `published_at`. A column [sqlName](/docs/define/table#names) still wins for that column.
</Callout>

<Callout type="warning" title="Only snake">
`"snake"` is the only value. Anything else is refused.
</Callout>

## Codecs

Codecs choose the TypeScript value. The SQL type stays the same.

| Codec | Values | Default |
| --- | --- | --- |
| `bigint` | `"string"`, `"number"`, `"bigint"` | `"string"` |
| `numeric` | `"string"`, `"number"` | `"string"` |
| `timestamps` | `"temporal"` | `"temporal"` |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const payments = table("payments", {
  id: t.identity(),
  amount: t.numeric(),
  cents: t.bigint(),
});

export default schema({
  tables: [payments],
  codecs: {
    bigint: "string", // [!code focus]
    numeric: "string", // [!code focus]
    timestamps: "temporal", // [!code focus]
  },
});
```

<Callout type="warning" title="Other values">
Any other value is refused when the schema is built.
</Callout>

<Callout type="info" title="Column as">
A column can still name its own `as` where that builder accepts one. The schema codec is the default for builders that do not.
</Callout>

## Row types

`types` is how row types are produced.

| Value | Result |
| --- | --- |
| omitted | `"emitted"`. |
| `"emitted"` | Writes the row types out. |
| `"inferred"` | Keeps them in the checker. |
| any other value | Refused. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  types: "inferred", // [!code focus]
});
```

<Callout type="warning" title="Other values">
Anything other than `"emitted"` or `"inferred"` is refused.
</Callout>

## Id default

`defaults.id` is what a bare `t.id()` means. A column option wins. `id` is the only name.

| Value | Result |
| --- | --- |
| omitted | A bare `t.id()` stores `uuidv7()`. |
| `"uuidv7"` | Stores `uuidv7()`. |
| `"uuidv4"` | Stores `gen_random_uuid()`. |
| a client generator | Filled on insert. Stays out of the catalog. `okid(...)` is [OKID](/docs/define/table#okid). |
| another key | Refused. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.id(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  defaults: { id: "uuidv7" }, // [!code focus]
});
```

<Callout type="info" title="On the column">
`t.id({ default: "none" })` takes the id on insert. That option is on the column, not on `defaults`.
</Callout>

<Callout type="error" title="OKM1812">
`uuidv7()` needs Postgres 18. A [requires](#postgres-version) floor below 18 is refused.
</Callout>

## Postgres version

`requires.postgres` is the engine this schema is written for. Connect records it.

| Value | Result |
| --- | --- |
| omitted | No version is named. A `uuidv7()` default stays. |
| `">=18"` | Names the engine. `uuidv7()` stays. |
| a floor below 18, such as `">=15"` | Refuses `uuidv7()` (OKM1812). |
| `""` | Refused. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.id({ default: "uuidv4" }),
  title: t.text(),
});

export default schema({
  tables: [notes],
  requires: { postgres: ">=15" }, // [!code focus]
});
```

<Callout type="error" title="OKM1812">
A floor below 18, such as `">=15"`, refuses a `uuidv7()` default.
</Callout>

## Traits

`traits` apply to every table. Importing `okmodel/traits` is what loads them. A schema that never imports a trait does not carry that code.

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `traits` | no | none | Applied to every table that does not opt out. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";
import { timestamps } from "okmodel/traits"; // [!code focus]

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  traits: [timestamps()], // [!code focus]
});
```

<Callout type="info" title="timestamps">
`timestamps()` adds `createdAt` and `updatedAt`. Both are sealed. `updatedAt` is set on update. `{ enforce: "trigger" }` also writes `updatedAt` in the database.
</Callout>

<Callout type="info" title="Opt out">
A table opts out with `omitDefaults` and a reason. The table can still pass its own `traits`. See [table traits](/docs/define/table#table-traits).
</Callout>

<Callout type="warning" title="Reason">
`omitDefaults` needs a reason. An empty reason is rejected when the schema is built.
</Callout>

## Tenancy

`tenancy` adds one tenant key to every table. Import it from `okmodel/tenancy`. The key is a guarded uuid. Insert and update omit it. The client fills it from the scope.

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `tenancy` | no | none | No tenant key until this is set. |
| `key` | yes | — | One name for `columnTenancy()`. Several names are `compositeTenancy()`. |
| `type` | yes | — | `"uuid"`. Anything else is refused. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";
import { columnTenancy } from "okmodel/tenancy"; // [!code focus]

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  tenancy: columnTenancy({ key: "tenantId", type: "uuid" }), // [!code focus]
});
```

<Callout type="info" title="Opt out">
A table opts out with `global("reason")`. A table that follows a relation instead of storing the key uses `via`. Both live on the [table](/docs/define/table#table-tenancy).
</Callout>

<Callout type="info" title="Unique">
A unique on a tenant table includes the key, unless the column calls `.unique({ global: "reason" })`.
</Callout>

## Validation

`validation` turns rules on for the schema. `schema()` stores the flag. It does not run the rules. `okm check` reads them, and the engine reads them on the first validated call.

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `validation` | no | off | Omit it and rules stay off. `true` turns them on. `false` leaves them off. |
| `enabled` | no | `true` on an object | Omitting this key inside an object turns rules on. |
| `onRead` | no | `false` | `true` runs the rules on read. |
| `style` | no | unset | `"inline"` or `"section"`. |

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  validation: { enabled: true, onRead: false, style: "inline" }, // [!code focus]
});
```

<Callout type="info" title="Per table">
A table can turn the flag on or off with its own `validation`. The rules themselves are [on the table](/docs/define/table#column-validation): a `validate` section, or `.validate()` on a column.
</Callout>

<Callout type="error" title="OKM1030">
The same field in the table `validate` section and in `.validate()` is refused. `okm check` reports it.
</Callout>

## Extensions

`extensions` is a list of extension definitions. Each one contributes its catalog record. `schema()` does not install the extension. Migrate writes `create extension`.

| Value | Import | Result |
| --- | --- | --- |
| `citext()` | `okmodel/pg/citext` | Declares `citext`. A [citext](/docs/define/table#text) column needs this name. |
| `pgTrgm()` | `okmodel/pg/pg_trgm` | Declares `pg_trgm`. `similar`, `wordSimilar`, `gin`, and `gist` are methods on that value. |
| `extension("name")` | `okmodel/ext` | Declares that name. There is no typed API. `ltree` is this form. |

Every call takes the same options.

| Option | Default | Result |
| --- | --- | --- |
| `version` | unpinned | `1.6` is written as `version '1.6'`. `>=0.7` is stored and is not written. An unpinned record matches any installed version. |
| `schema` | `public` | Objects are installed in that schema. |
| `relocatable` | `true` | `false` refuses a later move (OKM1814). |

```ts title="schema.ts"
import { pgTrgm } from "okmodel/pg/pg_trgm"; // [!code focus]
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  extensions: [pgTrgm()], // [!code focus]
});
```

<Callout type="error" title="OKM1813">
The same extension name twice is refused.
</Callout>

<Callout type="error" title="OKM1810">
A column that names an extension this list does not contain is refused. A plain object in the list is refused when another item is a real extension.
</Callout>

<Callout type="error" title="OKM1020">
A `citext` or `ltree` column is refused when `extensions` is omitted or empty.
</Callout>

## Functions

`functions` lists routines. `fn()` comes from `okmodel/fn`. `schema()` stores the catalog record. It does not run the body.

| Field | Required | Default | Values |
| --- | --- | --- | --- |
| `returns` | yes | — | The return type. |
| `language` | yes | — | `"sql"` or `"plpgsql"`. |
| `body` | yes | — | The routine body. |
| `volatility` | no | `"volatile"` | `"volatile"`, `"stable"`, `"immutable"`. |
| `security` | no | `"invoker"` | `"invoker"` or `"definer"`. |
| `schema` | no | `public` | The install schema. |
| `searchPath` | for `"definer"` | — | Missing on a definer is OKM1823. |
| `dependsOn` | for plpgsql | — | Missing on plpgsql is OKM1824. `LANGUAGE sql` that begins with `BEGIN ATOMIC` can omit it. |
| `arguments` | no | none | Each argument has a `name` and a `type`. |

```ts title="schema.ts"
import { fn } from "okmodel/fn"; // [!code focus]
import { schema, sql, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

const touch = fn("touch_notes", { // [!code focus]
  returns: "trigger", // [!code focus]
  language: "plpgsql", // [!code focus]
  body: sql`begin return new; end`, // [!code focus]
  dependsOn: [notes], // [!code focus]
}); // [!code focus]

export default schema({
  tables: [notes],
  functions: [touch], // [!code focus]
});
```

<Callout type="warning" title="plpgsql">
plpgsql without `dependsOn` is refused. Postgres does not record dependencies inside that body.
</Callout>

<Callout type="info" title="BEGIN ATOMIC">
A `LANGUAGE sql` body that begins with `BEGIN ATOMIC` can omit `dependsOn`. The edges are read from `pg_depend`.
</Callout>

<Callout type="info" title="Trigger">
A [trigger](#triggers) calls one of these functions.
</Callout>

## Triggers

`triggers` lists triggers. `trigger()` comes from `okmodel/fn`. Identity is the table plus the name.

| Field | Required | Default | Values |
| --- | --- | --- | --- |
| `on` | yes | — | The table. |
| `timing` | yes | — | `"before"`, `"after"`, `"instead"`. |
| `events` | yes | — | `"insert"`, `"update"`, `"delete"`, `"truncate"`. |
| `level` | yes | — | `"row"` or `"statement"`. |
| `calls` | yes | — | A function in this schema. |
| `updateOf` | no | — | SQL column names for `UPDATE OF`. |
| `when` | no | — | Optional SQL. |

```ts title="schema.ts"
import { fn, trigger } from "okmodel/fn";
import { schema, sql, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
  updatedAt: t.timestamptz().defaultSql("now()"),
});

const touch = fn("touch_notes", {
  returns: "trigger",
  language: "plpgsql",
  body: sql`begin new.updated_at = now(); return new; end`,
  dependsOn: [{ table: notes, column: "updated_at" }],
});

export default schema({
  tables: [notes],
  casing: "snake",
  functions: [touch],
  triggers: [ // [!code focus]
    trigger("notes_touch", { // [!code focus]
      on: notes, // [!code focus]
      timing: "before", // [!code focus]
      events: ["update"], // [!code focus]
      level: "row", // [!code focus]
      calls: touch, // [!code focus]
    }), // [!code focus]
  ], // [!code focus]
});
```

<Callout type="warning" title="SQL names">
`updateOf` and a `dependsOn` column are SQL names. With [casing](#casing) `updatedAt` is `updated_at`.
</Callout>

## Views

`views` lists views and materialized views. Both come from `okmodel/view`. You declare the output columns and the query. `schema()` stores the record.

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `columns` | yes | — | The output columns. Each has `name` and `type`. |
| `query` | yes | — | The SQL, stored as written. |
| `schema` | no | `public` | The install schema. |
| `tenancy` | no | — | `global("reason")` opts out. A tenant view that hides the key is OKM1820. |
| `indexes` | no | none | A materialized view only. |
| `refresh` | no | blocking | `"concurrently"` needs a unique index (OKM1822). Any other value is OKM1120. |

```ts title="schema.ts"
import { schema, sql, table, t } from "okmodel/pg";
import { materializedView, view } from "okmodel/view"; // [!code focus]

const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

const openNotes = view("open_notes", { // [!code focus]
  columns: [{ name: "id", type: "bigint" }, { name: "title", type: "text" }], // [!code focus]
  query: sql`select id, title from notes`, // [!code focus]
}); // [!code focus]

const noteCounts = materializedView("note_counts", { // [!code focus]
  columns: [{ name: "n", type: "bigint" }], // [!code focus]
  query: sql`select count(*) as n from notes`, // [!code focus]
}); // [!code focus]

export default schema({
  tables: [notes],
  views: [openNotes, noteCounts], // [!code focus]
});
```

<Callout type="error" title="OKM1820">
A tenant view that hides the tenant key is refused.
</Callout>

<Callout type="error" title="OKM1822">
`refresh: "concurrently"` needs a unique index. Any other refresh value is OKM1120.
</Callout>

<Callout type="info" title="Refresh">
`db.views.name.refresh()` runs `REFRESH MATERIALIZED VIEW`, with `CONCURRENTLY` when the view declares it.
</Callout>
