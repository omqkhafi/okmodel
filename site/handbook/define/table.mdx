## Keys

One table has one primary key.

| Place | Result |
| --- | --- |
| `.primaryKey()` | One column. Update omits it. Insert still accepts the value, unless the column is generated or guarded. |
| `primaryKey` | The key when it is more than one column, in column order. |
| a second `.primaryKey()` | Not a composite key. Use `primaryKey`. |
| `unique` | A named constraint. The value is the field list, in column order. |
| `.unique()` | The same constraint for one field. |
| `.unique({ global: "reason" })` | On a tenant table, the tenant key is left out. |
| an empty `global` reason | Refused. |

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.uuid().primaryKey(), // [!code focus]
    title: t.text(),
  },
);

export const memberships = table(
  "memberships",
  {
    organizationId: t.uuid(),
    userId: t.uuid(),
  },
  { primaryKey: ["organizationId", "userId"] }, // [!code focus]
);
```

```ts title="users.ts"
import { table, t } from "okmodel/pg";

export const users = table(
  "users",
  {
    id: t.identity(),
    email: t.text(),
  },
  { unique: { email: ["email"] } }, // [!code focus]
);
```

<Callout type="warning" title="Not a composite">
A second `.primaryKey()` is not a composite key. Use the `primaryKey` option.
</Callout>

<Callout type="warning" title="Tenant unique">
On a tenant table the key is included, unless you pass `{ global: "reason" }`. An empty reason is refused.
</Callout>

`t.id()` is a uuid primary key. `t.identity()` is a generated bigint. [OKID](#okid) is `t.id({ default: okid() })`, stored as `text`.

## Columns

Each field is a data type. The builder name is that type. Postgres is the only database today. A cell is `yes` when that database has the type built in, and `extension` when the schema must list that extension. Another database is another column on the same row. A missing extension declaration is OKM1020. See [extensions](/docs/define/schema#extensions).

An array is [`.array()`](#array) on a scalar. A fixed set of strings on a text column is a [picklist](#picklist). A named Postgres enum is its own type, under [enum](#enum).

| You store | Builder |
| --- | --- |
| a string with no length cap | `t.text()` |
| a string with a maximum length | `t.varchar(n)` |
| a string compared without case | `t.citext()` |
| a tight integer | `t.smallint()` |
| a typical count | `t.integer()` |
| a 64-bit integer | `t.bigint()` |
| a generated integer key | `t.identity()` |
| money, a rate, or any exact quantity | `t.numeric(precision, scale)` |
| a measurement that may round | `t.double()` |
| an instant | `t.timestamptz()` |
| a calendar day | `t.date()` |
| a span | `t.interval()` |
| true or false | `t.boolean()` |
| bytes | `t.bytea()` |
| a document you query | `t.jsonb()` |
| a uuid that is not the primary key | `t.uuid()` |
| a primary key the application mints | `t.id({ default: okid() })` |
| a closed set of labels | `t.enum(name, values)` |

### Text

Postgres stores `text`, `varchar`, and `char` with the same representation. The length is a check, counted in characters. A value up to 126 bytes is 1 byte plus the string. A longer value is 4 bytes plus the string. `char` includes its padding in that string. `citext` uses the same size.

#### Unbounded

`t.text()` is `text`. The TypeScript value is a string. A title, a body, or a name uses it.

```ts title="unbounded.ts"
import { table, t } from "okmodel/pg";

export const people = table("people", {
  id: t.identity(),
  name: t.text(), // [!code focus]
});
```

#### Varchar

`t.varchar(n)` is `varchar(n)`. The TypeScript value is a string. `n` is an integer from 1 to 10485760.

```ts title="varchar.ts"
import { table, t } from "okmodel/pg";

export const people = table("people", {
  id: t.identity(),
  code: t.varchar(16), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
A length outside 1 to 10485760 is refused.
</Callout>

<Callout type="error" title="OKM1210">
A longer value is refused when it is encoded.
</Callout>

#### Char

`t.char(n)` is `char(n)`. The TypeScript value is a string. `n` is an integer from 1 to 10485760. Encode stores the characters you pass.

```ts title="char.ts"
import { table, t } from "okmodel/pg";

export const people = table("people", {
  id: t.identity(),
  region: t.char(2), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
A length outside 1 to 10485760 is refused.
</Callout>

<Callout type="error" title="OKM1210">
A longer value is refused when it is encoded.
</Callout>

#### Citext

`t.citext()` is `citext`. The TypeScript value is a string. Comparison ignores case. The schema lists `citext()` from `okmodel/pg/citext`. See [extensions](/docs/define/schema#extensions).

```ts title="citext.ts"
import { citext } from "okmodel/pg/citext";
import { schema, table, t } from "okmodel/pg";

const people = table("people", {
  id: t.identity(),
  email: t.citext(), // [!code focus]
});

export default schema({
  tables: [people],
  extensions: [citext()], // [!code focus]
});
```

<Callout type="error" title="OKM1020">
`t.citext()` is refused when `extensions` is omitted or empty.
</Callout>

<Callout type="error" title="OKM1810">
`t.citext()` is refused when `extensions` is a list that does not contain `citext`.
</Callout>

### Integers

The value is a whole number inside that range.

#### Smallint

`t.smallint()` is `smallint`. The range is -32768 to 32767. The TypeScript value is a number. Storage is 2 bytes.

```ts title="smallint.ts"
import { table, t } from "okmodel/pg";

export const counts = table("counts", {
  id: t.identity(),
  flag: t.smallint(), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
A value that is not an integer in that range is refused when it is encoded.
</Callout>

#### Integer

`t.integer()` is `integer`. The range is -2147483648 to 2147483647. The TypeScript value is a number. Storage is 4 bytes. This is the usual count.

```ts title="integer.ts"
import { table, t } from "okmodel/pg";

export const counts = table("counts", {
  id: t.identity(),
  total: t.integer(), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
A value that is not an integer in that range is refused when it is encoded.
</Callout>

#### Bigint

`t.bigint()` is `bigint`. The range is -9223372036854775808 to 9223372036854775807. The TypeScript value is a decimal string, so a value past a safe integer stays exact. Storage is 8 bytes. The schema [bigint codec](/docs/define/schema#codecs) is the default when `as` is omitted. A [safe integer](#safe-integer) or a [JavaScript bigint](#javascript-bigint) selects the other modes.

```ts title="bigint.ts"
import { table, t } from "okmodel/pg";

export const counts = table("counts", {
  id: t.identity(),
  sequence: t.bigint(), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
A string that is not a canonical integer is refused when it is encoded. The spelling has no leading zeros, for example `0` or `-12`.
</Callout>

#### Safe integer

`{ as: "number" }` on `t.bigint()` or `t.identity()` makes the TypeScript value a number. It accepts a safe integer only.

```ts title="safe-integer.ts"
import { table, t } from "okmodel/pg";

export const counts = table("counts", {
  id: t.identity(),
  sequence: t.bigint({ as: "number" }), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
A value outside the safe integer range is refused when it is encoded.
</Callout>

#### JavaScript bigint

`{ as: "bigint" }` on `t.bigint()` or `t.identity()` makes the TypeScript value a JavaScript bigint.

```ts title="javascript-bigint.ts"
import { table, t } from "okmodel/pg";

export const counts = table("counts", {
  id: t.identity(),
  sequence: t.bigint({ as: "bigint" }), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
Any other `as` on `t.bigint()` or `t.identity()` is refused.
</Callout>

#### Identity

`t.identity()` is `bigint` `GENERATED ALWAYS AS IDENTITY` and a primary key. Insert and update omit it. The range and the `as` modes match [bigint](#bigint). A generated integer key uses this builder.

```ts title="identity.ts"
import { table, t } from "okmodel/pg";

export const counts = table("counts", {
  id: t.identity(), // [!code focus]
});
```

### Numbers

`t.numeric()` is exact. Money, rates, and quantities use it. Postgres `decimal` is this same type. The size is two bytes for each group of four decimal digits, plus 3 to 8 bytes. Leading and trailing zeros are not stored. The schema [numeric codec](/docs/define/schema#codecs) is the default when `as` is omitted.

#### Unconstrained

`t.numeric()` is `numeric`. The TypeScript value is a string. Omit precision and scale for an unconstrained numeric. The string keeps every digit.

```ts title="unconstrained.ts"
import { table, t } from "okmodel/pg";

export const payments = table("payments", {
  id: t.identity(),
  amount: t.numeric(), // [!code focus]
});
```

#### Precision

`t.numeric(precision)` is `numeric(precision)`. Precision is an integer from 1 to 1000.

```ts title="precision.ts"
import { table, t } from "okmodel/pg";

export const payments = table("payments", {
  id: t.identity(),
  amount: t.numeric(12), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
A precision outside 1 to 1000 is refused.
</Callout>

#### Scale

`t.numeric(precision, scale)` is `numeric(precision, scale)`. Scale is an integer from 0 to that precision.

```ts title="scale.ts"
import { table, t } from "okmodel/pg";

export const payments = table("payments", {
  id: t.identity(),
  amount: t.numeric(12, 2), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
A scale outside 0 to the precision is refused.
</Callout>

#### Number

`{ as: "number" }` makes the TypeScript value a `number`. The SQL type stays the same. It can lose digits past a JavaScript number. Any other `as` is refused.

```ts title="number.ts"
import { table, t } from "okmodel/pg";

export const payments = table("payments", {
  id: t.identity(),
  amount: t.numeric(12, 2, { as: "number" }), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
`as` must be `"string"` or `"number"`.
</Callout>

### Floats

`t.real()` and `t.double()` are binary floating point. A sum of them is not exact. An exact quantity uses [numeric](#numbers). Postgres `float` is this family.

#### Real

`t.real()` is `real`, single precision, about 6 decimal digits. The TypeScript value is a number. Storage is 4 bytes.

```ts title="real.ts"
import { table, t } from "okmodel/pg";

export const samples = table("samples", {
  id: t.identity(),
  reading: t.real(), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
Infinity and NaN are refused when the value is encoded.
</Callout>

#### Double

`t.double()` is `double precision`, about 15 decimal digits. The TypeScript value is a number. Storage is 8 bytes.

```ts title="double.ts"
import { table, t } from "okmodel/pg";

export const samples = table("samples", {
  id: t.identity(),
  reading: t.double(), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
Infinity and NaN are refused when the value is encoded.
</Callout>

### Time

The value is a `Temporal` object. The schema [timestamps codec](/docs/define/schema#codecs) is `"temporal"`. [Fractional seconds](#fractional-seconds) apply to `timestamptz`, `timestamp`, `time`, and `timetz`.

#### Instant

`t.timestamptz()` is `timestamptz`. The TypeScript value is `Temporal.Instant`. Postgres stores it in UTC. Storage is 8 bytes. A created time or an event uses it.

```ts title="instant.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  publishedAt: t.timestamptz(), // [!code focus]
});
```

#### Timestamp

`t.timestamp()` is `timestamp`. The TypeScript value is `Temporal.PlainDateTime`. It stores a civil date and time. Storage is 8 bytes.

```ts title="timestamp.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  editedAt: t.timestamp(), // [!code focus]
});
```

#### Date

`t.date()` is `date`. The TypeScript value is `Temporal.PlainDate`. It stores a calendar day. Storage is 4 bytes.

```ts title="date.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  day: t.date(), // [!code focus]
});
```

#### Time of day

`t.time()` is `time`. The TypeScript value is `Temporal.PlainTime`. It stores a clock time. The zone is its own column. Storage is 8 bytes.

```ts title="time-of-day.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  opens: t.time(), // [!code focus]
});
```

#### Offset

`t.timetz()` is `timetz`. The TypeScript value is `{ time, offset }`. `time` is a `Temporal.PlainTime`. `offset` is `+HH:MM` or `-HH:MM`. A daylight-saving change needs the zone in its own column. Storage is 12 bytes.

```ts title="offset.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  shift: t.timetz(), // [!code focus]
});
```

<Callout type="error" title="OKM1210">
An offset other than `±HH:MM` is refused when the value is encoded.
</Callout>

#### Interval

`t.interval()` is `interval`. The TypeScript value is `Temporal.Duration`. It stores a span. Storage is 16 bytes. `fields` is one of `year`, `month`, `day`, `hour`, `minute`, `second`, `year to month`, `day to hour`, `day to minute`, `day to second`, `hour to minute`, `hour to second`, `minute to second`.

```ts title="interval.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  length: t.interval("day to second"), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
Any other `fields` value is refused.
</Callout>

#### Fractional seconds

`precision` is fractional seconds, an integer from 0 to 6. Omit it for full precision. It applies to `t.timestamptz()`, `t.timestamp()`, `t.time()`, and `t.timetz()`.

```ts title="fractional-seconds.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  editedAt: t.timestamp(0), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
A precision outside 0 to 6 is refused.
</Callout>

### Boolean and binary

| Builder | SQL | TypeScript | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.boolean()` | `boolean` | `boolean` | 1 | yes |
| `t.bytea()` | `bytea` | `Uint8Array` | 1 or 4 + bytes | yes |

`t.boolean()` is true or false. The wire text may be `true`, `false`, `t`, `f`, `1`, or `0`. `t.bytea()` is raw bytes. Up to 126 bytes, the header is 1 byte. A longer value uses a 4-byte header. The wire text is `\x` plus lowercase hex.

```ts title="files.ts"
import { table, t } from "okmodel/pg";

export const files = table("files", {
  id: t.identity(),
  published: t.boolean().default(false), // [!code focus]
  body: t.bytea(), // [!code focus]
});
```

### JSON

| Builder | SQL | TypeScript | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.json()` | `json` | the `T` you name, or `unknown` | 1 or 4 + text | yes |
| `t.jsonb()` | `jsonb` | the `T` you name, or `unknown` | variable | yes |

`T` is the shape you pass. The sample names it. The codec does not check it. `t.jsonb()` is the document you query: Postgres stores it in a binary form and can index it. `t.json()` stores the text, including key order and insignificant space. A bigint inside the value is written as a decimal string. `undefined` and a function are refused.

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  meta: t.json<{ source: string }>(), // [!code focus]
  doc: t.jsonb<{ tags: string[] }>(), // [!code focus]
});
```

### UUID

| Builder | SQL | TypeScript | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.uuid()` | `uuid` | `string` | 16 | yes |
| `t.id()` | `uuid` | `string` | 16 | yes |

`t.uuid()` has no default. The text is 8-4-4-4-12 hexadecimal digits, 128 bits. `t.id()` is a primary key. A bare `t.id()` is `uuid`, 16 bytes. The default is covered in [keys](#keys). An [OKID](#okid) default is `text`, not this row.

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.id(), // [!code focus]
  authorId: t.uuid(), // [!code focus]
});
```

### OKID

`okid` comes from `okmodel/ids`. It is not a Postgres type. `t.id({ default: okid() })` is a primary key of `text` with collation `C`. The client mints one id on insert. The catalog stores no default. Calling `okid()` returns the generator. It does not mint the id at definition time.

A default body is 21 characters on a URL-safe alphabet, so the stored value is 22 bytes. A longer body, or a prefix, follows [text](#text): 1 byte plus the string up to 126 bytes, then 4 bytes plus the string.

| Call | Body | Bytes |
| --- | --- | --- |
| `okid()` | 21 characters | 22 |
| `okid(length)` | `length` characters, from 8 to 128 | 1 + the string |
| `okid({ sortable: true })` | 8 time characters, then random. Length is at least 16. | 1 + the string |
| `okid({ prefix })` | The prefix, then the body. The prefix is at most 32 characters. | 1 + the string |

`length` is the body. The prefix is extra. `sortable` keeps time order under collation `C`. `lowercase`, `uppercase`, `numbers`, and `symbols` default to included. `lookAlikes: false` drops characters that are easy to confuse.

`schema({ defaults: { id: okid() } })` applies to every bare `t.id()`. A column option wins. See [id default](/docs/define/schema#id-default).

```ts title="users.ts"
import { okid } from "okmodel/ids";
import { table, t } from "okmodel/pg";

export const users = table("users", {
  id: t.id({ default: okid({ prefix: "usr_", sortable: true }) }), // [!code focus]
  email: t.text(),
});
```

### Ranges

A range is empty, or a pair of bounds. A null bound is unbounded. `lowerInclusive` and `upperInclusive` choose `[` or `(`.

| Builder | SQL | Bound | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.int4range()` | `int4range` | `number`, the integer range | variable | yes |
| `t.int8range()` | `int8range` | `string`, a bigint | variable | yes |
| `t.numrange()` | `numrange` | `string`, a numeric | variable | yes |
| `t.daterange()` | `daterange` | `Temporal.PlainDate` | variable | yes |
| `t.tstzrange()` | `tstzrange` | `Temporal.Instant` | variable | yes |

There is no `tsrange` builder. An instant range is `t.tstzrange()`.

```ts title="plans.ts"
import { table, t } from "okmodel/pg";

export const plans = table("plans", {
  id: t.identity(),
  scores: t.int4range(), // [!code focus]
  active: t.tstzrange(), // [!code focus]
});
```

A bound is `{ empty: false, lower, upper, lowerInclusive, upperInclusive }`. `{ empty: true }` is the empty range.

### Network

Values are canonical text.

| Builder | SQL | Value | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.inet()` | `inet` | An IPv4 or IPv6 host. A prefix is optional. | 7 or 19 | yes |
| `t.cidr()` | `cidr` | An IPv4 or IPv6 network. A prefix is required. | 7 or 19 | yes |
| `t.macaddr()` | `macaddr` | Six lowercase groups: `aa:bb:cc:dd:ee:ff`. | 6 | yes |
| `t.macaddr8()` | `macaddr8` | Eight lowercase groups. | 8 | yes |

7 bytes is IPv4. 19 bytes is IPv6.

An IPv4 prefix above 32, or any prefix above 128, is refused. `t.cidr()` with no prefix is refused.

```ts title="hosts.ts"
import { table, t } from "okmodel/pg";

export const hosts = table("hosts", {
  id: t.identity(),
  address: t.inet(), // [!code focus]
  block: t.cidr(), // [!code focus]
  mac: t.macaddr(), // [!code focus]
});
```

### Geometry

Built-in plane geometry. A point is `{ x, y }`. A line is `{ a, b, c }` for `ax + by + c = 0`.

| Builder | SQL | TypeScript | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.point()` | `point` | `{ x: number, y: number }` | 16 | yes |
| `t.line()` | `line` | `{ a: number, b: number, c: number }` | 24 | yes |

`box`, `circle`, `lseg`, `path`, and `polygon` have no builder. PostGIS is not these types.

```ts title="places.ts"
import { table, t } from "okmodel/pg";

export const places = table("places", {
  id: t.identity(),
  location: t.point(), // [!code focus]
});
```

### Search

| Builder | SQL | TypeScript | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.tsvector()` | `tsvector` | `string` | variable | yes |
| `t.ltree()` | `ltree` | `string` | variable | extension |

`t.tsvector()` stores the vector text. A generated vector is [`.generated()`](#defaults). `t.ltree()` is labels separated by dots, such as `top.science`. Each label is letters, digits, or underscores. The schema lists `extension("ltree")` from `okmodel/ext`. See [extensions](/docs/define/schema#extensions). There is no `tsquery` builder.

```ts title="notes.ts"
import { extension } from "okmodel/ext";
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.identity(),
  search: t.tsvector(), // [!code focus]
  path: t.ltree(), // [!code focus]
});

export default schema({
  tables: [notes],
  extensions: [extension("ltree")], // [!code focus]
});
```

<Callout type="error" title="OKM1020">
`t.ltree()` with no `ltree` extension on the schema is refused when the catalog is built.
</Callout>

### Named types

| Builder | SQL | TypeScript | Bytes | Postgres |
| --- | --- | --- | --- | --- |
| `t.enum(name, values)` | the enum name | the union of the labels | 4 | yes |
| `t.domain(name, base, check)` | the domain name | the base column's type | the base type | yes |
| `t.custom({ sqlType, encode, decode })` | `sqlType` | the type `encode` accepts | the SQL type | yes |

An [enum](#enum) is its own type. A [picklist](#picklist) stays a string column and adds a CHECK.

`t.domain("email", t.text(), "VALUE LIKE '%@%'")` stores the check as written. The name and the check must be non-empty. An enum cannot be the base. Changing the base type of an existing domain is OKM1020.

`t.custom()` stores a SQL type that has no builder. `sqlType` must be non-empty. `accepts` names the object kinds the codec takes, such as `"Object"`. Omit `accepts` for a scalar. `extension` records an extension dependency. `sqlForm` defaults to `"quote"`.

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  email: t.domain("email", t.text(), "VALUE LIKE '%@%'"), // [!code focus]
  label: t.custom({
    sqlType: "text",
    encode: (value: string) => value,
    decode: (wire: string) => wire,
  }), // [!code focus]
});
```

### Other Postgres types

Postgres has these types. This dialect has no builder under that name. The Postgres cell stays `yes`, because the database has the type. The call is what you write instead.

| Postgres type | Bytes | Call | Postgres |
| --- | --- | --- | --- |
| `smallserial`, `serial`, `bigserial` | 2, 4, 8 | `t.identity()` | yes |
| `money` | 8 | `t.numeric(precision, scale)` | yes |
| `decimal` | variable | `t.numeric()` | yes |
| `tsrange` | variable | `t.tstzrange()` | yes |
| `tsquery` | variable | `t.custom()` with `sqlType: "tsquery"` | yes |
| `bit`, `bit varying` | 1 byte per 8 bits, plus 5 or 8 | `t.custom()` with that SQL type | yes |
| `xml`, `hstore` | variable | `t.custom()` with that SQL type | yes |
| `box`, `lseg` | 32 | `t.custom()` with that SQL type | yes |
| `circle` | 24 | `t.custom()` with that SQL type | yes |
| `path` | 16 + 16 per point | `t.custom()` with that SQL type | yes |
| `polygon` | 40 + 16 per point | `t.custom()` with that SQL type | yes |
| `oid` | 4 | `t.custom()` with that SQL type | yes |
| `pg_lsn` | 8 | `t.custom()` with that SQL type | yes |
| multirange | variable | `t.custom()` with that SQL type | yes |

## Defaults

Omitted, the column is required and not null.

### Nullable

`.nullable()` allows SQL NULL.

```ts title="nullable.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  publishedAt: t.timestamptz().nullable(), // [!code focus]
});
```

### Literal

`.default(literal)` stores the literal in the catalog. A default outside a [picklist](#picklist) is refused.

```ts title="literal.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text().default(""), // [!code focus]
});
```

### Generator

`.default(generator)` is filled on insert. The catalog stores no default.

```ts title="generator.ts"
import { table, t } from "okmodel/pg";
import { uuidv7 } from "okmodel/ids";

export const notes = table("notes", {
  id: t.uuid().default(uuidv7), // [!code focus]
});
```

<Callout type="info" title="Generators">
A generator is `uuidv4`, `uuidv7`, [OKID](#okid) (`okid(...)` from `okmodel/ids`), or any function. `t.id()` and `t.identity()` already carry a default. The schema [id default](/docs/define/schema#id-default) changes what a bare `t.id()` means. A column option wins.
</Callout>

### Null

`.default(null)` is accepted only after `.nullable()`.

```ts title="null-default.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  closedAt: t.timestamptz().nullable().default(null), // [!code focus]
});
```

<Callout type="warning" title="Null">
A null default is accepted only after `.nullable()`.
</Callout>

### SQL

`.defaultSql(expression)` stores the SQL expression as written. An empty expression is refused.

```ts title="default-sql.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  createdAt: t.timestamptz().defaultSql("now()"), // [!code focus]
});
```

### Generated

`.generated(expression)` omits the column from insert and update. `stored` defaults to true. An empty expression is refused.

```ts title="generated.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
  search: t.tsvector().generated("to_tsvector('simple', title)"), // [!code focus]
});
```

## Shape

`.array()` wraps a scalar. `.picklist()` narrows a string column. `t.enum()` creates a Postgres type.

### Array

`.array()` wraps a scalar. `dims` defaults to 1. It is an integer from 1 to 6. `array({ dims: 2 })` is a matrix. There is no second `.array()` call to add a dimension.

```ts title="array.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  tags: t.text().array(), // [!code focus]
  grid: t.integer().array({ dims: 2 }), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
A rank outside 1 to 6 is refused. Calling `.array()` on a column that is already an array is refused.
</Callout>

### Picklist

`.picklist(values)` narrows a string column to a literal union. The catalog gets a CHECK. `{ check: false }` keeps the list in the type and skips that CHECK.

```ts title="picklist.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  status: t.text().picklist(["open", "done"]).default("open"), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
An empty list, an empty value, or a repeated value is refused. A default outside the list is refused.
</Callout>

<Callout type="error" title="OKM1210">
A value outside the list is rejected when it is encoded.
</Callout>

### Enum

`t.enum(name, labels)` creates a Postgres enum. The column type is that name. Labels are stored in that order. The TypeScript type is the union of the labels. A [picklist](#picklist) stays a string column and adds a CHECK. An enum is its own type, so adding a label is a type change.

```ts title="enum.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  status: t.enum("note_status", ["open", "done"]), // [!code focus]
});
```

<Callout type="error" title="OKM1060">
An empty name, an empty list, an empty label, or a repeated label is refused.
</Callout>

<Callout type="error" title="OKM1210">
A value outside the labels is rejected when it is encoded.
</Callout>

<Callout type="error" title="OKM1020">
The same enum name with a different label list is refused.
</Callout>

## Names

The field name is the TypeScript name.

### SQL name

The SQL name is the field name. When the schema sets [casing](/docs/define/schema#casing) to `"snake"`, a camelCase field is stored as snake_case. `.sqlName()` replaces the column name. `sqlName` on the table replaces the table name. Casing does not rewrite a name you set. An empty name is refused.

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text().sqlName("headline"), // [!code focus]
  },
  { sqlName: "note" }, // [!code focus]
);
```

<Callout type="warning" title="Empty">
An empty column or table `sqlName` is refused.
</Callout>

### Previous name

Omitted until you set it. Migrations read the previous SQL name. `.renamedFrom()` is the previous column name. `renamedFrom` on the table is the previous table name. An empty value is refused.

```ts title="posts.ts"
import { table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text().renamedFrom("headline"), // [!code focus]
  },
  { renamedFrom: "posts" }, // [!code focus]
);
```

<Callout type="warning" title="Empty">
An empty column or table `renamedFrom` is refused.
</Callout>

<Callout type="error" title="OKM1020">
A previous name that the last snapshot does not contain is refused. Remove `renamedFrom` once the migration that used it has been applied.
</Callout>

### Comment

`.comment()` stores the text you pass on the column. Omit the call to leave it off. `comment` on the table is stored beside the table. An empty table comment is refused. An empty column comment is stored.

```ts title="labels.ts"
import { table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text().comment("Shown in the list"), // [!code focus]
  },
  { comment: "One row per note" }, // [!code focus]
);
```

<Callout type="warning" title="Empty">
An empty table `comment` is refused. A column comment stores the text you pass, including an empty one. Omit `.comment()` to leave it off.
</Callout>

## Visibility

Three flags. They do not change the SQL type.

### Hidden

`.hidden()` leaves the column out of the default row. A root `select` that names it returns it. An include omits it, including when that `select` names it.

| Call | Result |
| --- | --- |
| `.hidden()` | Out of the default row. `where` and `orderBy` refuse it. |
| `.hidden({ filterable: true })` | `where` and `orderBy` accept it. The default row still omits it. |
| `select` | The root read returns it when the list names it. |
| `include` | Omits it. |
| `filters()` | Refuses it in `allow`, `sort`, and `relations`. |
| `groupBy`, `sum`, `avg`, `min`, `max` | Refuse it. |

```ts title="users.ts"
import { table, t } from "okmodel/pg";

export const users = table("users", {
  id: t.identity(),
  email: t.text(),
  passwordHash: t.text().hidden(), // [!code focus]
  resetCode: t.text().hidden({ filterable: true }), // [!code focus]
});
```

<Callout type="error" title="OKM1120">
`where` and `orderBy` refuse a hidden column unless `filterable` is set. `groupBy`, `sum`, `avg`, `min`, and `max` refuse it either way.
</Callout>

<Callout type="error" title="OKM1123">
`filters()` refuses a hidden field in `allow`, `sort`, or `relations`. `filterable` does not change that. See [filters](#filters).
</Callout>

<Callout type="info" title="Roles">
A hidden column stays out of a reporting role's select unless [roles.columns](/docs/define/config#roles) names it. `filterable` does not add it.
</Callout>

### Sensitive

`.sensitive()` redacts the value in logs, errors, and `inspect()`. The placeholder is `[redacted]`. The stored value is unchanged. A read that selects the column still returns it. The same column can also be [hidden](#hidden).

```ts title="sessions.ts"
import { table, t } from "okmodel/pg";

export const sessions = table("sessions", {
  id: t.identity(),
  token: t.text().sensitive(), // [!code focus]
});
```

<Callout type="info" title="Hash">
The catalog hash does not include `.sensitive()`.
</Callout>

### Guarded

`.guarded()` omits the column from insert and update input. A write that sets it is OKM1190. `{ allow: ["role"] }` opens that field for that call.

| Call | Result |
| --- | --- |
| insert or update sets the field | OKM1190. |
| `{ allow: ["role"] }` | That call may set `role`. |
| a sealed trait field | OKM1190. `allow` does not open it. |
| the tenant key | OKM1190. `allow` does not open it. |

```ts title="accounts.ts"
import { table, t } from "okmodel/pg";

export const accounts = table("accounts", {
  id: t.identity(),
  email: t.text(),
  role: t.text().guarded(), // [!code focus]
});
```

<Callout type="error" title="OKM1190">
Input cannot set a guarded field. Pass `{ allow }` with the field name, or leave it out.
</Callout>

<Callout type="info" title="Filled elsewhere">
A [tenant key](/docs/define/schema#tenancy) is guarded. The client fills it from the scope. [`timestamps()`](/docs/define/schema#traits) and [`archivable()`](#archive) mark their columns guarded and sealed. Input cannot set those columns. `allow` does not open a tenant key or a sealed field.
</Callout>

## Validation

A field's rules live in one place. They run when validation is enabled and the engine has loaded.

### Inline

`.validate()` stores a list of [built-in](#rules) rules on the column, or one [Standard Schema](#standard-schema).

```ts title="notes.ts"
import { table, t } from "okmodel/pg";
import { v } from "okmodel/validate";

export const notes = table("notes", {
  id: t.identity(),
  title: t.varchar(200).validate([v.trim(), v.min(1, "title_required")]), // [!code focus]
  email: t.text().validate([v.lowercase(), v.email("email_invalid")]), // [!code focus]
});
```

### Section

`validate` is the section. Each key is a field, and `$row` is the whole row. Every value is a list of rules. A key that is not a column is refused. A `$row` rule sees the row after the field transforms.

```ts title="rows.ts"
import { table, t } from "okmodel/pg";
import { v } from "okmodel/validate";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    status: t.text().picklist(["draft", "active"]),
    qty: t.integer(),
  },
  {
    validate: { // [!code focus]
      title: [v.min(1, "title_required")], // [!code focus]
      $row: [ // [!code focus]
        v.rule( // [!code focus]
          (row: { readonly status?: string; readonly qty?: number }) => // [!code focus]
            row.status !== "active" || (row.qty ?? 0) > 0, // [!code focus]
          "qty", // [!code focus]
          "qty_required", // [!code focus]
        ), // [!code focus]
      ], // [!code focus]
    }, // [!code focus]
  },
);
```

<Callout type="error" title="OKM1030">
The same field in `.validate()` and in this section is refused. `okm check` reports it.
</Callout>

### Built-in

`v` comes from `okmodel/validate`. Importing it loads the engine.

#### Rules

`trim` and `lowercase` run before the checks. A string is changed. Any other value is left as it is.

| Call | Options | Result |
| --- | --- | --- |
| `v.trim()` | — | Removes leading and trailing whitespace. |
| `v.lowercase()` | — | Lowercases the string. |
| `v.email(key)` | the issue message | Rejects a string that is not an email. |
| `v.min(n, key)` | the minimum, the issue message | A string shorter than `n` characters, or a number below `n`. |
| `v.rule(fn, path, key)` | the predicate, the issue path, the issue message | `false` records `key` at `path`. On a field, `fn` receives that value. |
| `v.onInsert()` | none, or one rule | Limits the following rules, or that one rule, to insert. |
| `v.onUpdate()` | none, or one rule | Limits the following rules, or that one rule, to update. |

```ts title="phases.ts"
import { table, t } from "okmodel/pg";
import { v } from "okmodel/validate";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text().validate([ // [!code focus]
    v.onInsert(), // [!code focus]
    v.min(2, "insert_min"), // [!code focus]
    v.onUpdate(), // [!code focus]
    v.min(4, "update_min"), // [!code focus]
  ]), // [!code focus]
});
```

<Callout type="error" title="OKM1201">
A write that validates without `okmodel/validate` imported is refused. `okm check` reports it.
</Callout>

#### Column checks

The column type adds a check when validation is on. You do not pass a rule for it.

| Column | Option | Issue |
| --- | --- | --- |
| required on insert, or null | not nullable, and the column is written. A default lets insert omit it | `required` |
| `t.varchar(n)`, `t.char(n)` | `n`, counted in characters | `too_long` |
| `.picklist(values)` | the values. `{ check: false }` skips the database CHECK and this check still runs | `picklist` |
| `t.smallint()`, `t.integer()`, `t.bigint()` | that type's range | `integer_range` |
| `t.numeric(precision, scale)` | precision and scale. A bare `t.numeric()` accepts a decimal | `precision` |
| `t.real()`, `t.double()` | a finite number | `precision` |
| `t.uuid()` | a uuid string | `uuid` |
| `t.json()`, `t.jsonb()` | a value JSON can store | `json` |

<Callout type="error" title="OKM1200">
A failed check throws. `issues` lists `{ path, message }` in column order, then `$row`. A hidden or sensitive value stays out of the issue.
</Callout>

### Standard Schema

`.validate()` takes one Standard Schema instead of a list. `~standard.version` is 1, and `~standard.validate` checks the value. Zod, Valibot, and any other library with that shape work. A result of `{ value }` replaces the field. Each issue message is kept, and a path on the issue is added after the field.

In the [section](#section) the schema sits inside that field's list.

```ts title="zod.ts" no-check="zod is installed by the application"
import { z } from "zod";
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text().validate(z.string().trim().min(1)), // [!code focus]
});
```

```ts title="valibot.ts" no-check="valibot is installed by the application"
import * as v from "valibot";
import { table, t } from "okmodel/pg";

export const people = table("people", {
  id: t.identity(),
  email: t.text().validate(v.pipe(v.string(), v.email())), // [!code focus]
});
```

### Flag

`validation` overrides the [schema](/docs/define/schema#validation) for this table.

| Value | Result |
| --- | --- |
| omitted | The table follows the schema. |
| `true` | On for this table. |
| `false` | Off for this table. |
| `{ enabled, onRead, style }` | The same fields as the schema flag. |
| `style` | `"inline"` or `"section"`. |

```ts title="switch.ts"
import { table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  { validation: true }, // [!code focus]
);
```

<Callout type="info" title="One style">
`"inline"` is [`.validate()`](#inline). `"section"` is the [`validate` option](#section). A column rule under `"section"`, or a section rule under `"inline"`, is OKM1030.
</Callout>

## References

`.references()` points a column at another table. The argument is the table name, so the column type does not cycle.

### Target table

The first argument is the target table name. An empty name is refused.

```ts title="target.ts"
import { table, t } from "okmodel/pg";

export const comments = table("comments", {
  id: t.identity(),
  noteId: t.bigint().references("notes"), // [!code focus]
  body: t.text(),
});
```

<Callout type="error" title="OKM1020">
`schema()` checks that the target table exists. A missing table is refused.
</Callout>

### On delete

`onDelete` is `"cascade"`, `"no action"`, `"restrict"`, `"set default"`, or `"set null"`. Anything else is refused. Omitted leaves the clause off. `set null` needs a nullable column.

```ts title="on-delete.ts"
import { table, t } from "okmodel/pg";

export const comments = table("comments", {
  id: t.identity(),
  noteId: t.bigint().references("notes", { onDelete: "cascade" }), // [!code focus]
  body: t.text(),
});
```

### On update

`onUpdate` takes the same actions. Anything else is refused. Omitted leaves the clause off. `set null` needs a nullable column.

```ts title="on-update.ts"
import { table, t } from "okmodel/pg";

export const comments = table("comments", {
  id: t.identity(),
  noteId: t.bigint().nullable().references("notes", { onUpdate: "set null" }), // [!code focus]
  body: t.text(),
});
```

### Target columns

`columns` names the target column when it is not the primary key. The list needs one name. An empty name is refused. Omitted, `schema()` uses that table's primary key.

```ts title="target-columns.ts"
import { table, t } from "okmodel/pg";

export const comments = table("comments", {
  id: t.identity(),
  authorId: t.uuid().references("users", { columns: ["id"] }), // [!code focus]
  body: t.text(),
});
```

<Callout type="error" title="OKM1021">
A missing column, no primary key, or more than one name is refused.
</Callout>

<Callout type="error" title="OKM1022">
The column type and the target type must match.
</Callout>

<Callout type="info" title="Both">
A [relation](#relations) is the name you query. The reference is the foreign key. You want both: the column stores the key, and `one` or `many` names the edge.
</Callout>

## Relations

`relations` names edges. `schema()` resolves the foreign key.

<Callout type="error" title="OKM1020">
A missing table is refused. For a join, that includes the join table.
</Callout>

### To-one

`one(table, field)` is to-one. `field` is the local foreign key when this table has several keys to that table.

```ts title="to-one.ts"
import { one, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    authorId: t.bigint().references("users"),
    title: t.text(),
  },
  { relations: { author: one("users") } }, // [!code focus]
);
```

<Callout type="error" title="OKM1021">
An ambiguous key is refused. Pass `field` when more than one key points at that table.
</Callout>

### To-many

`many(table, field)` is to-many. `field` is the foreign key on the other table when that table has several keys here.

```ts title="to-many.ts"
import { many, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  { id: t.identity(), title: t.text() },
  { relations: { comments: many("comments") } }, // [!code focus]
);
```

<Callout type="error" title="OKM1021">
An ambiguous key is refused. Pass `field` when more than one key points here.
</Callout>

### Join table

`manyThrough(table, { through })` is to-many through a join table. The join table has one foreign key to this table and one to the related table. Name `from` and `to` when a table has more than one.

```ts title="through.ts"
import { manyThrough, table, t } from "okmodel/pg";

export const users = table(
  "users",
  { id: t.identity(), name: t.text() },
  { relations: { teams: manyThrough("teams", { through: "memberships" }) } }, // [!code focus]
);
```

<Callout type="error" title="OKM1021">
An ambiguous key is refused. Pass `from` and `to` when the join table has more than one foreign key to an end. The same field for both ends is refused.
</Callout>


### One relation, several tables

A comment that points at a task or a list is `morph("commentable", ["tasks", "lists"])` on the comment, next to `commentableType` and `commentableId`. Use it when one table points at a closed list of others and you want the matching row back. Include returns the task or the list, or null when the row is missing or the stored type is outside the list. Each target declares `morphMany("comments", "commentable")` for the comments that point at it. That reverse many takes a limit, an order, and `has`, `none`, and `every`. `morphTo("commentable", "tasks", id)` sets the type and the id together. Setting one without the other is refused. A type outside the list is refused. `has`, `none`, and `every` on the morph itself are refused, and so are `select`, `where`, `orderBy`, and `limit` on that include. See [known limits](/docs/known-limits).

```ts title="morph.ts"
import { connect } from "okmodel/pg/postgresjs";
import { morph, morphMany, morphTo, schema, table, t } from "okmodel/pg";

const tasks = table(
  "tasks",
  { id: t.text().primaryKey(), title: t.text() },
  { relations: { comments: morphMany("comments", "commentable") } },
);
const lists = table(
  "lists",
  { id: t.text().primaryKey(), name: t.text() },
  { relations: { comments: morphMany("comments", "commentable") } },
);
const comments = table(
  "comments",
  {
    id: t.text().primaryKey(),
    body: t.text(),
    commentableType: t.text(),
    commentableId: t.text(),
  },
  { relations: { commentable: morph("commentable", ["tasks", "lists"]) } },
);
const app = schema({ tables: [tasks, lists, comments] });

export async function attach(url: string, taskId: string): Promise<void> {
  await using db = connect(url, { schema: app });
  await db.comments.insert({
    id: "c1",
    body: "ship it",
    ...morphTo("commentable", "tasks", taskId),
  });
  const rows = await db.comments.find({ limit: 20, include: { commentable: true } });
  if (rows.length < 0) throw new Error("the morph did not run");
}
```

## Indexes

`indexes` receives column handles and returns an array of index calls.

<Callout type="info" title="SQL name">
The handle's `name` is the SQL name `schema()` will store. A [casing](/docs/define/schema#casing) of `"snake"` has already been applied by the time the catalog is written.
</Callout>

### Index

`index(...)` is one index, in column order. It needs a column.

```ts title="index.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  { indexes: (columns) => [index(columns.title)] }, // [!code focus]
);
```

### Unique

`.unique()` marks that index unique.

```ts title="unique-index.ts"
import { index, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    published: t.boolean().default(false),
  },
  { indexes: (columns) => [index(columns.published, columns.title).unique()] }, // [!code focus]
);
```

<Callout type="warning" title="Not a constraint">
A unique constraint and a unique index are different objects. A constraint belongs on [keys](#keys). An index belongs here.
</Callout>

## Checks

A check is named SQL. The function receives column handles. `sql` interpolates a handle as its SQL name. This is not a query builder. The database normalises the expression later.

| Field | Required | Role |
| --- | --- | --- |
| name | yes | The constraint name. |
| function | yes | Receives column handles and returns the expression. |

```ts title="notes.ts"
import { sql, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  {
    checks: {
      title_present: (columns) => sql`${columns.title} <> ''`, // [!code focus]
    },
  },
);
```

<Callout type="info" title="SQL name">
A handle becomes the SQL name `schema()` stores, including [casing](/docs/define/schema#casing).
</Callout>

## Filters

`filters()` allowlists what a caller may send. `parse` loads the parser on first use.

<Callout type="error" title="OKM1123">
A hidden field in `allow`, `sort`, or `relations` is refused here. `filterable` does not change that. See [hidden](#hidden).
</Callout>

<Callout type="error" title="OKM1121">
`parse` expects an object of fields.
</Callout>

### Allow

`allow` maps a field to operators. An operator outside the list is not assignable. A scalar is `eq` when that field allows `eq`. Several fields, or several operators on one field, are combined.

#### Accepted

| Operator | Value |
| --- | --- |
| `eq` | A scalar, or an object. |
| `in`, `inList` | An array. `in` in the list also accepts `inList`. |
| `notIn` | An array. |
| `lt`, `lte`, `gt`, `gte` | The bound. |
| `between` | `[from, to]`. |
| `startsWith`, `endsWith`, `like`, `ilike` | A string. |
| `contains` | The value. |
| `not` | A scalar or null. |
| `containedBy`, `overlaps` | The value. |
| `hasKey` | A string. |
| `hasAnyKey` | An array of strings. |

```ts title="allow.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
  status: t.text(),
});

export const noteFilters = notes.filters({
  allow: { title: ["eq", "startsWith"], status: ["eq", "in"] }, // [!code focus]
});
```

<Callout type="error" title="OKM1120">
An operator the field does not list is refused. So is a value that operator does not take.
</Callout>

#### Refused

`path`, `matches`, `similar`, `wordSimilar`, boolean trees, relation quantifiers, and write operators. A caller cannot name them in `allow`.

### Sort

`sort` names the fields a caller may sort. The request key `sort` is one of those names. `parse` orders that field ascending.

```ts title="sort.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export const noteFilters = notes.filters({
  allow: { title: ["eq"] },
  sort: ["title"], // [!code focus]
});
```

### Related fields

`relations` maps a [relation](#relations) name to fields of that table. `parse` turns `{ author: { name: { startsWith: "a" } } }` into `has`. Those fields accept the [operators](#accepted) above. A name in `allow` is the column when that name is also a relation.

```ts title="related.ts"
import { one, table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    authorId: t.bigint().references("users"),
  },
  { relations: { author: one("users") } },
);

export const noteFilters = notes.filters({
  relations: { author: ["name"] }, // [!code focus]
});
```

<Callout type="error" title="OKM1123">
A field that is not in that relation's list is refused.
</Callout>

## Traits

Schema [traits](/docs/define/schema#traits) are the defaults. A table adds its own, or opts out.

### Added

`traits` is a list, added on top of those defaults. A value that is not a list is refused.

```ts title="added.ts"
import { table, t } from "okmodel/pg";
import { archivable } from "okmodel/traits";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  { traits: [archivable()] }, // [!code focus]
);
```

### Omit defaults

`omitDefaults` is the reason. It drops the schema list and keeps this table's `traits`.

```ts title="omit-defaults.ts"
import { table, t } from "okmodel/pg";

export const sessions = table(
  "sessions",
  {
    id: t.identity(),
    token: t.text(),
  },
  { omitDefaults: "sessions are not stamped" }, // [!code focus]
);
```

<Callout type="warning" title="Reason">
`omitDefaults` needs a reason. An empty reason is rejected when the schema is built.
</Callout>

### Built-in traits

`timestamps` and `archivable` come from `okmodel/traits`.

| Trait | Columns | Options |
| --- | --- | --- |
| `timestamps()` | `createdAt`, `updatedAt` | `{ enforce: "trigger" }` |
| `archivable()` | `archivedAt`, `archiveId` | `cascade`, `strategy` |

<Callout type="error" title="OKM1012">
A column the table already has, or that another trait adds, is refused.
</Callout>

#### Timestamps

`timestamps()` adds `createdAt` and `updatedAt`. Both are `timestamptz`, not null, default `now()`, guarded and sealed. Insert leaves them to the default. Update sets `updatedAt` and leaves `createdAt`. `{ enforce: "trigger" }` also writes `updatedAt` in the database. Any other option is refused.

```ts title="timestamps.ts"
import { table, t } from "okmodel/pg";
import { timestamps } from "okmodel/traits";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  { traits: [timestamps({ enforce: "trigger" })] }, // [!code focus]
);
```

#### Archive

`archivable()` adds `archivedAt` and `archiveId`. `archivedAt` is `timestamptz` and nullable. `archiveId` is `uuid` and nullable. Both are guarded and sealed. Uniques on that table become partial. `cascade` names child tables archived and restored with the row. An empty name is refused. `strategy: "column"` keeps archived rows in the table.

```ts title="archive.ts"
import { table, t } from "okmodel/pg";
import { archivable } from "okmodel/traits";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
  },
  { traits: [archivable({ cascade: ["comments"] })] }, // [!code focus]
);
```

<Callout type="error" title="OKM1061">
`strategy: "table"` is not available yet.
</Callout>

### Versioned and sortable

`versioned()` adds `version`. An update passes the version you read, and the write bumps it. Use it when two editors must not overwrite each other. A stale write is a conflict and changes nothing. A miss stays `{ count: 0 }`. `inc` and the other atomic writes still bump `version`. `delete`, `archive`, and `restore` do not check it. An upsert and `.all()` are refused. `sortable("laneId")` adds `position`. New rows go at the end of that lane. `move` places a row before or after another in the same lane. A move is O(n) for that lane. `find` and `page` order by `position` when you omit `orderBy`. Changing the lane in the same update is refused. `via()` on this table is refused. A delete leaves a gap until the next `move`. See [known limits](/docs/known-limits).

```ts title="traits.ts"
import { connect } from "okmodel/pg/postgresjs";
import { schema, table, t } from "okmodel/pg";
import { sortable, versioned } from "okmodel/traits";

const tasks = table(
  "tasks",
  { id: t.text().primaryKey(), title: t.text(), laneId: t.text() },
  { traits: [versioned(), sortable("laneId")] },
);
const app = schema({ tables: [tasks] });

export async function edit(url: string, id: string, otherId: string): Promise<void> {
  await using db = connect(url, { schema: app });
  const current = await db.tasks.one({ where: { id } });
  if (current === null) return;
  const saved = await db.tasks.update({
    where: { id },
    set: { title: "next" },
    version: current.version,
  });
  const placed = await db.tasks.move(id, { before: otherId });
  if (saved.count < 0 || placed.position < 0) throw new Error("the write did not run");
}
```

## Tenancy

Schema [tenancy](/docs/define/schema#tenancy) adds the key to every table. `global` and `via` come from `okmodel/tenancy`. Anything else is refused.

### Schema key

Omitted, the schema key is added.

```ts title="schema-key.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  email: t.text().unique({ global: "login email" }), // [!code focus]
  title: t.text(),
});
```

<Callout type="info" title="Unique">
A unique on a tenant table includes the key unless `.unique({ global: "reason" })` says otherwise.
</Callout>

### Global

`global("reason")` leaves the tenant column off this table. The reason is required.

```ts title="global.ts"
import { table, t } from "okmodel/pg";
import { global } from "okmodel/tenancy";

export const plans = table(
  "plans",
  { id: t.identity(), code: t.text() },
  { tenancy: global("plans are shared") }, // [!code focus]
);
```

<Callout type="error" title="OKM1705">
A global table that references a tenant table is refused.
</Callout>

### Path

`via("a.b")` isolates through relations. Steps are separated by `.`, up to three. An empty path is refused.

```ts title="path.ts"
import { table, t } from "okmodel/pg";
import { via } from "okmodel/tenancy";

export const tasks = table(
  "tasks",
  {
    id: t.identity(),
    projectId: t.uuid().references("projects"),
    title: t.text(),
  },
  { tenancy: via("project.organization") }, // [!code focus]
);
```

<Callout type="error" title="OKM1705">
A path that does not end at a tenant table, a missing relation, a cycle, or more than three steps is refused.
</Callout>

## Presets

A preset is a named refinement you call on the table: `notes.pending()`. It receives a builder and returns that builder.

| Rule | Result |
| --- | --- |
| `where` | The only method. It adds a predicate. It cannot remove or replace one. |
| a client method, or `find`, `insert`, `then` | OKM1040. The same list is a type error on the option. |

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table(
  "notes",
  {
    id: t.identity(),
    title: t.text(),
    status: t.text(),
  },
  {
    presets: {
      pending: (q) => q.where({ status: "pending" }), // [!code focus]
    },
  },
);
```

<Callout type="error" title="OKM1040">
A name that is a client method, or a reserved name such as `find`, `insert`, or `then`, is refused. The same list is a type error on the option.
</Callout>

<Callout type="info" title="Around the preset">
The tenant predicate and an active set are not in the builder. The planner puts them around the preset.
</Callout>

<Callout type="info" title="Trait names">
A trait can add presets too. The table's own names are applied first.
</Callout>

## Reference rows

`reference` declares rows the application needs.

<Callout type="info" title="Insert only">
Apply inserts a row when its key is missing. It does not update or delete. The rows stay on the schema. They are not a diff in the catalog.
</Callout>

| Field | Required | Values |
| --- | --- | --- |
| `key` | yes | One column name or several, in constraint order. |
| `rows` | yes | Each value is a string, a number, a boolean, or null. |

```ts title="statuses.ts"
import { table, t } from "okmodel/pg";

export const statuses = table(
  "statuses",
  {
    code: t.text().primaryKey(),
    label: t.text(),
  },
  {
    reference: {
      key: "code", // [!code focus]
      rows: [
        { code: "open", label: "Open" },
        { code: "done", label: "Done" },
      ],
    },
  },
);
```
