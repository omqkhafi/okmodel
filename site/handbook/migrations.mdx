You change the schema. `okm generate` writes the SQL. `okm migrate apply` runs the files that this database has not applied yet.

```sh
bunx okm build
bunx okm generate init
bunx okm migrate apply
```

`init` is the first migration. Later changes are `bunx okm generate`.

## The files check themselves

`okm migrate check` replays the history on a throwaway database. It fails if the files do not match the schema, or if the linter reports an error. Do not point it at a database you need to keep.

The [linter](/docs/reference/linter) reads the plan and does not connect. [Check](/docs/reference/check) is the command for a pipeline. A [backfill](/docs/reference/backfill) is a step inside a migration file. There is no separate backfill command.

[Production](/docs/reference/production) is how a target is marked protected, and how connect refuses a database whose catalog is missing.

## Names, and an upgrade from 0.5.1

A unique or a foreign key is named from every SQL column, after `casing` and `sqlName`. A database created on 0.5.1 still has the older names. `connect()` is OKM1520 until `okm migrate apply` runs once. That migration is `RENAME CONSTRAINT`. It does not drop the table or the row. A protected target needs `--allow-protected` on that invocation. The next plan is empty.
