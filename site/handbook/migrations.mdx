You change the schema. `okm generate` writes the SQL. `okm migrate apply` runs the files that this database has not applied yet.

```sh
bunx okm build
bunx okm generate init
bunx okm migrate apply
```

`init` is the first migration. Later changes are `bunx okm generate`.

## The files check themselves

`okm migrate check` replays the history in a scratch schema inside one transaction and rolls that transaction back. It does not edit system catalogs or real ACLs. Lint runs first. Transaction control in a step is refused. A hand-written `public.t` does not change the real table. It fails if the files do not match the schema, or if the linter reports an error. Do not point it at a database you need to keep. A postgres.js `stream()` can end early when the connection drops; node-postgres and Bun.sql report that as unavailable.

The [linter](/docs/reference/linter) reads the plan and does not connect. [Check](/docs/reference/check) is the command for a pipeline. A [backfill](/docs/reference/backfill) is a step inside a migration file. There is no separate backfill command.

[Production](/docs/reference/production) is how a target is marked protected, and how connect refuses a database whose catalog is missing.

## Names, and an upgrade from 0.5.1

A unique or a foreign key is named from every SQL column, after `casing` and `sqlName`. A database created on 0.5.1 still has the older names. `connect()` is OKM1520 until `okm migrate apply` runs once. That migration is `RENAME CONSTRAINT`. It does not drop the table or the row. A protected target needs `--allow-protected` on that invocation. The next plan is empty. This ships in 0.6.0. The stored hash from 0.5.1 stays until that rename is applied.

## Windows

Git on Windows checks SQL out as CRLF unless `.gitattributes` says otherwise. `okm` reads those files as LF, including a `\r\n` inside a SQL string literal, so apply, check, and the linter see the same steps. A file that still parses to no steps, and does not say `-- no steps`, fails instead of printing `nothing to apply`.

`okm generate init` writes this `.gitattributes` when the project does not have one. An existing file is not edited.

```text
migrations/*.sql text eol=lf
*.catalog.json text eol=lf
.okm/** text eol=lf
```

Save the files as UTF-8. A BOM is stripped. UTF-16 is refused. Point `schema`, `migrations`, and `out` at an absolute path or at `..` when the project is not the process directory. Use `postgres://localhost:5432/app`. A named pipe is not a connection string here.

`okmodel.config.ts` needs Node.js 22.18 or newer, because that is when Node strips types without a flag. `bunx okm` runs on Node. `bun --bun okm` runs on Bun.
