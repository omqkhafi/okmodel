The calls below use one table and one connection. `insert` returns the row. `find` returns a list, so it takes a `limit`. `one` returns that row, or null when none matches. More than one match throws.

```ts title="index.ts"
import { connect } from "okmodel/pg/postgresjs";
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", { id: t.identity(), title: t.text() });
const app = schema({ tables: [notes] });

export async function read(url: string): Promise<void> {
  await using db = connect(url, { schema: app });
  const inserted = await db.notes.insert({ title: "hello" });
  const found = await db.notes.find({ where: { id: inserted.id }, limit: 5 });
  const single = await db.notes.one({ where: { id: inserted.id } });
  if (found.length !== 1 || single === null || single.title !== "hello") {
    throw new Error("the row did not come back");
  }
}
```

`where` is the columns of the table. A field you did not declare is not a valid filter. A request from the client goes through `filters({ allow, sort, relations })`. `parse` applies `eq`, `in`, `notIn`, `lt`, `lte`, `gt`, `gte`, `between`, `startsWith`, `endsWith`, `contains`, `like`, `ilike`, `not`, `containedBy`, `overlaps`, `hasKey`, and `hasAnyKey`. A listed relation becomes `has`. A hidden field is refused.

[Safety](/docs/model/safety) covers fields that are stored but not returned, and writes that need an explicit allow.

## The first rows of a relation

A to-many include takes `limit`. That limit is the first N related rows of each parent, not N rows in total. The read is still one statement: a lateral join. Pass `orderBy` for the order inside that parent. The primary key follows it, ascending, for any key you did not name, so two rows with the same score stay in the same order. Leave `orderBy` out and the related rows follow the primary key. A parent with no related rows comes back with an empty list. `select`, a nested include, and a preset still apply. `matches` and `relevance` work inside the include. `search` stays on `find` and `count`.

```ts title="include.ts"
import { connect } from "okmodel/pg/postgresjs";
import { many, schema, table, t } from "okmodel/pg";

const posts = table(
  "posts",
  { id: t.identity(), title: t.text() },
  { relations: { comments: many("comments", "postId") } },
);
const comments = table("comments", {
  id: t.identity(),
  postId: t.bigint().references("posts"),
  body: t.text(),
  score: t.integer(),
});
const app = schema({ tables: [posts, comments] });

export async function read(url: string): Promise<void> {
  await using db = connect(url, { schema: app });
  const latest = await db.posts.find({
    limit: 20,
    include: {
      comments: { orderBy: { score: "desc" }, limit: 3, select: ["id", "body"] },
    },
  });
  if (latest.length < 0) throw new Error("the include did not run");
}
```

## Number the rows

`rowNumber`, `rank`, `denseRank`, and `runningTotal` go in `select` on `find` or `one`. `partitionBy` is the group. Leave it out to number the whole result. `orderBy` is the order inside the group, and `as` is the name on the row. `rowNumber` and `runningTotal` append the primary key, so a tie stays stable. `rank` and `denseRank` leave a tie tied: two equal amounts share a rank, and `rank` skips the next number. A running total uses the column's type. An integer is a number. A `numeric` column is the decimal string. `page()` refuses a window when the call runs.

```ts title="windows.ts"
import { connect } from "okmodel/pg/postgresjs";
import { rank, rowNumber, runningTotal, schema, table, t } from "okmodel/pg";

const tasks = table("tasks", {
  id: t.identity(),
  status: t.text(),
  amount: t.integer(),
});
const app = schema({ tables: [tasks] });

export async function read(url: string): Promise<void> {
  await using db = connect(url, { schema: app });
  const numbered = await db.tasks.find({
    select: [
      "id",
      "status",
      rowNumber({ partitionBy: ["status"], orderBy: { amount: "desc" }, as: "n" }),
      rank({ partitionBy: ["status"], orderBy: { amount: "desc" }, as: "r" }),
      runningTotal("amount", { partitionBy: ["status"], orderBy: { id: "asc" }, as: "soFar" }),
    ],
    limit: 20,
  });
  if (numbered.length < 0 || numbered[0]?.n === undefined) {
    throw new Error("the window did not run");
  }
}
```

## Search your text

Pass the words. When the table has one column built for search, that is the column. The closest rows come back first, then the primary key, so the order stays put. `count({ search })` uses the same match and does not order. An `orderBy` you pass replaces the ranking. `where`, `select`, `include`, and a preset still apply. `page()` does not take `search` in this version: use `find({ search, limit })` for one ranked list.

```ts title="search.ts"
import { connect } from "okmodel/pg/postgresjs";
import { matches, relevance, schema, table, t } from "okmodel/pg";

const pages = table(
  "pages",
  { id: t.identity(), title: t.text(), body: t.tsvector() },
  { presets: { titled: (q, title: string) => q.where({ title }) } },
);
const app = schema({ tables: [pages] });

function deployNotes(title: string) {
  return { search: "deploy rollback", where: { title }, limit: 20 };
}

export async function read(url: string): Promise<void> {
  await using db = connect(url, { schema: app });
  const ranked = await db.pages.find({ search: "deploy rollback", limit: 20 });
  const phrase = await db.pages.find({
    search: { for: "deploy rollback", match: "phrase", language: "english" },
    limit: 20,
  });
  const scoped = await db.pages.titled("ship").find({ search: "deploy", limit: 20 });
  const named = await db.pages.find(deployNotes("ship"));
  const same = await db.pages.find({
    where: { body: matches("deploy rollback", { match: "phrase", language: "english" }) },
    orderBy: {
      body: relevance("deploy rollback", { match: "phrase", language: "english" }),
      id: "asc",
    },
    limit: 20,
  });
  if (ranked.length + phrase.length + scoped.length + named.length + same.length < 0) {
    throw new Error("the search did not run");
  }
}
```

`match` is `natural` (the default, the same kind of text a search box accepts), `all-words`, `phrase`, or `advanced`. `advanced` is the database's own query syntax. `language` is a text search language such as `english`. Leave it out to use the database default. When the table has more than one search column, name it: `search: { for: "deploy", in: "body" }`. The error lists the names when you do not.

A named query is a preset, or a function that returns the `find` options, as `titled` and `deployNotes` do above. There is no separate call for one.

## How it works

The column is a `tsvector`: the document Postgres matches, not the plain text. You fill it when you write, often with `to_tsvector` in `.generated(...)`. `natural` compiles to `websearch_to_tsquery`. `all-words` is `plainto_tsquery`, `phrase` is `phraseto_tsquery`, and `advanced` is `to_tsquery`. Ranking is `ts_rank`, highest first. `find({ search })` emits that same match and that same rank. A highlighted snippet, a search of a plain text column, a helper that writes the `to_tsvector` expression, and a ranked `page()` are not in this version.
