`lintFrom` is the first migration id that `okm migrate check` lints. Files before it, in apply order, are the adoption baseline. The id itself is linted.

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `lintFrom` | no | every file | First id `okm migrate check` lints. |

## lintFrom

Apply order is the sorted `*.sql` names. Files before the id are still read, so a later file is linted against the catalog they left. An id that is not a migration is refused: `lintFrom <id> is not a migration id.`

```ts title="okmodel.config.ts"
import { defineConfig } from "okmodel/migrate";

export default defineConfig({
  schema: "./schema.ts",
  database: process.env.DATABASE_URL!,
  lintFrom: "20260301000000_init", // [!code focus]
});
```

## What check lints

| Case | Result |
| --- | --- |
| `lintFrom` omitted | Every migration file. |
| A migration id | That file and every file after it. |
| Files before that id | Not linted. An old drop does not fail check. |
| The id itself | Linted. |
| An id that is not a migration | Refused. |
| An error finding on a linted file | OKM1510. |

## Apply

`okm migrate apply` does not read `lintFrom`. It lints every migration that still has a step to run, and it does that before any DDL. A database with no `okm_history` lints every file.
