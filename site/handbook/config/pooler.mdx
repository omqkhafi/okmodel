Migration commands refuse a pooler host. Apply holds an advisory lock on one session. A transaction-mode pooler can hand the next statement a different backend.

| Field | Required | Default | Role |
| --- | --- | --- | --- |
| `allowPooler` | no | `false` | Skip the pooler refusal. |

## allowPooler

Set it only when the URL is a pooler you mean to use. `--allow-pooler` does the same for that invocation. Either one is enough.

```ts title="okmodel.config.ts"
import { defineConfig } from "okmodel/migrate";

export default defineConfig({
  schema: "./schema.ts",
  database: process.env.DATABASE_URL!,
  allowPooler: true, // [!code focus]
});
```

```sh
okm migrate apply --allow-pooler # [!code focus]
```

## The host

The host is lowercased before this check. The message is `Refusing pooler host <host>. Apply needs a direct connection.`

| Shape | Result |
| --- | --- |
| Host contains `pooler` | Refused. |
| Host contains `pgbouncer` | Refused. |
| Port `6543` or `6432` | Refused. |
| Query `pgbouncer=true` | Refused. |
| A direct `postgres://` URL | Allowed. The flag is not required. |

## Commands

| Command | Pooler host |
| --- | --- |
| `okm migrate apply`, `okm migrate check`, `okm push`, `okm seed` | Refused until the opt-in. |
| `okm check`, when it compares one database | Refused until the opt-in. |
| `provision()` | Refused until `allowPooler` in the config. The call takes no flag. |
| `okm migrate status`, `okm migrate plan`, `okm doctor`, `okm ext` | Allowed. |
| `connect()` | Allowed. |

## A changing session

When the host check passes, two reads of `pg_backend_pid()` must return the same pid. A change is OKM1854. `allowPooler` and `--allow-pooler` skip that probe.
