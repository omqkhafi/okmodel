Define the table, then the schema, then point `okmodel.config.ts` at that file. Build, generate, and apply read the config. The insert omits `id`, and the row that comes back carries it as a string.

| Step | Command | Connects | Result |
| --- | --- | --- | --- |
| Define table | `table()` | no | `notes`. `id` is the primary key. |
| Define schema | `schema()` | no | One catalog, default-exported. |
| Define config | `okmodel.config.ts` | no | `schema` is `./schema.ts`. |
| Build | `okm build` | no | Writes `.okm/`. |
| Generate | `okm generate init` | no | `migrations/0001_init.sql` and its catalog. |
| Apply | `okm migrate apply` | yes | An empty database installs the head snapshot. |
| Read it back | `insert`, then `find` | yes | The row. `id` is a string. |

## Define table

`table()` stores the columns. `t.identity()` is a `bigint`, generated always. `.primaryKey()` makes `id` the primary key. Insert omits it. The default codec is a string. A key of more than one column is the `primaryKey` option. [Keys](/docs/table/keys).

```ts title="schema.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity().primaryKey(), // [!code focus]
  title: t.text(),
});
```

## Define schema

`schema()` compiles the tables into one catalog. The module default-exports that result.

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity().primaryKey(),
  title: t.text(),
});

export default schema({ tables: [notes] }); // [!code focus]
```

## Define config

`okm build`, `okm generate`, and `okm migrate apply` load `okmodel.config.ts` from the project directory. The file default-exports `defineConfig`. A file that does not is refused. A module that is not a `schema()` is refused: `<path> must export a schema().` `schema` is the file from the previous step. `database` is the direct URL apply connects to. Build and generate do not connect. Other options are on [Config](/docs/config/file).

```ts title="okmodel.config.ts"
import { defineConfig } from "okmodel/migrate";

export default defineConfig({
  schema: "./schema.ts", // [!code focus]
  database: process.env.DATABASE_URL!,
});
```

## Build

`okm build` checks the schema and writes `.okm/`. It does not connect.

```sh
bunx okm build
```

## Generate

`okm generate init` writes `migrations/0001_init.sql` and `migrations/0001_init.catalog.json`. The name is the part after the number. If the project has no `.gitattributes`, generate writes one. Git then stores the migration SQL, the catalog JSON, and `.okm` with Unix line endings, so a Windows checkout does not rewrite them. An existing `.gitattributes` is left as it is. A later schema change is `okm generate`. With no name, that file is called `migration`. A name is letters, digits, `_`, or `-`. No schema change prints `no changes` and writes no SQL.

```sh
bunx okm generate init
```

## Apply

`okm migrate apply` connects. An empty database installs the head snapshot, which creates the tables. It does not replay the files. A database that already has history runs only the SQL not yet in `okm_history`. A database that is not empty and has no history is OKM1851.

```sh
bunx okm migrate apply
```

`bunx okm` runs with Node. `bun --bun okm` uses the Bun runtime.

## Read it back

`connect` takes the direct URL and the schema. The process keeps `db`. Direct asserts the URL. Safe refuses an empty `DATABASE_URL`.

<Tabs items={["Direct", "Safe"]}>

<Tab value="Direct">

```ts title="db.ts"
import { connect } from "okmodel/pg/postgresjs";

import schema from "./schema.ts";

export const db = connect(process.env.DATABASE_URL!, { schema }); // [!code focus]
```

</Tab>

<Tab value="Safe">

```ts title="db.ts"
import { connect } from "okmodel/pg/postgresjs";

import schema from "./schema.ts";

const url = process.env.DATABASE_URL;
if (url === undefined || url.length === 0) throw new Error("DATABASE_URL is not set"); // [!code focus]

export const db = connect(url, { schema });
```

</Tab>

</Tabs>

Insert passes `title` and omits `id`. The row that comes back has `id`.

```ts title="notes.ts"
import { db } from "./db.ts";

export async function createNote(title: string) {
  const note = await db.notes.insert({ title }); // [!code focus]
  return note;
}
```

`find` returns a list. `limit: 1` asks for one row. Omit the limit and the call is OKM1101. The row is `[0]`, or `undefined` when nothing matched. `.all(reason)` is how you ask for the full set.

```ts title="notes.ts"
import { db } from "./db.ts";

export async function readNote(id: string) {
  const found = await db.notes.find({ where: { id }, limit: 1 }); // [!code focus]
  return found[0];
}
```

Put those two calls in the server you already run.
