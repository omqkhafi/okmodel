One table, three commands, then a client. The insert omits the id. The row that comes back carries it, as a string.

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text(),
});

export default schema({ tables: [notes] });
```

```sh
bunx okm build
bunx okm generate init
bunx okm migrate apply
```

`okm build` checks the schema and writes `.okm/`. It does not connect.

`okm generate init` writes the first SQL migration and names it `init`. Read that file. The next schema change is `okm generate`.

`okm migrate apply` runs the SQL this database has not applied yet. An empty database gets the tables created.

The `okm` command runs with Node, even under `bunx`. Use `bun --bun okm` when the command must use the Bun runtime.

```ts title="db.ts"
import { connect } from "okmodel/pg/postgresjs";
```

<Tab value="Cloudflare Workers">

```ts title="src/index.ts"
import { db } from "../db.ts";

export default {
  async fetch(request: Request): Promise<Response> {
    const url = new URL(request.url);
    if (request.method === "POST" && url.pathname === "/notes") {
      const body = (await request.json()) as { title: string };
      const note = await db.notes.insert({ title: body.title });
      return Response.json(note, { status: 201 });
    }
    const id = /^\/notes\/([^/]+)$/.exec(url.pathname)?.[1];
    if (request.method === "GET" && id !== undefined) {
      const found = await db.notes.find({ where: { id }, limit: 1 });
      const note = found[0];
      if (note === undefined) return Response.json({ error: "not found" }, { status: 404 });
      return Response.json(note);
    }
    return Response.json({ error: "not found" }, { status: 404 });
  },
};
```

The same two routes, in the server you already run. The process keeps `db`. `find` returns a list, so the read asks for one row with `limit: 1`. Cloudflare Workers export that `fetch` handler from `src/index.ts`. Any-runtime is the same handler where Bun or Deno calls `fetch(request)`. Node uses one of the servers above.

The schema can say more than one column. [Schema](/docs/model/schema) adds a relation. [Queries](/docs/model/queries) is the same read, written as a function you can call.
