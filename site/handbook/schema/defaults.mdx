`defaults.id` is what a bare `t.id()` means. A column option wins.

```ts title="schema.ts"
import { schema, table, t } from "okmodel/pg";

const notes = table("notes", {
  id: t.id(),
  title: t.text(),
});

export default schema({
  tables: [notes],
  defaults: { id: "uuidv7" },
});
```

`"uuidv7"` stores `uuidv7()`. `"uuidv4"` stores `gen_random_uuid()`. A client generator is filled on insert and stays out of the catalog.

With no schema default, a bare `t.id()` is still `uuidv7()`. `t.id({ default: "none" })` takes the id on insert. `id` is the only name `defaults` accepts.

`uuidv7()` needs Postgres 18. Declare [requires](/docs/schema/requires) when the server is older, and do not use that default.
