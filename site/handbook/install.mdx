Install the package and one Postgres driver. The next page defines a table and reads a row.

<Callout title="Use a direct database URL">
  `DATABASE_URL` is a direct Postgres connection, not a pooler. Migration commands refuse a pooler host.
</Callout>

## Add the package

```sh
bun add okmodel postgres
```

## Point the config at the schema

<Tabs items={["Direct", "Safe"]}>

<Tab value="Direct">

```ts title="okmodel.config.ts"
import { defineConfig } from "okmodel/migrate";

export default defineConfig({
  schema: "./schema.ts",
  database: process.env.DATABASE_URL!,
});
```

</Tab>

<Tab value="Safe">

```ts title="okmodel.config.ts"
import { defineConfig } from "okmodel/migrate";

const url = process.env.DATABASE_URL;
if (url === undefined || url.length === 0) {
  throw new Error("DATABASE_URL is not set");
}

export default defineConfig({
  schema: "./schema.ts",
  database: url,
});
```

</Tab>

</Tabs>

`schema` is the file you are about to write. `database` is the one target those commands use. Direct asserts the URL. Safe refuses an empty `DATABASE_URL`.

Node.js 22.18 or newer loads `okmodel.config.ts` (type stripping). Older Node prints that and stops. `bunx okm` uses Node. `bun --bun okm` uses Bun. On Windows, use a `postgres://` URL. `okm generate init` adds a `.gitattributes` so migration SQL stays LF. The [migrations](/docs/ship/migrations) page has the lines.
