A column is required and not null until you say otherwise.

`.nullable()` allows SQL NULL. A null default is only accepted after `.nullable()`.

`.default()` stores a literal in the catalog, or a client generator. A generator is filled on insert and the catalog stores no default. Pass `uuidv4`, `uuidv7`, `okid(...)` from `okmodel/ids`, or any function.

`.defaultSql()` stores a SQL expression as written.

`.generated()` stores a generated expression. Insert and update omit the column. `stored` defaults to true.

```ts title="notes.ts"
import { table, t } from "okmodel/pg";

export const notes = table("notes", {
  id: t.identity(),
  title: t.text().default(""),
  publishedAt: t.timestamptz().nullable(),
  createdAt: t.timestamptz().defaultSql("now()"),
  search: t.tsvector().generated("to_tsvector('simple', title)"),
});
```

`t.id()` and `t.identity()` already carry a default. The schema [id default](/docs/schema/defaults) changes what a bare `t.id()` means. A column option wins.

A default that is not in a [picklist](/docs/table/shape) is refused.
